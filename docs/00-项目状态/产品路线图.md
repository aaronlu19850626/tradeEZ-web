# 产品路线图

路线图只保存稳定阶段目标；迭代、负责人、日期和完成度由 GitHub Project 维护。

## 阶段 0：协作基线

- 建立可运行、可测试的 `main`。
- 建立 Issue、worktree、PR、CI、文档和数据库迁移规则。
- 完成文档唯一事实源治理。

## 阶段 1：核心能力盘点

- 逐模块研究 TradeZella 页面、交互、状态、数据对象和跨模块关系。
- 对照 TradeEZ 代码形成能力差距矩阵。
- 以核心用户闭环、依赖、风险和复用价值评估 P0/P1/P2。

## 阶段 2：一期确认

- 产品负责人确认一期模块、开发波次、验收深度和不做项。
- 为每个模块建立 Epic、功能矩阵、模块规格和验收标准。
- 明确共享组件、接口、迁移和集成顺序。

## 阶段 3：模块交付

每个模块执行研究、需求评审、前端 Mock、用户确认、后端、联调、测试、PR 和生产测试环境验收。下一波模块只有在依赖稳定后启动。

## 阶段 4：发布准备

- 完成安全、性能、备份恢复、可观测性和连接器可靠性验收。
- 固化生产迁移、回滚和发布审批。
- 以 GitHub Release 或发布 PR 记录实际发布范围。
