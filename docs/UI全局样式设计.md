版本：1.0；状态：已确认并持续执行；依据：一期需求评审、用户最新视觉验收和《全局样式规则.md》。

> 当前执行时以《全局样式规则.md》为准。本文保留早期设计盘点和历史提案，用于追溯，不覆盖已经确认的单一浅色主题、深紫侧栏、紫色操作色、指标卡提示、Tooltip 宽度和 EA 状态语义。

## 最新确认（覆盖下文旧提案中的冲突内容）

- 保留原 UI 主框架、导航、页面结构及交互能力，不采用独立样板的新框架。
- 保留布局切换、侧栏折叠、内容宽度、顶栏样式和侧栏变体及对应偏好；不得清理这些配置。
- 固定为单一浅色工作台，取消深色/浅色切换、多配色预设与字体自定义；统一字体、间距、边框、圆角和控件状态。
- 旧偏好迁移仅针对 theme_preset、font；theme_mode 保留兼容读取但不再提供切换。content_layout、navbar_style、sidebar_variant、sidebar_collapsible 保持现有读取、写入和交互。
- 下文第 4 节固定侧栏/顶栏尺寸提案、第 6 节删布局偏好方案不再执行；第 2 节导航归并建议不属于本次实施。
- 独立 `/ui-preview` 样板已移除。全局样式直接在原框架内实施和验收。
- 验收须额外验证：原布局切换、侧栏折叠及刷新后偏好恢复不受影响；不修改业务路由、数据和功能。
本次交付是源码盘点和设计文档，尚未修改业务页面。盘点基线：e394961。

## 1. 范围与证据

本阶段负责固定浅色主题、TradeEZ 品牌色、字体、间距、组件语义及旧偏好迁移；不改变指标计算、交易数据、数据库或登录权限。

品牌基线：深紫侧栏、白色内容区、左上角 TradeEZ 标识；操作主色采用紫色体系，悬浮、选中和禁用状态由同一组语义色派生。

源码确认：

- `src/navigation/sidebar/sidebar-items.ts` 当前包含 13 个业务导航入口。
- `src/lib/preferences/preferences-config.ts` 含 7 项偏好：theme_mode、theme_preset、font、content_layout、navbar_style、sidebar_variant、sidebar_collapsible；当前默认 light。
- `src/app/layout.tsx` 注入全部偏好属性，ThemeBootScript 首屏恢复 Cookie，PreferencesStoreProvider 维护客户端状态。
- Dashboard layout 还从服务端读取侧栏样式，并挂载 LayoutControls，因此仅隐藏设置按钮不足以固定框架。
- `src/lib/fonts/registry.ts` 引入多款 Google 字体，需要收敛字体和外部加载依赖。
- 今日页已关联 DailyPlan、Intentions、DailyReviewCard、SyncHealthAlerts，须保留这些业务能力。
- 页面目录还存在医疗、物流、电商、CRM 等模板路由。患者页直接使用本地 patients 数据；其余模板删除前须逐项核查引用与访问入口，不能仅凭名称删除。

本次没有读取用户在外部浏览器中的 TradeZella 登录会话；设计参考用户提供截图与已确认方向。以下色值是待验收的候选值，不宣称为 TradeZella 精确取色。

## 3. 视觉基线

中性炭灰背景、同色系容器、细边框、清晰文字；保留品牌蓝操作色。取消早期海军蓝铺底方案。深色默认，浅色固定备用，用户只能切换明暗。

| 语义 Token | 深色候选 | 浅色候选 |
|---|---|---|
| 页面背景 | zinc-950 | zinc-50 |
| 卡片/侧栏 | zinc-900 | white |
| 次级区/悬停 | zinc-800 | zinc-100 |
| 边框 | zinc-800 | zinc-200 |
| 正文 | zinc-100 | zinc-900 |
| 次文字 | zinc-400 | zinc-600 |
| 主操作 | blue-600，白字 | blue-600，白字 |
| 盈利 | emerald-400 | emerald-700 |
| 亏损 | rose-400 | rose-700 |
| 警告 | amber-400 | amber-700 |

页面使用语义变量，不直接散落颜色值。主色只用于操作、选中、焦点等；交易结果红绿与正负号同时呈现。买卖方向使用“买/卖、多/空”文字，不暗示结果。零盈亏使用中性色，缺失数据 N/A，不显示为 0。非盈亏图表使用统一分析色，不将操作蓝复用为收益上涨信号。

字体采用固定系统无衬线栈（中文优先系统中文字体），数字使用 tabular-nums；删除字体选择和多字体网络请求。建议标题 24px/600，分区标题 16px/600，正文 14px，辅助文字 12px，指标 28px；移动端指标 24px。

间距以 4/8px 为基准；桌面页面边距 24px，手机 16px；卡片间距 16px，内边距 20px。卡片圆角 12px，控件 8px；以边框分层，仅弹层使用柔和阴影。

## 4. 框架与交互提案

- 桌面侧栏固定 240px，可收起为 64px 图标栏；收起是操作状态，不属于自定义框架。
- 顶栏 56px，保留同步状态与明暗切换；AI、通知未实现前不展示可误点的空入口。
- 内容区流式宽度，建议最大 1600px；表格可内部横向滚动。
- 768–1279px 默认收起侧栏；小于 768px 采用菜单抽屉。此提案替代旧稿的手机底部导航，待本次确认。
- 未来全局 AI 在桌面采用右侧面板，手机全屏；本阶段仅规定承载空间，不实现 AI。
- 账户/日期筛选显示作用范围；未完成统一筛选逻辑前保留各页现有数据行为，避免显示统一但实际不生效。

## 5. 组件和状态规范

- 按钮区分主操作、次操作、文字操作、危险操作；加载时防止重复提交。
- 表格数字右对齐、表头固定、行高建议 44px；行悬停不使用高饱和背景。
- 指标卡保持统一背景，颜色只作用于语义值和小标记，不整卡染色。
- 图表保持低对比网格、单位/币种可见、Tooltip 统一；正负与颜色双重编码，多序列同时使用标签或线型。
- 编辑区背景跟随主题，正文行高约 1.7；本阶段不重构 Markdown 文档模型。
- 空状态、加载、接口错误、无权限、N/A 分开呈现；错误提供明确重试入口。
- 所有交互有键盘焦点，正文对比度目标至少 4.5:1，控件/焦点至少 3:1；最终按实际组合验证。

## 6. 偏好迁移和数据结构

无数据库结构变更、无新增业务 API。建议显示偏好仅保留：theme_mode=dark|light 和 sidebar_state=open|collapsed。

迁移规则：已有明确 dark/light 选择保留；system、无值或非法值归为 dark。旧 theme_preset、font、content_layout、navbar_style、sidebar_variant、sidebar_collapsible 不再读取或写入；定向清理这些外观 Cookie/存储键，不清空全站存储、登录 Token、业务筛选及笔记草稿。

首屏脚本、服务端布局和客户端状态须采用一致默认值，避免浅色闪烁和 hydration 冲突。禁用存储时仍可正常显示默认深色。纯显示偏好不因切换模式触发业务数据修改。

## 8. 阶段交付与验收

1. 本文评审：确认色板方向、字体密度、固定框架及偏好迁移方案。
2. 组件样板：使用明确标记的演示数据展示双主题按钮、输入、指标、表格、图表、弹窗及状态，不连接用户数据。
3. 样板验收后应用全局基础样式，移除旧自定义能力；导航重排与业务布局仍按模块独立验收。
4. 每个功能先提交独立设计文档，确认后实现，再进入下一模块。

UI-1 验收用例：

- 新浏览器首次进入深色；手动切浅色刷新保留。
- 旧彩色主题/字体/侧栏变体的 Cookie 不再改变框架；登录和业务数据不受影响。
- 登录、今日、账户、订单页及弹层明暗一致，无明显首屏闪烁。
- 1440、1024、390px 视口不出现页面级横向溢出；表格可局部滚动。
- 盈利、亏损、零值、N/A 可清晰区分；不能以颜色作为唯一信息。
- 焦点、禁用、加载、错误和空状态可辨识；固定字体不依赖 Google Fonts 下载。
- 所有已有计划、订单、复盘和同步入口保持可达；阶段内不删除演示路由或业务功能。
