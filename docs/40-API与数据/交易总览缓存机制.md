# 交易总览缓存机制

版本：1.0；状态：已实现单进程缓存观测与请求合并。

## 1. 缓存类型

交易总览使用后端进程内对象缓存，不缓存数据库查询计划和浏览器响应。

- 缓存对象：`OverviewOut`
- 存储位置：FastAPI 当前进程内存
- 默认 TTL：30 秒
- 最大条目：512
- 适用场景：同一用户重复打开总览、重复应用相同筛选条件、页面刷新

## 2. 缓存键

缓存键由以下内容组成：

```text
user_id + variant + 规范化 TradeFilter JSON
```

`TradeFilter` 包含：

- 账户 ID
- 日期范围
- 方向
- 结果
- 币种
- 市场
- 品种

参数顺序不会影响缓存命中；任一筛选值变化都会形成新的缓存键。

## 3. 读取流程

1. 请求进入 `/api/v1/trades/overview`。
2. 服务函数检查 `variant="overview"` 的缓存。
3. 命中且未过期时，直接返回 `OverviewOut`。
4. 未命中或已过期时，执行总览 SQL 和像素桶散点 SQL。
5. 组装结果后写入缓存。

缓存只减少重复请求的计算，不加快第一次冷请求。

## 4. Single-flight

同一个缓存键被多个并发请求同时命中时，只允许一个请求执行加载函数：

1. 第一个请求取得该键的内存锁并开始计算。
2. 其他请求等待同一个锁。
3. 第一个请求完成后写入缓存。
4. 等待请求直接复用刚写入的对象。

这样可以避免缓存击穿时多个请求重复计算同一份总览。

## 5. 失效机制

以下操作会删除该用户的全部交易缓存：

- 账户创建、更新、删除
- 重置密钥、重置交易
- 交易导入
- MT5 同步
- 统一连接器事件写入
- 账户统计范围变化

此外，缓存超过 30 秒后会在读取时自然过期。

## 6. 指标接口

内部接口：

```text
GET /api/v1/internal/cache/stats
X-Internal-Token: <TRADESYNC_INTERNAL_API_TOKEN>
```

返回字段：

| 字段 | 说明 |
|---|---|
| `scope` | 当前为 `process` |
| `entries` | 当前缓存条目数 |
| `max_entries` | 最大条目数 |
| `ttl_seconds` | TTL |
| `hits` | 命中次数 |
| `misses` | 未命中次数 |
| `expired` | 过期删除次数 |
| `evictions` | 容量淘汰次数 |
| `sets` | 写入次数 |
| `coalesced` | 被请求合并复用的次数 |
| `invalidated` | 主动失效的条目数 |
| `hit_rate` | 命中率 |

## 7. 当前局限

- 缓存只在单进程内共享，多实例部署时命中率无法共享。
- 当前淘汰策略是简单 FIFO，不是严格 LRU。
- 512 个 `OverviewOut` 对象会占用一定内存。
- 需要多实例部署时，应迁移到 Redis，并使用用户级版本号失效。
