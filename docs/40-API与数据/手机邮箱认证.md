# 手机号 / 邮箱验证码注册登录

版本：历史功能说明；状态：功能仍存在，存储与运维细节需以当前 PostgreSQL 代码复核；用途：说明认证行为和安全边界；维护人：后端负责人；验收入口：认证接口测试与当前模块 PR。

本文后续 SQLite 迁移、备份和限流存储描述属于旧实现。当前运行数据库为 PostgreSQL，数据库事实以代码、schema 和《数据库迁移》为准。

登录页 `/auth/v2/login` 默认手机号，可切换邮箱。首次验证成功自动注册，再次使用同一手机号或邮箱即登录。

手机号当前支持中国大陆 11 位号码，允许输入 `+86` 前缀，统一存为 `+86` 格式；邮箱去首尾空格并转小写。两个入口分别注册的账户独立，不自动合并，原邮箱账户请继续使用邮箱登录。绑定另一种登录方式/账户合并不在本次范围。

## 测试开关

在后端 `.env` 设置并重启全部 API 进程：

```dotenv
TRADESYNC_ENVIRONMENT=test
TRADESYNC_AUTH_TEST_MODE=true
TRADESYNC_DEV_FIXED_LOGIN_CODE=
```

两种通道均固定为 `123456`，不调用短信或邮件服务。仍必须先点击“获取验证码”，仍校验有效期、冷却时间、使用次数和错误尝试次数。登录页显示测试提示。

关闭 `AUTH_TEST_MODE` 后使用 `secrets.randbelow` 生成六位随机数字，保留前导零，不在 HTTP 响应中返回随机验证码。旧的 `DEV_FIXED_LOGIN_CODE` 仅兼容开发环境的 `123456`，建议留空。`ENVIRONMENT=production` 时只要任一测试开关开启就拒绝启动。

## 正式短信（阿里云）与邮件（SMTP）

```dotenv
TRADESYNC_ENVIRONMENT=production
TRADESYNC_AUTH_TEST_MODE=false
TRADESYNC_DEV_FIXED_LOGIN_CODE=
TRADESYNC_SMS_PROVIDER=aliyun
TRADESYNC_ALIYUN_ACCESS_KEY_ID=填写RAM用户AccessKeyId
TRADESYNC_ALIYUN_ACCESS_KEY_SECRET=填写RAM用户AccessKeySecret
TRADESYNC_ALIYUN_SMS_SIGN_NAME=填写审核通过的短信签名
TRADESYNC_ALIYUN_SMS_TEMPLATE_CODE=SMS_填写审核通过的验证码模板编号
TRADESYNC_ALIYUN_SMS_CODE_PARAM=code

TRADESYNC_EMAIL_PROVIDER=smtp
TRADESYNC_SMTP_HOST=smtp.example.com
TRADESYNC_SMTP_PORT=587
TRADESYNC_SMTP_USERNAME=填写邮箱账号
TRADESYNC_SMTP_PASSWORD=填写邮箱授权码
TRADESYNC_SMTP_FROM_EMAIL=no-reply@example.com
TRADESYNC_SMTP_FROM_NAME=TradeEZ
TRADESYNC_SMTP_STARTTLS=true
TRADESYNC_SMTP_SSL=false
```

保留已有 `TRADESYNC_AUTH_SECRET`、数据库路径和同步密钥加密配置；不要覆盖成示例值。上述参数属于后端配置，不能放在 `NEXT_PUBLIC_` 前端变量中。宝塔/systemd 若另设了环境变量，其优先级高于 `.env`，应同时核对。

阿里云模板应只包含一个验证码变量（默认 `${code}`，其他名称通过 `ALIYUN_SMS_CODE_PARAM` 配置）。签名、模板、RAM 凭据、短信余额/发送资格需要在自己的阿里云账户中准备。正式环境启动会检查必填配置和 SMTP TLS，缺失时拒绝启动。

SDK 使用 HTTPS、5 秒连接超时、10 秒读取超时，关闭自动重试避免重复短信。仅当 SendSms 返回 `Code=OK` 才标记为已发送；这代表服务商已受理，最终到达手机需要真实号码联调验证。SMTP 为 587+STARTTLS；如果供应商要求 465，则设 `SMTP_PORT=465`、`SMTP_SSL=true`、`SMTP_STARTTLS=false`。

官方参考：[阿里云 Python SDK](https://help.aliyun.com/en/sms/developer-reference/using-python-openapi-example)、[SendSms 参数与返回值](https://help.aliyun.com/zh/sms/developer-reference/api-dysmsapi-2017-05-25-sendsms)。依赖见 `backend/requirements.txt`，已锁定 `alibabacloud-dysmsapi20170525==4.6.0`。

## 接口与保护

- `GET /api/v1/auth/config`：返回 `test_mode` 和 `phone_region`，不含密钥。
- `POST /api/v1/auth/send-code`：`{"phone":"138xxxxxxxx"}` 或 `{"email":"you@example.com"}`，必须二选一。
- `POST /api/v1/auth/verify-code`：同上并增加 `"code":"六位数字"`。
- `GET /api/v1/users/me`：返回 `email` / `phone`，未注册该种联系方式的字段为 `null`。
- 默认有效期 600 秒、同一身份 60 秒冷却、每小时最多 5 次；错误 5 次即失效；重发使旧验证码失效；验证成功只能使用一次。
- 同 IP 每小时 30 次、所有身份滚动 24 小时合计 1000 次（含失败发送），通过 `CODE_MAX_PER_IP_HOUR` / `CODE_MAX_TOTAL_PER_DAY` 调整。限制保存在 SQLite，多个工作进程共享，不因重启清零。
- 只使用 ASGI 提供的客户端 IP，不自行信任请求头。Nginx 应覆盖转发头，Uvicorn 仅信任本机反向代理，禁止把可信代理设为任意来源。局域网开发代理下多个客户端可能共用 IP 配额。
- 未完成发送、发送失败、过期、已消费、测试/正式模式不匹配的验证码均不能登录。短信/SMTP 异常只返回统一中文错误，不泄露服务商异常中的凭据。
- API 日志只记录是否提供手机号/邮箱，不记录原始联系方式和验证码。生产不允许 console 邮件通道。

## 数据升级及验收

迁移 `0006_phone_auth` 为加法迁移，保留已有用户 ID、交易账户、复盘及附件。手机号用户有独立的 `phone` 字段。为避免重建父表触发 SQLite 级联删除，旧数据库的 `users.email` 唯一键对手机号用户存储内部 `phone:+86...` 身份；API 不将其作为邮箱暴露，SMTP 也不会使用该值。后续做联系方式绑定时应迁移到独立身份表。

迁移时使旧验证码失效，升级后重新获取即可，已登录会话保留。先通过 `backend/scripts/backup_database.py` 做 SQLite 在线备份，再运行 `python -m alembic upgrade head`（应用启动也会升级）。

自动化验证覆盖手机号规范化、新注册/重复登录、邮箱兼容、单次消费、错误耗尽、测试隔离、发送未完成/失败、生产配置防护、频率限制及阿里云 SDK 请求参数。测试使用临时数据库与模拟发送，不会给真实手机号发送短信。真实送达验收仍需填写自己的阿里云与 SMTP 参数后进行。
