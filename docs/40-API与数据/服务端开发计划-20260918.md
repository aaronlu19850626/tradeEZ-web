# 服务端开发计划（2026-09-18 重整版）

> 范围：**仅服务端（FastAPI）与必要的 Web 端配套**。EA 端不修改、不挂载，一切以 EA 侧已发布的
> 《TradeEZ-SOP 数据同步接口说明》（2026-09-18 15:25 基线，下称“七接口契约”）为准。
> 优先级：**先保证与 EA 的连接和交易数据可靠同步，再做复盘相关功能。**

## 0. 当前基线（已完成并测试）

- 七接口契约全部实现，成功统一 HTTP 200，业务错误返回非 2xx（EA 不解析 body 业务码）。
- 原始 body + X-Timestamp 的 HMAC-SHA256 验签，±300 秒窗口；新 Key 强制签名，老 Key 兼容 Bearer。
- 成交按 `(mt5_login, ticket)` 幂等 upsert，单请求一个事务；游标为 entry=OUT 的 deal_time，只增不减。
- 两阶段提交：成交持久化与游标推进分离；游标推进前校验 OUT 成交已落库。
- symbols / snapshots / settings(55 字段, 6 组) / heartbeat 四接口幂等与冲突口径就绪。
- Trade 生命周期落库、部分平仓/反转/OUT_BY、待核对、原始成交查询、同步轮次与审计日志。
- 复盘域：标签、复盘与版本、反思、截图附件、Setup/Playbook/规则评价、业绩分析与导出。
- 每日计划/意图/日总结/周复盘/习惯/提醒、工作区设置、账号维护（停用/重置/删除/Key 轮换）。
- 后端测试 95 项全部通过（2026-09-18 修复 3 类历史失败后）。

EA 侧已知边界（服务端接受现状，不假设不存在的能力）：
- 只有出现 OUT 的持仓才会上传，**纯在仓仓位不会同步**；余额/信用类成交 position_id=0 不上传。
- 游标由 EA 按平仓时间推进；查询失败 EA 自行回退 7 天，因此服务端必须对重传完全幂等。
- EA 请求超时仅 200–800ms，接口必须保持轻量；无实例 ID、无远程配置下发、无撤单接口。

## P0 — EA 连接与数据同步可靠性（最高优先级）

目标：任何时候挂上 EA，成交都能不丢、不重、可重放地同步进来。

- [x] P0-1 修复失败测试，恢复绿色基线（95 通过）。
- [x] P0-2 运维探针：`GET /healthz`（存活，不泄露配置）、`GET /readyz`（数据库可写、迁移版本为 head）；保留 `/health`。
- [x] P0-3 心跳限流余量：EA 固定 300 秒一次（12 次/小时），叠加手动/每日完整同步会触发 429；提高到 30 次/小时。
- [x] P0-4 用临时库跑通七接口冒烟脚本与 HMAC/重放/第二批失败等契约场景，形成可重复的同步验收命令。
- [x] P0-5 契约复核：逐接口核对状态码、必填字段、幂等/冲突响应与《接口说明》一致，记录到验收文档。
- [x] P0-6 同步可观测性：Web 端可按账号看到最近握手、游标、轮次状态、失败原因（已有 sync-runs/api-logs，做一轮字段核对）。

完成标准：临时库冒烟 + 全部后端测试通过；七接口在重复请求、乱序重试、游标回退、停用/删除账号下行为符合契约。

## P1 — 同步数据的核对与展示

- [x] P1-2 Trade 归并结果可核对：缺开仓、数量不平、反转、跨起点在列表和详情中有明确状态与问题明细。

## P2 — 复盘功能闭环

目标：用户能完整解释每一笔已结束交易，并把改进行动带入下一次计划。

- [x] P2-1 单笔复盘：事实只读、标签/笔记/情绪/错误/结论/下次行动、乐观锁版本与历史版本。
- [x] P2-2 截图附件：私有存储、鉴权访问、类型大小限制、失败不覆盖复盘。
- [x] P2-3 Setup/Playbook/规则版本：草稿/发布/停用，发布版本不可变；评价引用历史版本。
- [x] P2-4 执行评分：覆盖率口径、关键违规、证据不足/未评分不产生误导性分数。
- [x] P2-5 业绩分析：分币种、样本数、已实现盈亏曲线、维度统计、筛选下钻与当前页导出。
- [x] P2-6 每日计划/意图/日总结/周复盘/行动/习惯与 Trade 的关联和迟到数据核对。

（以上多数后端能力已存在，P2 以缺口核对、回归测试和前端对接为主，不重复造轮子。）

## 工作规则

1. EA 接口任何改动只能“加可选字段”，不得改变既有路径、字段含义和成功状态码。
2. 每个缺陷修复先加/改回归测试，再改实现；里程碑结束跑“全部 pytest + 冒烟”。
3. SQL 只进 repository；日志不记录 Key、Token、HMAC、验证码、价格、手数、盈亏明细。
4. 金额永远带币种；事实时间一律 UTC 秒，展示时区属于工作区配置。
