# TradeEZ 文档入口

本目录只保留当前有效的长期文档。任务状态、负责人、确认记录和测试流水以 GitHub Project、Issue、PR 和 Actions 为准；已删除旧稿通过 Git 历史查询。

## 新成员和新模型

最短阅读路径：

1. 根目录 [`AGENTS.md`](../AGENTS.md)
2. [当前状态](00-项目状态/当前状态.md)
3. 当前 GitHub Issue
4. [AI 接手与会话交接](10-开发与协作/AI接手与会话交接.md)
5. 当前模块在[模块目录](20-产品与研究/模块目录.md)登记的规格

## 目录

| 目录 | 唯一职责 |
|---|---|
| `00-项目状态` | 稳定项目概览、发布级状态和产品路线图 |
| `10-开发与协作` | 开发、GitHub、AI 交接、质量和数据库协作规则 |
| `20-产品与研究` | 产品原则、TradeZella 研究方法、模块登记和模板 |
| `30-模块规格` | 每个模块唯一的长期规格 |
| `40-架构与数据` | 系统、数据、认证、统计、连接器和同步契约 |
| `50-前端与设计系统` | 前端实现、视觉、组件和图标规范 |
| `60-运行与部署` | 本地并行运行、部署、测试环境和 EA 配置 |

## 文档状态

| 状态 | 含义 | 是否可直接指导开发 |
|---|---|---|
| `active` | 当前生效的规则或已确认事实 | 可以 |
| `needs-review` | 有历史实现或设计，尚待新流程复核 | 不可以，需当前 Issue 确认 |
| `paused` | 明确暂停 | 不可以 |

## 维护规则

- 所有 `docs/**/*.md` 使用统一元数据：`doc_id`、`status`、`owner`、`last_verified`。
- 模块规格另加 `github_issue`；只有绑定有效 Issue 和验收证据后才能标为 `active`。
- 动态进度不复制到仓库；`当前状态.md` 只在主干发布、阶段或重大阻塞改变时更新。
- 规则只保留一个权威文件，其他文档只能链接，不得复制全文。
- 单次测试报告、截图、研究证据和确认记录放在 Issue、PR 或 Actions artifact。
- 过期正文不建立归档目录，通过 Git 历史恢复。
- 提交前运行 `python3 scripts/docs/check_docs.py`。
