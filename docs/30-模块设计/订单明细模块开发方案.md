# 订单明细模块开发方案

版本：1.0；状态：待评审。

## 1. 目标

订单明细模块用于承载单笔交易从开仓到平仓的完整生命周期，包括统计、执行明细、策略、附件、图表、笔记、日复盘和运行中盈亏。

模块入口：

- 从交易记录的整条记录进入。
- 从日视图、周视图、月历日的交易明细进入。
- 从交易总览“最近交易”进入。
- 支持交易列表内上一笔、下一笔连续浏览。

本模块不替代完整的订单管理与仓位管理模块，只负责已同步交易的查看、归因和复盘。

参考样本：

- TradeZella 订单明细页 `/tracking/trades/2049442f`
- 样本交易：XAU，2026-09-10，SHORT，MT5 2079
- 样本净损益：`122.7`
- 样本执行：2 笔

## 2. 参考页结构

### 2.1 左侧交易列表

页面左侧保留当前交易日或当前筛选范围内的交易列表：

- 顶部“+ Add Trade”主按钮。
- 当前日期和日期切换入口。
- 当日统计：
  - Net P&L
  - Total trades
  - Win rate
  - Profit factor
- 每笔交易卡片：
  - 品种代码
  - 净损益
  - 开仓时间和平仓时间
  - 已复盘状态圆点
  - 多选框
- 点击任意交易后，右侧详情区切换到该笔交易。

我们的实现建议：

- 增加左侧列表在移动端折叠为顶部交易选择器。
- 使用共享 `SymbolBadge`、`TradeSideBadge` 和统一的金额格式化。
- 保留列表、详情双向联动。

### 2.2 订单头部

订单头部包含：

- 返回交易列表。
- 上一笔、下一笔交易。
- 品种代码。
- 交易日期。
- Unknown symbol 标记。
- Mark as reviewed。
- Replay。
- Share。
- 设置。

业务逻辑：

- 上/下笔在当前筛选结果内移动，不跨出当前查询范围。
- Unknown symbol 来自品种规格未匹配，不是错误状态。
- Replay 只有在订单存在时间、价格和行情回放数据时才启用。
- Reviewed 是用户级状态，不影响交易统计。
- Share 生成分享链接或分享配置。

## 3. 核心业务对象

### 3.1 订单生命周期

一个订单明细对应一个已平仓的 position lifecycle：

```text
position_id
account_id
symbol
side
open_time
close_time
volume
entry_price
exit_price
net_pnl
```

一个 lifecycle 可以包含多个 execution。

### 3.2 执行明细 Execution

一个 execution 对应平台的一条成交事件：

```text
deal_ticket
position_id
entry / exit
side
quantity
price
deal_time
commission
swap
gross_pnl
```

数量符号规则以浏览器样本为准：

- SHORT 开仓显示负数，例如 `-0.3`。
- SHORT 平仓显示正数，例如 `0.3`。
- Gross P&L 只在平仓执行上体现。

我们需要把 quantity 明确定义为：

```text
执行数量相对持仓方向的有符号值
```

内部仍保留原始 `type`、`entry`、`volume`，展示层再做符号转换。

### 3.3 复盘状态

订单级状态：

- reviewed
- rating
- strategy_id
- tags
- note
- journal
- attachment

复盘状态属于用户，不改变成交本身。

## 4. 详情区 Tab

### 4.1 Stats

Stats 是订单结构和结果的主信息区。

必须包含：

| 字段 | 口径 |
|---|---|
| Net P&L | gross + commission + swap |
| Side | Long / Short |
| Account | 平台账户名称 |
| Contracts / Volume | 总成交手数 |
| Commissions & Fees | 佣金与费用合计 |
| Total Swap | 库存费合计 |
| Net ROI | net P&L / adjusted cost |
| Gross P&L | profit + swap |
| Adjusted Cost | 调整后的交易成本 |
| Strategy | 关联策略 |
| Zella Scale | 平台评分，预留 |
| Price MAE / MFE | 最大不利/有利波动 |
| Running P&L | 运行中盈亏序列 |
| Trade Rating | 星级评分 |
| Profit Target | 目标价格和目标数量 |

必要性分级：

- P0：Net P&L、Side、Account、Volume、Fees、Swap、Net ROI、Gross P&L。
- P1：Strategy、Rating、Running P&L、MAE/MFE。
- P2：Adjusted Cost、Zella Scale、Profit Target。

### 4.2 Strategy

两种状态：

1. 未关联策略：
   - 空态插画。
   - “Create Strategy”按钮。
   - 说明策略可以帮助跟踪有效行为。
2. 已关联策略：
   - 策略名称。
   - 策略版本。
   - 是否遵守规则。
   - 策略备注。

我们的实现建议：

- 一期只做策略只读选择与关联，不在订单明细内创建完整策略编辑器。
- 策略列表复用后续策略模块，不在本模块复制。

### 4.3 Executions

默认显示当前订单的执行明细：

- 执行数量。
- View all。
- 表格：
  - Date/Time
  - Price
  - Quantity
  - Gross P&L
  - 图表定位按钮

参考样本：

```text
2026-09-09 13:08:50  $4418.76  -0.3  $0
2026-09-09 13:37:33  $4414.67   0.3  $122.7
```

业务规则：

- 默认时间展示使用用户设置的时区，一期固定北京时间。
- 时间列可增加 Tooltip 显示平台服务器时间。
- View all 在超过当前展示条数时打开 Dialog。
- 图表按钮将图表定位到对应 execution 的时间点。

### 4.4 Attachments

支持：

- 拖拽上传。
- Browse Files。
- 文件列表。
- 缩略图或文件类型图标。
- 删除附件。

建议文件类型：

- PNG / JPG / WEBP
- PDF
- CSV
- TXT
- 截图

实现依赖：

- 需要对象存储或附件存储接口。
- 数据库只存文件名、MIME、大小、URL、创建时间。

### 4.5 Chart

Chart Tab 展开后占用右侧主区域：

- 时间周期：1m / 5m / 15m / 1h / 4h / 1d。
- K 线类型。
- Indicators。
- 画线工具。
- 撤销 / 重做。
- Save。
- Layout。
- 全屏。
- 底部 Notes 区域。
- Trade note / Daily Journal 切换。

业务逻辑：

- 图表品种优先使用订单 symbol。
- 无品种规格或 Unknown symbol 时显示空图表和提示。
- executions 以标记点叠加到图表。
- 图表定位与 execution 表格双向联动。
- 图表时间轴使用用户时区，一期固定北京时间。

技术约束：

- 使用 `lightweight-charts`。
- 行情 K 线需要独立行情数据源。
- 若没有历史行情，可以先支持 execution 点位图，不伪造 K 线。

### 4.6 Notes

Notes Tab 包含两个子 Tab：

#### Trade note

用于单笔交易复盘：

- 为什么做这笔交易。
- 是否遵守规则。
- 情绪、图形、交易管理经验。

#### Daily Journal

用于当日交易复盘：

- 按日期归档。
- 可复用模板。
- 与订单记录关联。

参考样本中的模板：

```text
BECOMING AWARE OF YOUR EMOTIONS
EMOTION | WHAT YOUR MIND TELLS YOU | HOW YOU ACT
```

编辑器功能：

- 语音输入。
- 字体和字号。
- 加粗。
- 链接。
- 无序列表。
- 有序列表。
- 文本颜色。
- 高亮颜色。
- 待办列表。
- 撤销 / 重做。
- 全屏。

推荐分阶段：

- 一期：基础 Markdown 文本 + 模板 + 自动保存。
- 二期：富文本编辑器。

### 4.7 Running P&L

Running P&L 展示持仓期间的浮动盈亏曲线。

数据和算法通常需要：

- tick 或分钟级价格。
- 订单方向和手数。
- 点值、合约规模和币种换算。
- 开仓到平仓的持仓区间。

如果只有 MT5 成交和快照，缺少逐 tick 数据时，不能精确还原 Running P&L。

我们的处理建议：

- 第一期先显示空态和“暂无可计算数据”。
- 有 OHLC 行情后，以每分钟收盘价估算曲线。
- 有 tick 数据后再做真实 Running P&L。

## 5. 顶部操作与弹层

### 5.1 Mark as reviewed

- 单选按钮或图标按钮。
- 点击后立即保存。
- 按钮状态切换为已复盘。
- 失败时回滚并提示。

### 5.2 Replay

- 有回放数据时打开交易回放页。
- 无数据时禁用，并显示原因 Tooltip。

### 5.3 Share

弹层建议包含：

- 分享链接。
- 是否公开方向、金额、账户。
- 是否包含笔记。
- 是否包含附件。
- 复制链接。
- 生成图片。

此处涉及权限和敏感数据，默认仅分享订单统计和图形，不分享账户号。

### 5.4 设置

建议菜单：

- 编辑交易。
- 重新匹配品种。
- 修改策略。
- 修改标签。
- 删除交易。

危险操作必须进入标准 Dialog。

### 5.5 日期选择

顶部日期支持切换交易日：

- 前后日。
- Calendar 选择日期。
- 跳回当前日期。

切换日期后左侧交易列表更新，默认选中第一笔。

### 5.6 Add template

打开模板选择弹层：

- 内置模板。
- 用户收藏模板。
- 模板分类。
- 预览。
- 插入。
- 新建模板。

## 6. 页面布局

### 6.1 桌面端

```text
左侧导航
  |
交易列表 320px
  |
订单详情主区域
  - Header
  - Stats / Strategy / Executions / Attachments
  - Chart / Notes / Running P&L
```

Chart 展开时：

- Chart 占右侧主区域。
- Notes 固定在 Chart 下方。
- 左侧交易列表保持可见。

### 6.2 平板

- 交易列表可收起。
- 详情区占满宽度。
- 左侧 Tabs 和右侧 Tabs 允许横向滚动。

### 6.3 移动端

- 首页展示交易列表。
- 点击交易后进入订单详情全屏页。
- Chart 全屏显示。
- Notes 使用 Bottom Sheet 或独立全屏编辑器。

## 7. 推荐接口

### 7.1 订单详情

```text
GET /api/v1/trades/{trade_id}
```

返回订单统计、账户、品种、复盘状态。

### 7.2 执行明细

```text
GET /api/v1/trades/{trade_id}/executions
```

### 7.3 相邻交易

```text
GET /api/v1/trades/{trade_id}/navigation?scope=...
```

返回上一笔、下一笔和当前序号。

### 7.4 复盘状态

```text
PATCH /api/v1/trades/{trade_id}/review
```

### 7.5 笔记

```text
GET /api/v1/trades/{trade_id}/notes
PUT /api/v1/trades/{trade_id}/notes
GET /api/v1/trades/{trade_id}/journal
PUT /api/v1/trades/{trade_id}/journal
```

### 7.6 附件

```text
GET /api/v1/trades/{trade_id}/attachments
POST /api/v1/trades/{trade_id}/attachments
DELETE /api/v1/trades/{trade_id}/attachments/{attachment_id}
```

### 7.7 分享

```text
POST /api/v1/trades/{trade_id}/share
GET /api/v1/shared/trades/{share_token}
```

## 10. 验收标准

- 从交易记录、总览和月历均可进入同一订单详情。
- 左侧列表、上一笔/下一笔和 URL 状态同步。
- Stats 字段与交易记录和统计口径一致。
- Executions 数量、时间、价格、数量和 Gross P&L 正确。
- Unknown symbol 不阻塞详情页。
- Reviewed、Note、Strategy 和 Attachment 保存后可恢复。
- 复盘的失败状态可回滚，不产生假成功。
- Chart 和 Running P&L 数据不足时显示明确空态，不伪造数据。
- 桌面、平板、移动端无页面级横向溢出。
- 所有按钮、Tabs、Dialog、上传和菜单使用标准控件。

## 11. 风险

- MT5 成交不包含逐 tick 行情，Running P&L 无法仅靠成交还原。
- 图表需要独立行情数据源，否则只能显示 execution 点位。
- 附件需要对象存储，不能写入本地磁盘。
- 富文本编辑器会扩大一期范围，建议先 Markdown。
- 分享功能涉及账户和金额隐私，必须单独做权限设计。
