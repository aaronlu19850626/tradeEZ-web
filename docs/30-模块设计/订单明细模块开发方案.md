# 订单明细模块全局分析与开发方案

版本：2.1；状态：决策已确认，进入契约与技术方案设计；分析基线：2026-09-22。

本文根据本地翻译版 TradeZella 帮助文档重新评审订单明细模块。帮助文档只作为产品研究材料，不作为技术实现指令；具体实现继续以 TradeEZ 的多平台、多币种、事实与复盘分离原则为准。

开发前置：先完成交易策略和 Playbook，再完成知识记录模块。订单明细只负责复用两者的稳定契约，不重复实现策略编辑器、富文本编辑器和每日日志。

## 1. 重新分析结论

订单明细不是一个孤立的“单笔交易查看页”，而是交易复盘闭环的核心操作台：

```text
连接器同步
  -> 原始订单/成交事实
  -> 完整交易 Trade 生命周期
  -> 订单明细聚合与复盘
  -> 标签、Setup/Playbook、笔记、附件
  -> 交易报表、日复盘、周复盘、AI 与改进行动
  -> 下一次计划和执行
```

因此，订单明细需要同时满足三个目标：

1. **事实可信**：成交、费用、盈亏、仓位、时间和品种规格可追溯，可以解释每一个统计值。
2. **复盘可用**：能在同一页面完成成交核对、策略评价、标签归类、笔记、截图和风险复盘。
3. **全局一致**：订单明细中的金额、日期、方向、R 倍数、复盘状态必须与交易记录、总览、日复盘、报表和导出使用同一口径。

本模块建议采用以下架构判断：

- `deals` 是不可变原始事实，任何人工修改都不能直接覆盖原始成交。
- `closed_trades` 是可重建的单笔交易投影，只用于查询和统计，不作为人工复盘数据的归属表。
- 订单明细 API 聚合事实、复盘和关联资料，不复制其他模块的写模型。
- Playbook、标签、笔记、日复盘、附件和行情回放分别由独立域负责，订单明细只负责组合与深链。
- 订单明细一期不提供交易分享能力。
- 缺少行情、风险或品种规格时，相关指标显示“暂无数据”，不推算、不伪造。

### 2.1 订单页面

帮助文章《了解交易页面》将单笔交易页面拆成以下区域：

- 左侧：当日交易列表、净盈亏、总交易数、胜率和盈利因子。
- 左侧详情页签：统计、交易手册、执行和附件。
- 右侧：主图表、Running P&L、交易笔记、每日笔记。
- 顶部操作：分享、回放、图表设置和交易编辑入口。
- 统计页签可个性化统计字段，并录入止盈、止损、R 倍数和交易标签。
- 执行页签可以查看全部成交，也可以进入成交编辑链路。
- 每日笔记与交易笔记属于不同范围：交易笔记只关联当前交易，每日笔记会被当天所有交易和日视图共享。

对我们的影响：

- 页面结构可以复用，但“交易笔记”和“日复盘”必须拆成两个数据实体。
- “统计字段个性化”应属于用户列偏好，不应改变服务端统计口径。
- 订单明细内的编辑入口必须进入受审计的修正流程，不能直接覆盖 `deals`。

### 2.2 成交、费用与利润

《如何手动添加佣金和费用》《不同的利润计算方法》《了解 NET ROI 计算》说明：

- 佣金和费用可以按账户、品种、成交方向、执行范围设置默认规则。
- 新导入交易可自动应用规则；已有交易可批量应用，并明确是否覆盖已有值。
- 外汇库存费可能作为费用的一部分处理。
- Net ROI 使用调整后成本或收益，调整后成本为数量、乘数和价格的组合。
- FIFO、LIFO 和加权平均是账户级利润计算方式，会影响未使用唯一持仓编号的平台。

对我们的影响：

- 佣金与费用规则属于账户域，订单明细只展示规则来源和最终金额。
- 必须新增“费用来源”标记：平台原始值、账户默认规则、人工修正或系统计算。
- 调整后成本需要 `multiplier/contract multiplier`，不能只用当前 `contract_size` 近似。
- MT5 已有 `position_id`，应优先沿用平台持仓事实；FIFO/LIFO/加权平均只作为缺少持仓关联时的账户级计算策略。

### 2.3 风险与 R 倍数

《了解 R-Multiple》和《设置止盈和止损》定义了以下计算：

```text
交易风险 = 初始止损对应的潜在亏损
初始目标 = 止盈对应的潜在盈利
计划 R = 初始目标 / 交易风险
已实现 R = 净盈亏 / 交易风险
```

TradeZella 支持六类风险输入方式：

| 方式 | 含义 |
|---|---|
| 价格 | 直接录入止盈和止损价格 |
| 价格走势 | 按入场后的价格变化量计算 |
| Ticks | 按最小变动单位计算 |
| Points | 按平台点数计算 |
| PnL | 按期望的金额盈利或亏损计算 |
| Pips | 按外汇点数计算 |

同时支持多个止盈和止损级别，每个级别包含价格和数量。

对我们的影响：

- 当前单一 `sl_price`、`tp_price` 只能支持基础 R 展示。
- 完整方案需要“风险计划”实体，保存计算类型、级别、数量、来源和快照。
- 没有有效止损、止损与方向矛盾、数量不足或品种规格缺失时，R 必须为空并显示原因。
- 订单明细中的 R 不应直接修改交易事实，而是修改与当前 Trade 关联的风险计划。

### 2.4 最大不利偏移、最大有利偏移和运行盈亏

《了解 MAE 和 MFE》《未实现盈亏 FAQ》明确：

- Price MAE 是持仓期间的最大不利价格偏移。
- Price MFE 是持仓期间的最大有利价格偏移。
- Running P&L 是单笔持仓期间的浮动盈亏历史。
- 导入交易只有已平仓或部分平仓的已实现盈亏才进入正式统计。
- Running P&L 依赖持仓期间行情，不是仅凭两笔成交即可精确计算。

对我们的影响：

- MAE、MFE 和 Running P&L 必须依赖 `market_bars`、tick 或等价行情源。
- 行情缺失时显示明确空态，不以开平仓线性插值冒充真实曲线。
- 最小可用版本可以先提供基于分钟 OHLC 的估算，字段和 UI 必须标记“估算”。
- 所有价格图表、MAE/MFE 和 Running P&L 必须使用同一展示时区。
- 已确认 Running P&L、MAE/MFE 和回放属于一期交付；现有行情接口和回放组件可以复用，具体行情技术方案另行评审。

### 2.5 标签、策略和笔记

帮助文档确认它们是不同业务对象：

- 交易标签按类别组织，支持颜色、描述、创建、删除、合并和报表分析。
- 标签可以来自交易详情或日交易页面，标签结果会影响报表和筛选。
- 笔记标签与交易标签不同，互不同步。
- Setup/Playbook 包含分组和规则，规则可按盈利、亏损、盈亏平衡或始终显示。
- 交易可以关联 Playbook，并逐条勾选规则；报表按规则计算遵循率、胜率、盈利因子和净盈亏。
- 交易笔记最多一笔交易一条；每日笔记按交易日共享，并可被当天所有交易访问。

对我们的影响：

- 标签不能再只存在于 `trade_reviews.tags_json`，后续应迁移到规范化表。
- 订单明细需要展示规则的当时版本和执行结果，历史评价不能因 Playbook 更新而改变。
- 交易笔记、日复盘、笔记文件夹是三个层次，不能合并为一段自由文本。
- 标签、笔记和规则评价属于用户资料，重同步交易事实时默认保留并进入待核对状态。

### 2.6 图表、回放、编辑和分享

相关帮助文章还说明：

- 图表支持默认指标、图表设置、执行箭头、盘前盘后数据和画线。
- 分享交易时可以分享带回放能力的链接。
- 回放可以按成交跳转，并支持同时回放多笔交易。
- 交易日志支持自定义列、排序、筛选、合并、拆分、转移和删除。
- 成交可以编辑；删除交易会同时影响关联笔记和标签。

对我们的影响：

- 图表引擎、回放和指标应复用独立模块，订单明细只携带 `trade_ref` 和 `execution_ref` 深链。
- 原生成交不允许原地编辑；使用“修正记录 + 原始值保留”的方式。
- 合并、拆分和转移属于交易记录批量操作，订单明细只展示归并问题和关联明细。
- 分享属于单独的隐私与权限域，已确认一期不实现，只在模块边界上保留未来扩展位置。

## 3. 全局业务闭环

### 3.1 数据闭环

```text
平台连接器
  -> 原始订单 Orders
  -> 原始成交 Deals
  -> 持仓 Position
  -> 完整交易 Trade Lifecycle
  -> closed_trades 查询投影
  -> 订单明细聚合
```

支持后续 MT4、cTrader、ATAS 和 CTP 时，订单明细不得依赖 MT5 专属字段。连接器统一输出：

- 账户和平台
- 市场类型
- 品种标识
- 原始订单和成交标识
- 持仓或交易生命周期标识
- 成交方向、开平类型、数量、价格、费用和时间
- 品种规格与合约乘数
- 数据来源和同步批次

### 3.2 复盘闭环

```text
交易记录 / 总览 / 日历 / 回放
  -> 打开订单明细
  -> 核对事实和成交
  -> 关联 Setup/Playbook
  -> 逐条规则评价
  -> 标签归类
  -> 交易笔记和日复盘
  -> 截图与行情证据
  -> 标记已复盘
  -> 进入报表、日复盘和周复盘
```

### 3.3 改进闭环

```text
订单明细结论
  -> 标签与规则执行统计
  -> 发现重复错误或有效模式
  -> 转化为改进行动
  -> 进入下一次计划或 Playbook 修订
```

订单明细不能只把数据展示出来，还必须让用户能够回答：

1. 这笔交易事实上发生了什么？
2. 当时计划是什么？
3. 哪些规则执行了，哪些没有执行？
4. 这笔交易应该归入什么机会、错误和情绪类别？
5. 下次要保留或改变什么？

## 4. 对象与职责边界

| 对象 | 唯一真相源 | 订单明细职责 | 所属域 | 阶段 |
|---|---|---|---|---|
| Deal | `deals` | 展示和关联成交修正 | 交易事实 | P0 |
| Trade | `closed_trades` 或后续 `trades` 投影 | 展示生命周期和派生统计 | 交易事实 | P0 |
| Execution | Deal 的视图 | 时间线、数量和盈亏归属 | 交易事实 | P0 |
| Symbol Spec | 版本化品种规格 | 提供 tick、乘数、币种和精度 | 行情/账户 | P0 |
| Risk Plan | 风险计划表 | 展示 R、目标、止损和级别 | 复盘 | 一期 |
| Trade Review | `trade_reviews` | 状态、结论和版本 | 复盘 | 已实现 |
| Trade Note | 独立交易笔记实体 | 仅关联当前交易 | 笔记 | 一期 |
| Daily Journal | `daily_reviews` | 读取当天共享内容 | 日复盘 | 复用一期 |
| Trade Tags | 规范化标签表 | 选择、创建和展示 | 标签 | 一期 |
| Note Tags | 笔记标签关系 | 不从交易标签复制 | 笔记 | P2 |
| Playbook Evaluation | `review_evaluations` | 选择版本、规则回答和结果 | Playbook | 一期 |
| Attachment | `trade_attachments` | 上传、预览和分类 | 附件 | 一期 |
| Market Bars/Ticks | 外部行情或本地缓存 | 图表、MAE/MFE、Running P&L | 行情 | 一期 |
| Replay Session | 回放模块 | 携带成交定位参数并跳转 | 回放 | 一期 |
| Share Link | 分享链接表 | 本期不实现 | 分享 | 暂不实施 |

### 4.1 稳定交易标识

对外 API 不使用数据库自增 `id` 作为长期标识。推荐使用稳定交易引用：

```text
trade_ref = opaque(account_id, position_id, anchor_ticket)
```

理由：

- 交易重算或投影重建后，自增 ID 可能变化。
- 复盘资料要用 `account_id + position_id + anchor_ticket` 恢复关联。
- 成交与持仓的定位需要稳定引用，方便分享、回放和导出。

### 4.2 原始事实与人工修正

订单明细允许用户纠正展示信息，但不能直接覆盖原始事实：

| 场景 | 允许方式 |
|---|---|
| 修改佣金或费用 | 新增修正记录，保留平台原值 |
| 修改成交价格或数量 | 新建修正版本，重新构建 Trade |
| 修改品种 | 人工映射或修正记录 |
| 修改归并 | 交易记录模块的合并/拆分流程 |
| 修改复盘内容 | 复盘版本表 |
| 删除交易 | 进入交易记录批量危险操作 |

## 5. 页面信息架构

### 5.1 左侧交易列表

保留交易列表作为连续复盘导航，但范围为打开订单时携带的查询上下文。

- 顶部：当前日期、前后日期、日期选择。
- 当日统计：净盈亏、总交易数、胜率、盈利因子。
- 交易卡片：品种、方向、净盈亏、开平仓时间、复盘状态。
- 交易卡片不显示过多派生指标，避免挤压详情空间。
- 移动端折叠为顶部交易选择器，不保留固定窄栏。
- 桌面端支持收起，但状态写入用户偏好。

### 5.2 顶部操作区

建议保留：

- 返回当前列表
- 上一笔、下一笔
- 品种、市场徽标和时间
- 未匹配品种提示
- 已复盘状态
- 回放
- 更多操作

不建议：

- 将“已复盘”作为独立布尔字段与复盘状态并列保存。
- 在无行情或无成交时仍提供可用但点击无结果的动作。

建议将 `review_status` 作为复盘状态的唯一来源。顶部“标记已复盘”是状态操作或快捷入口，不新增第二套状态。

### 5.3 统计 Stats

按信息层级分组，而不是平铺大量指标：

**事实区**

- 账户和平台
- 品种和市场
- 方向
- 成交量或合约数
- 开仓均价、平仓均价
- 首次开仓、最终平仓
- 持仓时长

**盈亏区**

- Gross P&L
- 库存费
- 佣金和费用
- Net P&L
- 调整后成本
- Net ROI

**风险区**

- 止损、止盈
- 初始风险
- 初始目标
- 计划 R
- 已实现 R
- MAE、MFE

**复盘区**

- Setup
- Playbook 版本
- 执行分和规则结论
- 标签
- 评分
- 复盘状态

每个派生值都应支持 Tooltip 展示口径和来源：

```text
来源：平台成交
口径：净盈亏 / 初始风险
状态：已计算
```

缺失值显示原因：

```text
无法计算 R
原因：未设置有效止损，或品种规格缺失
```

### 5.4 策略 Playbook

一期复用已实现的 Setup、Playbook 和评价能力：

- 未关联时显示可选 Playbook。
- 已关联时固定显示当时版本。
- 规则按检查时点和分组展示。
- 回答支持 PASS、FAIL、UNKNOWN、N/A 和证据。
- 完整度、覆盖率、执行分和关键违规由系统计算。
- Playbook 更新不会改变历史评价快照。

订单明细内不重复实现 Playbook 编辑器。

### 5.5 成交 Executions

执行明细应同时服务于核对、盈亏归属和图表定位：

| 列 | 说明 |
|---|---|
| 时间 | 使用全局展示时间，悬浮可看原始服务器时间 |
| 类型 | 开仓、加仓、减仓、平仓、反向 |
| 价格 | 原始成交价格 |
| 数量 | 展示层相对持仓方向的带符号数量 |
| 佣金 | 该成交佣金 |
| 费用 | 该成交费用 |
| 库存费 | 发生在该成交或持仓级别的库存费 |
| 已实现盈亏 | 平仓或减仓成交对应的盈亏 |
| 来源 | 平台同步或人工修正 |

数量符号只在展示层计算：

```text
direction_factor = long ? +1 : -1
entry_factor = open ? +1 : -1
display_quantity = volume * direction_factor * entry_factor
```

内部计算始终使用无符号 `volume`、`entry` 和 `type`。

执行表格应支持：

- 查看全部
- 跳转到图表
- 跳转到回放
- 查看来源成交标识
- 查看修正记录

### 5.6 附件

附件至少按以下用途分类：

- 盘前计划
- 入场证据
- 退出证据
- 复盘截图
- 其他

已确认将附件升级为 `trade_attachments`。现有 `review_attachments` 作为迁移来源，不建立长期双写：

- `trade_ref` 为交易级归属，`review_id` 改为可空关联。
- 文件元数据与二进制分开。
- 支持标题、说明、周期、排序、替换和软删除。
- 私有对象存储或受控 BLOB 存储，访问必须鉴权。

不要在订单明细和复盘模块建立两套附件存储。

### 5.7 图表 Chart

图表复用项目现有图表实验室、回放和 `lightweight-charts` 能力。

| 数据条件 | 能力 |
|---|---|
| 有成交、无行情 | 只显示成交点位 |
| 有 OHLC | 显示蜡烛、成交标记和手动画线 |
| 有 tick | 支持更精细的回放和 Running P&L |
| 无品种规格 | 显示未匹配提示，不伪造价格轴 |

图表需要统一处理：

- 展示时区
- 常规/延长交易时段
- 成交在价格点或 K 线上方两种显示方式
- 指标和图表设置的个人默认值
- 画线与交易或品种时间的归属
- 全屏和移动端布局

### 5.8 知识记录候选接口（待重新评审）

本节是旧方案中的接口候选，不是当前 Notebook、笔记历史或笔记模板的需求事实。订单明细只保留可扩展的关联边界；具体对象、基数、标签和入口必须等核心模块盘点与新需求评审后确定。

必须区分：

| 内容 | 范围 | 写法 |
|---|---|---|
| 交易记录内容 | 一笔交易 | 关联基数和入口待评审 |
| 每日笔记 | 一个交易日 | 一笔内容被当天所有交易共享 |
| 内容标签 | 待定义对象 | 是否与交易标签分离待评审 |
| 复盘结论 | 复盘状态的一部分 | 版本化保存 |

一期建议：

- 复用现有复盘笔记保存交易结论。
- 新增独立的交易笔记实体，确保“交易笔记”和“日复盘”不混写。

- 编辑器先支持 Markdown 或基础富文本。
- 语音、嵌入视频、复杂表格和 PDF 导出放后续阶段。

### 5.9 Running P&L

Running P&L 的展示必须带数据质量标识：

| 数据质量 | 展示 |
|---|---|
| tick 行情 | 精确曲线 |
| 分钟 OHLC | 估算曲线，明确标注 |
| 仅成交 | 显示空态和缺失原因 |
| 未平仓 | 可显示当前浮动，但不进入已实现统计 |

计算依赖：

- 持仓方向和数量
- 合约乘数
- 报价币种与账户币种换算
- 行情时间戳
- 部分平仓后的剩余仓位
- 展示时区

## 6. 统计口径

### 6.1 金额

统一公式：

```text
gross_profit = sum(exit_deal.profit)
swap = sum(deal.swap)
commission = sum(deal.commission)
fees = sum(deal.fee)
gross_pnl = gross_profit + swap
net_pnl = gross_profit + swap + commission + fees
```

当前系统尚未单独保存 `fee` 时，可将费用并入 `commission`，但 API 字段中应预留区分能力。

### 6.2 调整后成本和 Net ROI

```text
adjusted_cost = sum(entry_execution.volume * multiplier * entry_price)
net_roi = (realized_return - adjusted_cost - fees) / adjusted_cost
```

约束：

- `multiplier` 必须来自当时有效的品种规格版本。
- 外汇的调整后成本是名义价值，可能明显大于保证金，UI 必须解释这一点。
- 跨币种报价或账户币种不一致时，必须先转换为账户币种。
- 缺少乘数或汇率时，Net ROI 显示不可计算。

### 6.3 R 倍数

```text
trade_risk = sum(risk_level.price_distance * quantity * point_value)
initial_target = sum(target_level.price_distance * quantity * point_value)
planned_r = initial_target / trade_risk
realized_r = net_pnl / trade_risk
```

只有以下条件同时满足才计算：

- 风险和方向一致
- 止损价格有效
- 数量有效
- 品种规格有效
- 能转换为账户币种

### 6.4 每日盈亏归属

根据帮助文档，日历和日复盘的主要盈亏按平仓或部分平仓时间归属：

- 开仓当天不产生已实现盈亏。
- 部分平仓当天只反映该次实现的部分。
- 完全平仓当天反映剩余实现盈亏。
- 订单明细显示整笔 Trade 的总净盈亏，同时展示平仓成交归属。

因此订单明细需要明确显示：

```text
这笔交易的总净盈亏
其中各次平仓分别归属哪个交易日
```

该规则要与交易记录、总览月历、日复盘和一致性统计保持一致。

### 6.5 MAE、MFE

```text
long: MAE = min(low) - entry_price
long: MFE = max(high) - entry_price
short: MAE = entry_price - max(high)
short: MFE = entry_price - min(low)
```

必须使用完整持仓区间内的行情，并明确是否包含盘前盘后和周末隔夜。

### 6.6 盈亏平衡区间

盈亏平衡区间是展示和分类规则，不修改原始盈亏：

- 账户级配置金额或百分比。
- 在范围内显示为盈亏平衡。
- 订单明细仍显示真实 Net P&L。
- 交易记录和日历使用同一配置。

### 6.7 Zella Scale 类执行标尺

帮助文档把 Zella Scale 定义为“潜在结果与实际结果”的对比：

```text
潜在结果 = 如果交易按计划运行，在这段行情中可能实现的盈利或亏损
实际结果 = 实际净盈亏
差距 = 潜在结果 - 实际结果
```

该指标依赖计划目标、最大有利/不利价格和行情数据，不能在缺少数据时只用目标价与净盈亏反推。

TradeEZ 第一阶段不复制 Zella 品牌和算法，建议使用“执行标尺”作为内部概念：

- 数据成熟后再定义公式和权重。
- 明确是价格空间指标还是金额指标。
- 与 R 倍数、MAE、MFE 分开，不合并成含义不明的综合分。
- 只有规则、目标和行情证据完整时才计算。

## 7. 交互与状态

### 7.1 页面加载

- 详情骨架和查询上下文分开加载。
- 事实数据优先，行情和 Running P&L 延迟加载。
- 加载期间禁止修改复盘状态、规则和附件。
- 大数据量统计显示“正在汇总”的轻量提示。
- 局部失败不阻塞整个详情页。

### 7.2 编辑策略

| 操作 | 保存策略 |
|---|---|
| 已复盘状态 | 乐观更新，失败回滚 |
| 标签 | 选择后显式保存或统一保存 |
| Playbook 规则 | 保存为评价版本 |
| 交易笔记 | 自动保存，带版本冲突提示 |
| 日复盘 | 独立保存，与交易笔记分离 |
| 附件 | 上传成功即落库，不依赖笔记保存 |
| 修正成交 | 建立修正记录并异步重建 Trade |

### 7.3 导航和返回

- 上一笔、下一笔必须限制在打开详情时的筛选上下文。
- URL 应保存 `trade_ref` 和 `scope_token`。
- 返回交易记录时恢复原视图、分页、排序和筛选。
- 从总览、日历、回放进入时，也使用相同详情页。
- 未保存编辑退出时提示。

### 7.4 响应式

- 桌面：左侧列表 + 详情区。
- 平板：列表可收起，详情区占满。
- 移动：列表和详情分层，Tab 可横向滚动。
- 图表全屏，笔记使用独立全屏编辑或底部抽屉。
- 不产生页面级横向溢出。

## 10. 开发阶段

### 阶段 A：订单明细事实框架

- 稳定 `trade_ref`
- 详情聚合接口
- Executions
- Stats
- 数据完整性问题
- 复盘状态与版本
- 上一笔、下一笔和来源上下文

退出条件：

- 交易记录、总览和日历可以进入同一详情。
- 金额、方向、时间和成交数量与来源一致。
- 缺失字段有原因，不显示假数据。

### 阶段 B：复盘资料闭环

- 交易标签
- 交易笔记和日复盘
- 附件
- 复盘保存、冲突和重同步保留

退出条件：

- 交易标签与笔记标签不混用。
- 日复盘和交易笔记双向进入同一内容。
- 重同步不丢失人工资料。

### 阶段 C：策略执行和风险

- Setup/Playbook 关联
- 规则评价
- 多止盈、多止损
- 风险计划
- 计划 R 和已实现 R
- 费用规则和来源

退出条件：

- 没有止损时 R 为空并说明原因。
- 多级退出计算正确。
- Playbook 更新不改变历史评价。

### 阶段 D：行情和高级分析（一期必做）

- 图表
- MAE、MFE
- Running P&L
- 成交图表定位
- 回放深链

行情技术方案待专项评审，至少需要确定：

- 行情供应商、授权范围和覆盖品种。
- tick、分钟线或两者并存的粒度。
- 历史数据回填范围和存储位置。
- 部分平仓、隔夜、周末和停牌期间的数据处理。
- 展示时区和夏令时规则。
- 预估与精确数据的标识。
- 行情缺失时的降级策略。

退出条件：

- 无行情时明确降级。
- 估算和精确数据区分。
- 时间轴与交易记录、日复盘一致。
- MAE、MFE、Running P&L 和回放通过同一组订单样本验收。

### 阶段 E：AI 增强

- AI 复盘上下文
- 自动标签建议
- 图表和笔记辅助

退出条件：

- AI 只能读取授权上下文，修改必须显式确认。

## 11. 对其他模块的影响

### 交易记录

- 行点击进入稳定 `trade_ref`。
- 批量标签、复盘、合并、拆分和转移保留在列表。
- 列表筛选需要支持复盘标签、Playbook 和风险完整度。
- 平仓实现归属应与订单明细一致。

### 交易总览

- 最近交易点击进入订单明细。
- 总览统计和订单明细使用同一金额、方向、时段和币种口径。
- 日历金额按平仓或部分平仓归属。

### 日复盘

- 复用同一批平仓实现盈亏。
- 日复盘笔记与交易笔记分表。
- 订单明细中的日复盘是共享内容的入口，不是副本。

### 报表

- 标签、Setup、Playbook、执行分和错误分类来自订单明细关联资料。
- 报表必须返回样本数和缺失原因。
- 修改标签或规则后，统计更新但历史复盘文字不自动改写。

### 行情回放

- 订单明细携带成交标识跳转到回放。
- 回放定位到成交的准确时间点。
- 多笔回放和单笔回放使用同一成交引用。

### AI 中心

- AI 可读取订单事实、复盘和规则结果。
- AI 不得绕过权限。
- 自动写入标签、笔记或规则前必须由用户确认。
- AI 建议要区分来源，不能伪装成用户判断。

### 账户设置

- 币种、市场类型和利润计算方法属于账户配置。
- 默认佣金、费用和风险规则属于账户或品种配置。
- 订单明细只展示并应用，不在页面内复制设置。

## 12. 验收和数据测试

### 12.1 事实一致性

- 从交易记录、总览、日历和回放进入，看到同一笔交易。
- 执行数量、价格、费用、时间与原始成交一致。
- 重算出 `closed_trades` 后 `trade_ref` 不变化。
- 部分平仓保留全部成交，但只计一笔完整交易。

### 12.2 金额和归属

- 测试净盈亏、Gross P&L、库存费、佣金和费用。
- 测试一笔开仓、三次跨日部分平仓。
- 日复盘只显示每个平仓日的实现部分。
- 订单明细显示整笔交易总净盈亏。
- 测试零手续费、负库存费、正库存费和人工修正费用。

### 12.3 R 和风险

- 没有止损时 R 为空。
- 止损方向错误时拒绝计算。
- 单一止盈止损计算正确。
- 多级止盈和止损按数量计算正确。
- 品种乘数缺失时 R 为空。

### 12.4 复盘资料

- 交易标签与笔记标签互不影响。
- 交易笔记只能关联一笔交易。
- 每日笔记被当天多笔交易共享。
- Playbook 更新后历史评价版本仍可查看。
- 附件删除后旧链接不可访问。
- 重同步后复盘保留，事实变化时进入待核对。

### 12.5 行情降级

- 无行情时图表只显示成交点位。
- 无行情时 MAE、MFE 和 Running P&L 显示明确空态。
- 分钟行情显示估算标识。
- 切换展示时区后成交和图表时间一致。

### 12.6 UI 和性能

- 所有按钮、Tabs、Dialog、输入和上传使用标准控件。
- 数字统一格式化，超过 10,000 使用 K 值规则。
- 国内期货和外汇的盈亏颜色按市场规则，但方向徽标不依赖盈亏色。
- 加载期间禁止修改筛选和报告状态。
- 大数据量下首屏不被 Running P&L 和图表阻塞。
- 桌面、平板和移动端无正文溢出或遮挡。

## 13. 主要风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 行情技术方案未定 | 一期要求的图表、MAE/MFE、Running P&L 和回放无法收口 | 先完成专项技术评审，再冻结接口和数据模型 |
| 品种规格不完整 | Net ROI、R 和金额换算错误 | 规格版本化，缺失时不计算 |
| 复盘与投影紧耦合 | 重同步丢失人工资料 | 用稳定引用和待恢复机制 |
| 标签存在 JSON 中 | 无法高效筛选、合并和统计 | 迁移到规范化标签表 |
| 交易笔记和日复盘混写 | 一笔修改影响多笔交易 | 拆成独立实体 |
| 直接编辑成交 | 破坏可信事实 | 修正记录和审计 |
| 一次实现全部高级能力 | 周期过长，核心链路受阻 | 按 A-E 阶段推进 |

## 14. 已确认决策

| 序号 | 已确认决策 |

| 1 | 订单明细一期只读交易事实，所有成交修改走受审计的修正流程。 |

## 15. 建议的下一步

下一阶段按以下顺序推进：

1. 完成交易策略和 Playbook 模块，冻结策略、规则版本和评价契约。
2. 完成核心模块盘点后，评审是否以及如何建设知识记录能力。
3. 固化 `TradeDetailOut`、`ExecutionOut`、`RiskPlanOut`、`ReviewOut` 和能力标记契约。
4. 输出 `trade_ref`、交易笔记、规范化标签、`trade_attachments` 和多级风险计划的迁移方案。
5. 完成行情专项技术方案，明确数据源、行情粒度、存储、回填、时区和降级规则。
6. 做只读事实版订单明细页面原型，完成与交易记录、总览和日复盘的数据对账。
7. 只接入一期评审确认的复盘、Playbook、知识记录、风险计划和行情能力，按 A-E 阶段验收。
