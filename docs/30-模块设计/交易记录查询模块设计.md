# M2 交易记录查询详细设计（需求稿）

版本：0.6；状态：前后端已接入真实数据；币种与国内期货扩展见《多币种与国内期货准备方案》。

本稿依据用户提供的三张 TradeZella 参考图（参考图 1 按天、参考图 2 按周、参考图 3 全部）整理，并把 TradeZella 的交互映射到本项目已有的账户、派生交易和原始成交数据。订单明细（单笔交易详情）与复盘在一起较复杂，另立模块，不在本稿范围。

## 1. 模块目标与范围

### 1.1 目标

让登录用户按“按天 / 按周 / 全部”三种视图检索、浏览并对比自己已同步的 MT5 交易记录与表现，回答：某个时期我做了哪些交易、结果如何、好坏集中在哪些天或哪个品种、整体是否稳定。

### 1.2 本模块包含

- 三种视图模式：按天、按周、全部。
- 全局工具栏：账户范围、币种、日期范围、筛选、视图密度切换。
- 右侧月历：按日盈亏着色，用于定位和跳转。
- 分组内图表（累计盈亏曲线、每日盈亏柱状、最大盈亏标尺）与指标卡。
- 交易只读列表（分页与数量提示），支持多账户。

### 1.3 本模块不包含（后续独立模块）

- 订单明细：单笔交易详情、成交分摊展开、来源成交清单。
- 复盘：笔记、标签、截图、规则评估、执行评分、复盘状态（未写/草稿/已复盘）。
- 手动添加交易、Trade Replay（K 线回放）、AI 助手与“View note / Start my day”。
- 批量操作中的合并交易、拆分交易、转移交易、打标签、加入策略。
- 导出（可作为一个轻量后续项单独确认）。

### 1.4 数据来源

- 账户 `accounts`、派生交易 `trade_lifecycles` / `trade_allocations`、原始成交 `deals`、账户快照 `snapshots`。
- 交易归属日期沿用现有口径：按 UTC 平仓时间归属，不做本地时区偏移。

> 重要：账户模块清理时删除了旧的交易归并重建代码（原 `app/trades/*`）。本模块需要重新实现“成交 → 派生交易”的重建逻辑，否则没有可查询的 Trade 数据。这部分是后端第一件事。

## 2. 三种视图总览

| 视图 | 分组维度 | 分组头部 | 分组内容 | 列表 | 页面顶部 |
|---|---|---|---|---|---|
| 按天 | 交易日 | 星期+日期、当日净盈亏（着色） | 累计盈亏曲线 + 当日指标 | 当日交易列表 | 无独立顶部（在分组内） |
| 按周 | 统计周 | 周区间、周净盈亏（着色） | 7 天条 + 每日盈亏柱状 + 周指标 + 最大盈亏标尺 | 本周交易列表 | 无独立顶部（在分组内） |
| 全部 | 不分组 | — | — | 全量交易表格（分页） | 4 张指标卡 |

三种视图共用同一套工具栏、筛选、账户范围、月历和交易列表字段；差别只在分组方式和分组内的图表/指标。

## 3. 全局工具栏与页面框架

页面沿用现有 Dashboard 外壳。内容区自上而下：

1. 面包屑与页面标题：`交易 > 交易记录`，标题“交易记录”。
2. 视图切换 Tabs：`按天`、`按周`、`全部`，默认 `按天`。
3. 内容区右上工具栏（同一行排列）：

   | 控件 | 作用 | 一期 |
   |---|---|---|
   | 列显示 | 参考图工具栏最左侧图标；打开“选择列”浮层，决定表格显示哪些列 | 是 |
   | 币种 | 按账户币种筛选；混合币种强制选择单一币种 | 是 |
   | 筛选 | 方向、品种、结果（盈/亏/平）等 | 是（策略/标签放后续） |
   | 日期范围 | 双月日历区间选择 + 预设快捷 | 是 |
   | 账户范围 | 默认取账户模块的“统计账户”，页面顶部可临时显示 / 隐藏账户 | 是 |

   日期范围选择器（按用户确认图）：左右两个月的日历 + 顶部“起 → 止”区间显示，右侧预设快捷为 全部 / 今天 / 本周 / 本月 / 近 30 天 / 上月 / 本季度 / 年初至今；区间按统计时区（北京时间）计算。默认区间为**全部已同步数据**（最早一笔到最新一笔），头部按实际区间显示，用户可修改；日历打开时定位到区间末端月份，避免从最早月份向前翻页。

   列显示浮层（按用户确认图）：标题“选择列”，说明“选择要在表格中显示的列”；顶部为列名搜索框 + “恢复默认”；中间为列清单（即 §7 的列池），支持“全选 / 全不选”；底部为“取消 / 更新”。列选择结果按用户持久化到服务端，跨设备同步。

4. 内容区右侧：月历（独立于工具栏，位于列表右侧，可按需折叠）。
5. 内容区主体：按当前视图渲染分组卡片或全量表格。

账户范围默认取账户模块（M1）里已勾选的“统计账户”，汇总口径与 Dashboard 初始口径一致。页面顶部提供“账户范围”开关，可临时显示或隐藏账户：该调整只影响本页展示，不写入账户模块、不改变全局设置。

工具栏里 TradeZella 专有的“添加交易 / 开始我的一天”等入口不在本模块提供。

## 4. 视图一：按天（参考图 1）

按交易日分组，每个“有交易”的交易日一张可折叠卡片，默认展开。没有交易的日期不生成分组、不做补空（参考图 1 里“Net P&L $0”的空日期卡片在本项目中不显示）。默认区间为全部已同步数据；分组较多时按需加载，不一次性全部铺出。

### 4.1 分组头部

- 展开/折叠箭头。
- 日期：星期 + 日期，如“周四, 2026-09-17”。
- 当日净盈亏：按盈亏语义着色（盈利绿、亏损红、为零中性）。
- 右侧图标：保留“笔记”和“回放”图标（按确认保留）；点击后的笔记与回放能力在对应模块实现，一期先展示图标。

### 4.2 展开内容

- 累计盈亏曲线：当日按平仓顺序累计净盈亏，零轴为基线，盈利段绿、亏损段红（参考图为下降的红色面积）。
- 指标网格（两行排列）：总笔数、毛盈亏、盈利/亏损笔数、佣金、胜率、成交量、盈利因子。
- 交易列表：当日交易，字段见 §7。

参考图 1 的“周四 2026-09-17”示例：总笔数 5、毛盈亏 -$888.3、盈利/亏损 0/5、佣金 $0、胜率 0%、成交量 1.8、盈利因子 0.00。

## 5. 视图二：按周（参考图 2）

按统计周分组，只展示“有交易”的周，没有交易的周不生成分组、不做补空。默认区间为全部已同步数据。

### 5.1 分组头部

- 周区间，如“2026-09-14 ~ 2026-09-20”（周一 ~ 周日）。参考图 2 的示例按周日~周六分组（2026-09-13 ~ 2026-09-19），本项目按确认改用周一~周日。
- 周净盈亏（着色）。

### 5.2 分组内容

- 7 天条：按周一~周日排列，每格显示日期、方向图标、当天净盈亏、当天笔数；无交易日置灰；点击某天可下钻到该天（切到按天视图并定位，或按该天过滤）。
- 每日盈亏柱状图：7 天的净盈亏柱，零轴基线。
- 周指标网格：同按天，但按整周汇总。
- 盈亏区间标尺：区间起点记为 0，按平仓时间顺序累加净盈亏，取该累计曲线的最大净盈利（右，绿）与最大净亏损（左，红），大的一侧粗、小的一侧细。
- 交易列表：本周交易，字段见 §7。

参考图 2 的“2026-09-13 ~ 2026-09-19”示例：总笔数 94、毛盈亏 -$2,151.87、盈利/亏损 48/46、佣金 $12.81、胜率 51.06%、成交量 24.55、盈利因子 0.65（该图的最大亏损 / 最大盈利为单笔口径，本模块已改为累计曲线口径，见 §4）。

不分组，整体表现以顶部指标卡呈现，下面是全量交易表格。

### 6.1 顶部指标卡（4 张）

| 卡片 | 数值 | 图形 |

| 累计净盈亏 | 区间内累计净盈亏 | 累计盈亏面积曲线 |

全量交易表格，字段见 §7，支持分页；多账户时增加“账户”列。

> 参考图 3 的表格列（Adjusted cost、Adjusted proceeds、Average entry、Average exit、Best exit 系列等）是 TradeZella 的高级分析列。本项目一期的列以 §7 冻结清单为准，TradeZella 专有列（Best exit 逃顶分析等）作为后续可选。

## 7. 交易列表字段

### 7.1 固定列（各视图恒定显示、始终排在最前、列显示不可增删）

固定列顺序：平仓时间、建仓时间、品种、方向、交易量、净盈亏、开仓价、平仓价。

| 视图 | 固定列 |
|---|---|
| 按天 | 平仓时间、建仓时间、品种、方向、交易量、净盈亏、开仓价、平仓价 |
| 按周 | 交易日、平仓时间、建仓时间、品种、方向、交易量、净盈亏、开仓价、平仓价 |
| 全部 | 平仓时间、建仓时间、品种、方向、交易量、净盈亏、开仓价、平仓价（日期并入时间列，不单列交易日） |

- 可排序：交易日、平仓时间、建仓时间、品种、方向、交易量、净盈亏；点击表头切换升 / 降序。
- 不可排序：止损/止盈（已改为可选列）、策略。
- 按天视图不显示“交易日”，因为分组本身就是按天。

### 7.2 可选列（工具栏“列显示”维护，按视图各自保留选择）

固定列之后按下列顺序追加，未勾选的不显示：

| 顺序 | 字段 | 说明 |
|---|---|---|
| 1 | 盈亏比 | 已实现 R 倍数（逐笔口径），无止损时 N/A |
| 2 | 盈亏点数 | 价差 ÷ 品种常规点值 |
| 3 | 止损/止盈 | 合并展示该笔的止损价与止盈价，不可排序；**由用户在列显示中自行维护，不属于固定列** |
| 4 | 库存费 | 持仓过结算时间的费用 |
| 5 | 佣金 | 手续费 |
| 6 | 持仓时间 | “10小时3分钟 / 24分钟34秒 / 45秒”式展示 |
| 7 | 账户 | 多账户时区分账户 |
| 8 | 策略 | 依赖策略模块 |
| 9 | 评分 | 单笔交易评分（0–100，含"待复盘"角标），口径见《Dashboard（总览）模块设计》§4.2；默认关闭 |

默认开启（按视图区分）：按天与按周只开“盈亏比、持仓时间”；**全部视图默认开启全部可选列**，方便用户一次看到全部字段后自行收敛。列显示浮层只列出可选列并说明固定列范围；“恢复默认”按当前视图的默认值恢复。选择结果按用户持久化到服务端，跨设备同步。

### 7.3 对齐与列宽

表格使用固定布局（`table-layout: fixed` + 列宽声明），表头与单元格使用同一套对齐规则，避免出现某些列被撑宽、右侧留大段空白的情况。

| 列 | 对齐 | 宽度 | 理由 |
|---|---|---|---|
| 交易日 / 账户 / 策略 | 左 | 96 | 文本类字段左对齐符合阅读顺序 |
| 平仓时间 / 建仓时间 | 居中 | 96 | 定长值，居中后整列视觉重量均衡 |
| 品种 / 方向 | 居中 | 88 / 72 | 短标识与状态标签居中更整齐 |
| 交易量 | 右 | 80 | 数量右对齐，小数位对齐 |
| 净盈亏 | 右 | 100 | 金额右对齐，正负号成列 |
| 止损/止盈 | 居中 | 164 | 复合值（SL / TP），居中避免与单值金额列混淆 |
| 开仓价 / 平仓价 | 右 | 96 | 价格右对齐，便于纵向比对 |
| 盈亏比 / 盈亏点数 | 右 | 84 / 88 | 数值右对齐 |
| 库存费 / 佣金 | 右 | 88 | 金额右对齐 |
| 持仓时间 | 右 | 96 | 数量型文本右对齐，右边缘成列 |
| 多选列 | 居中 | 44 | 勾选框居中 |

列宽之和不小于内容区宽度时表格横向滚动，内容区更宽时按列宽比例分配剩余空间。

默认排序：按平仓时间倒序（同一时间按交易 ID 倒序）；分组视图按分组倒序，组内同样按平仓时间倒序。列表分页每页最大 100 条。

## 8. 指标与口径定义

金额都以账户原币计算；多账户合计仅在同币种时成立。混合币种账户同时选中时，一期强制选择单一币种。

| 指标 | 口径 |
|---|---|
| 净盈亏 Net P&L | Σ(profit + swap + commission)，按派生交易汇总 |
| 毛盈亏 Gross P&L | Σ(profit + swap)，不含佣金 |
| 佣金 | Σ(commission) |
| 总笔数 | 参与统计的派生交易数 |
| 盈利 / 亏损 / 持平 | 按净盈亏 > 0 / < 0 / = 0 计数 |
| 胜率 | 盈利笔数 / 总笔数；持平计入分母 |
| 盈利因子 | 盈利合计 / 亏损合计绝对值；无亏损返回 N/A |
| 平均盈亏比 | 平均盈利 / 平均亏损绝对值；缺任一类返回 N/A |
| 成交量 | Σ volume |
| 净收益率 Net ROI | 净盈亏 / 名义成本（开仓价 × 合约规格 × 手数） |
| R 倍数 | 净盈亏 / 初始风险；初始风险 = \|开仓价 − 止损价\| × 合约规格 × 手数，无止损返回 N/A |
| 最大净盈利 / 最大净亏损 | 区间起点记为 0，按平仓时间顺序累加净盈亏，取累计曲线的最高点 / 最低点；未出现亏损时最大净亏损显示 $0.00，未出现盈利时最大净盈利显示 $0.00 |
| 累计盈亏曲线 | 区间内按平仓时间顺序累加净盈亏 |
| 回撤 | 基于累计盈亏曲线逐笔计算（非账户权益回撤） |

## 9. 数据来源与归属规则

- Trade 由 `deals` 派生：按 position_id 归并 IN/OUT/INOUT，产出 `trade_lifecycles` 与 `trade_allocations`（重建逻辑需重写，见 §1.4）。
- 交易状态：`complete`（完整）、`partial`（部分平仓）、`needs_review`（待核对）。
- 归属日期与统计周期：按服务器时区（北京时间，UTC+8）换算平仓时间后归属；统计周为周一至周日。注意这与旧分析文档“按 UTC 归属、不偏移时区”的口径不同，以本次确认为准。
- 未平仓：不列入指标统计（按确认）。部分平仓在全部平仓后一次计入；待核对（needs_review）计入指标（按确认）。
- 只在账户所有者范围内查询；默认范围限定为账户模块的统计账户，页面内可临时增减。金额按账户币种展示，混合币种账户同时选中时强制选择单一币种，不做跨币种换算。

## 10. 交互、状态与全局样式

沿用《全局样式规则》，本模块只补充特有项：

- 盈亏颜色只在表达盈亏时使用；缺失数据用 N/A，不用 0 代替。
- 指标卡标题旁提供 `?` 提示，说明口径与范围；Tooltip 最大宽度 256px。
- 表格表头浅紫灰、加粗、约 40px；时间/金额用等宽数字；核心操作行内。
- 所有可点击元素显示手型；禁用态不显示手型并保持对比度。
- 状态表现：加载骨架（保留标题与表头）、空状态（无交易时引导配置 EA 或导入）、失败局部错误与重试（不清空已有数据）、无数据用 N/A。
- 视图切换、筛选、日期范围变化都应更新 URL 查询参数，支持深链与刷新保持。

## 11. 接口方案（已实现，2026-09-20）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/trades/summary` | 全部视图指标：`{ stats, series }`（stats 含 §8 全部指标，series 为累计净盈亏曲线） |
| GET | `/api/v1/trades` | 交易列表：`{ items, total, page, page_size }`，分页（上限 100）、筛选、排序 |
| GET | `/api/v1/trades/groups` | 按天/按周分组（`view=day\|week`）：每组含 `key/startDay/endDay/stats/series/days`；`include_trades=false` 时只返回摘要 |
| GET | `/api/v1/trades/group-trades` | 按 `view+key` 在用户展开某一分组时加载该组交易明细 |
| GET | `/api/v1/trades/calendar` | 月历按日净盈亏与笔数：`[{ day, net, count }]` |
| GET | `/api/v1/trades/symbols` | 去重品种列表，供筛选器使用 |

公共筛选参数（summary / trades / groups / calendar 共用）：`account_ids`（逗号分隔的账户 id，缺省取当前用户的统计账户）、`currency`（币种，缺省按当前账户范围强制选择单一币种）、`from_day` / `to_day`（`YYYY-MM-DD`，北京时间，缺省为全部数据）、`side`（`all|buy|sell`）、`result`（`all|win|loss|flat`）、`symbol`。列表额外支持 `sort`（`closeTime/openTime/symbol/side/volume/net/points/rr/swap/commission/duration/accountName`）、`order`（`asc|desc`）、`page`、`page_size`（≤100）。

账户范围：缺省只统计 `is_statistics=true` 的账户；传入 `account_ids` 时按这些账户统计（非本人账户返回 404），不改全局设置，与前端“页面级筛选”一致。

交易派生：一笔交易 = 一个 MT5 **持仓**（`position_id`）。同一持仓的多笔 `entry=1`（DEAL_ENTRY_OUT）分次平仓合并为一条记录：`volume` 取平仓量之和、`closePrice` 取成交量加权均价、`closeTime` 取最后一笔平仓时间、`profit/swap/commission` 取平仓成交之和；`openTime` / `openPrice` 取同 `position_id` 的 `entry=0` 开仓成交的最早时间与加权均价（多次加仓同样按加权处理）。方向取**开仓成交**的方向（MT5 的平仓成交方向与持仓方向相反，用平仓方向会把方向与盈亏点数符号整体取反）；`point` / `contract_size` 取 `symbols` 表用于盈亏点数、R 倍数与净收益率。未平仓不计入；`needs_review` 的细化口径留待后续按 §9 补齐。

后端模块位于 `backend/app/trade_center/`，路由已注册到 `app.main`；接口随 FastAPI 自动生成文档（`/docs`）。列表/汇总/分组/月历均按账户所有权隔离，金额按账户原币计算；混合币种通过币种筛选收敛为单一币种。

### 11.1 用户偏好（列选择持久化）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/preferences/trade-center.columns` | 读取当前用户保存的列选择；未保存时返回 `payload: null`，前端回落到各视图默认值 |
| PUT | `/api/v1/preferences/trade-center.columns` | 保存 `{ day: [...], week: [...], all: [...] }`，按 `(user_id, namespace)` 覆盖写 |

通用偏好表 `user_preferences(user_id, namespace, payload)` 按命名空间隔离，后续模块（分组展开状态、默认视图、Dashboard 布局等）复用同一套接口即可。命名空间限 `^[a-z0-9][a-z0-9._-]{0,63}$`，payload 必须是 JSON 对象且不超过 32 KB；键值非法返回 400，超限返回 413。

### 11.2 URL 深链

页面把视图与筛选同步到查询参数，刷新或分享链接可还原同一屏：`view`（`day|week|all`，默认 view 不写）、`from`/`to`（`YYYY-MM-DD`，仅在与“全部已同步数据”跨度不同时写入）、`side`、`result`、`symbol`、`accounts`（逗号分隔的账户 id，仅在偏离统计账户默认范围时写入）、`page`（仅大于 1 时写入）。读取发生在挂载时（同时响应 `popstate`），写入使用 `history.replaceState`，不会产生多余的历史记录或触发路由跳转。

### 14.16 “图表边框”根因与修复（2026-09-20）

现象：当日明细弹框里的图表看起来有一圈浅紫色细边框。

排查过程与结论（逐项验证，不是猜测）：

1. 扫描弹框内所有元素的 border / outline / box-shadow，只有表格外框与底部操作栏分隔线有边框，图表 SVG 自身 `stroke: none`。
2. 扫描图表 SVG 内部所有带描边的图形，只有 7 条网格虚线、1 条零轴参考线和折线本身，没有矩形描边。
3. 放大用户截图取样，边框颜色为 `rgb(191,179,235)`，正好等于全局 `--ring` 色 `#8065d6` 叠加 50% 透明度后的结果。
4. 查询焦点元素，发现 `document.activeElement` 就是图表 SVG，其 `outline-width` 为 3px、`outline-color` 为 ring/50；该 SVG 的属性为 `role="application" tabindex="0"`（recharts 为无障碍添加），因此 Radix 弹框打开时自动聚焦到它，全局 `* { outline-ring/50 }` 便画出一圈浅紫描边。

修复：三个图表容器（当日趋势、每日盈亏柱、累计盈亏）统一加上 `[&_*:focus]:outline-none [&_*:focus-visible]:outline-none`，聚焦时不再绘制描边，同时保留 recharts 自身的无障碍属性。强制 `:focus-visible` 后截图验证，图表不再出现任何边框。

### 14.23 盈亏区间改为累计曲线口径（2026-09-20）

- 验收样例：2026-09-14~09-20 周为最大净亏损 $0.00 / 最大净盈利 $202.38（该周累计曲线未转负）；2026-09-07~09-13 周为最大净亏损 -$521.23 / 最大净盈利 $21.95。

### 14.30 与 TradeZella 对账后的两处口径修正（2026-09-21）

以 UpWay 账户全量数据与 TradeZella 同一账户对账，逐项定位差异并修正：

- **部分平仓合并（已修正）**：原实现“一笔平仓成交 = 一笔交易”，导致分次平仓的持仓被拆成多笔（实测 2392 笔 vs TradeZella 2388 笔，胜率 64.21% vs 64.18%、平均盈亏比 0.53 vs 0.54）。改为**按 `position_id` 合并**后：2388 笔、1532 胜 / 855 负 / 1 平、净额 -11,791.94、盈利因子 0.96、平均盈利 $182.45、平均亏损 -$340.71、平均盈亏比 0.54，与 TradeZella 完全一致。
- **方向与盈亏点数符号（已修正）**：MT5 的平仓成交方向与持仓方向相反（全部 2392 笔中平仓方向均与开仓方向相反），原实现取平仓成交方向，导致“方向”列显示的是平仓方向、且“盈亏点数”符号与盈亏相反（实测 2392 笔中 0 笔符号一致）。改为取开仓成交方向后，盈亏点数符号与盈亏一致（2391/2391 笔非平交易一致）。
- **交易日时区（待决策）**：TradeZella 的“日胜率”按纽约时间切分自然日（实测 113 个交易日 = 44 胜 / 69 负，38.94%），本项目按北京时间（116 个交易日 = 53 胜 / 63 负，45.69%）。两者差异完全来自交易日边界时区，不是数据缺失；是否改为可配置（北京时间 / 纽约 / UTC / MT5 服务器时间）待确认，见《Dashboard（总览）模块设计》§9。
