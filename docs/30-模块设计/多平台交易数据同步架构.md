# 多平台交易数据同步架构

版本：0.1；状态：方案已确认，进入开发阶段。

## 1. 目标

账户模块未来不仅要同步 MT5，还要支持 MT4、cTrader、ATAS、国内期货 CTP，以及平台选择器中已经预留的 Interactive Brokers、TradeStation、NinjaTrader、TradingView、Tradovate 等平台。

本方案把同步层从“MT5 SOP 专用接口”升级为“平台连接器 + 统一交易视图”，让新增平台只实现平台适配，不重复开发账户、交易、指标、筛选和复盘逻辑。

## 2. 平台现状

前端平台选择器已经展示多平台，见 `frontend/src/lib/tradesync/platforms.ts`。但当前真正可同步的只有 MT5：

| 平台 | 前端入口 | 当前同步 | 建议连接方式 |
|---|---|---|---|
| MT5 | 已支持 | 已实现 SOP 推送 | 保留现有 EA 推送 |
| MT4 | 已展示 | 未实现 | MT4 Manager API / EA API |
| cTrader | 已展示 | 未实现 | cTrader Open API / FIX |
| ATAS | 未单独展示 | 未实现 | ATAS API / 官方插件 |
| CTP 国内期货 | 待加入 | 未实现 | 独立 CTP 适配器 |
| Interactive Brokers / TradeStation / NinjaTrader / TradingView / Tradovate 等 | 已展示 | 未实现 | 按平台 API、Webhook 或专用适配器 |

平台选择器目前只是展示层，不代表后端已有对应同步能力。后续应通过“连接器状态”区分可同步、仅文件导入、即将上线、暂不支持。

## 3. 核心原则

1. 账户身份不绑定 `mt5_login`，改用 `external_login + broker_code + platform`。
2. 平台原始数据允许差异，但最终都归一化到统一交易模型。
3. 每个平台通过连接器清单声明能力，而不是在账户表和交易表里写死平台分支。
4. 密钥、API Key、Token 等凭证统一加密保存，并按平台配置权限和访问日志。
5. 旧 MT5 SOP 接口继续维护，不被其他平台复用。
6. 币种继续作为账户权威属性，不因平台上报值自动改写。

## 4. 平台连接器清单

建议新增 `platform_connectors` 或配置级平台清单，字段至少包括：

- `code`：例如 `mt5`、`mt4`、`ctrader`、`atas`、`ctp`。
- `name`：平台名称。
- `transport`：`sop_push`、`rest_pull`、`websocket`、`file_import`、`adapter`。
- `account_identity`：数字账号、文本账号、投资者账号等。
- `default_currency`：建议默认币种；`currency_locked` 表示是否锁定。
- `capabilities`：成交、持仓、订单、快照、品种、心跳、历史回补。
- `credential_schema`：该平台需要哪些认证信息。
- `status`：`live`、`beta`、`import_only`、`planned`。

账户创建界面据此动态展示字段，不再固定为 MT5 的券商服务器和数字账号。

## 5. 账户与凭证模型

`accounts` 在保留旧 `mt5_login` 的基础上增加通用字段：

- `external_login TEXT`：平台账号标识。
- `broker_code TEXT`：券商、期货公司或前置环境标识。
- `connector_code TEXT`：实际使用的同步连接器。
- `connection_config_json TEXT`：平台连接参数，不存明文密钥。
- `credential_ref`：指向加密凭证的引用。

MT5 现有账户回填 `external_login = mt5_login`、`connector_code = mt5`。平台账号唯一性最终按 `platform + broker_code + external_login` 处理。

## 6. 原始数据与统一交易视图

`deals` 继续作为 MT5 原始成交表。其他平台不得强行写入 `deals`，优先使用独立原始表或通用原始事件表：

- `raw_trade_events`：平台、连接器、事件类型、外部 ID、原始 JSON、接收时间。
- `raw_orders`：平台订单数据。
- `raw_trades`：平台成交数据。
- `raw_positions`：平台持仓数据。

各平台连接器把原始事件转换到统一交易模型：

- 账户、平台、品种、方向、开平标志。
- 开仓时间、平仓时间、价格、数量。
- 手续费、库存费、平仓盈亏等金额组件。
- 原始订单与成交引用。

统一结果进入 `trade_lifecycles` 或后续的统一交易表。交易中心和总览只依赖统一模型，不依赖具体平台。

## 7. 同步接口演进

短期保留现有 `/api/v1/sync/*` 作为 MT5 兼容入口。新增平台按连接器接入：

- MT4：优先复用 MT5 同步协议的独立变体，或通过 Manager API 拉取。
- cTrader：实现 cTrader Open API 或 FIX 拉取适配器。
- ATAS：通过官方 API 或插件接入。
- CTP：新增国内期货专用适配器，处理订单、成交、持仓和结算数据。
- 其他平台：统一使用平台 API、Webhook 或专用适配器。

不要求所有平台一开始都做到实时同步。统一接口契约见《连接器统一接口方案》；一期先落地连接器会话、游标和类型化事件流，再按平台接入。

## 8. 与币种方案的关系

多平台会放大多币种问题。账户币种仍是账户级、不可修改的权威字段：

- MT4、MT5、cTrader 等默认建议 USD，但允许用户选择其他币种。
- CTP 默认并锁定 CNY。
- ATAS 和其他平台根据账户设置选择币种。
- 混合币种账户同时统计时，强制选择单一币种，不做汇率换算。

品种筛选也要平台感知。未来如果同一品种代码在不同平台含义不同，应在统一交易模型中保留平台和交易所信息。

## 9. 开发阶段

1. 确认首批目标平台优先级：MT4、cTrader、ATAS、CTP。
2. 账户模型升级为通用平台标识和凭证引用。
3. 建立统一交易模型和原始事件模型。
4. MT5 作为首个连接器接入统一模型。
5. 分别实现 MT4、cTrader、ATAS、CTP 等 API 或专用适配器。
6. 按平台补齐实时数据、历史回补、快照、持仓和心跳。
7. 每接入一个平台，补齐品种、快照、持仓、心跳和验收。

## 10. 验收重点

- 同一账户模型可承载 MT4、MT5、cTrader、ATAS、CTP 等不同账号格式。
- 新增平台不修改交易中心、总览、账户页的核心统计逻辑。
- 平台原始数据保留可追溯来源和原始 JSON。
- 凭证不以明文写入业务表或日志。
- MT5 旧账户迁移后继续正常同步。
- 混合平台和混合币种场景不会产生错误汇总。

## 11. 待确认
