# 交易策略与 Playbook

版本：1.4；状态：前端 Mock 已完成，模块暂缓；恢复条件：知识记录模块 完成前端 Mock 验收后由用户指定恢复。

本文结合 TradeZella 策略页和本地帮助文档完成需求确认。研究期间创建的 `Codex Research Strategy 2026-09-23` 仅用于观察交互，不作为正式需求数据。

## 1. 模块定位

交易策略模块用于管理用户的机会模型、执行规则和版本：

```text
Strategy / Setup
  -> Playbook 草稿
  -> 规则组与规则
  -> 发布版本
  -> 关联一笔或多笔交易
  -> 逐条评价规则
  -> 进入策略统计和交易复盘
```

订单明细后续直接复用策略评价组件和规则统计，不复制第二套实现。

## 5. 数据与版本规则

Strategy 包含名称、说明、图标、颜色、适用品种、方向范围及启停状态；同一用户下名称唯一。

每个 Strategy 最多有一个可修改草稿。发布后版本不可修改，再次编辑会从最新版本复制出下一版草稿。归档 Strategy 保留历史版本，但不能发布新版本。

Playbook 包含市场环境、关键位置、触发条件、失效条件、风险约束、持仓管理、退出原则和禁止事项。规则支持分组、检查时点、关键规则、权重和 N/A 条件。

规则结果条件：

| 条件 | 含义 |
|---|---|
| Always | 每次评价都显示 |
| Winner | 盈利交易才显示 |
| Loser | 亏损交易才显示 |
| Break even | 盈亏平衡交易才显示 |

评价支持 PASS、FAIL、UNKNOWN、N/A 和证据。系统计算评价完整度、证据覆盖率、执行分、合规结论及关键违规；覆盖率未达到 100% 时不产生正式执行分。评价每次保存都会保留历史快照。

一个交易可以关联多个 Strategy/Playbook。每个 Strategy/Playbook 分别保存关联版本、规则评价和统计。取消某一关联只影响该 Strategy，不删除交易对其他 Strategy 的关联和评价。

## 6. 统计口径

### 6.1 列表统计

| 指标 | 含义 |
|---|---|
| Shared strategies | 已分享副本数；分享暂缓时固定为 `-` |
| Average loser | 关联交易中的平均亏损 |
| Average winner | 关联交易中的平均盈利 |
| Total net P&L | 关联交易净收益合计 |
| Profit factor | 总盈利 / 总亏损 |
| Trades | 已关联交易数 |
| Expectancy | 每笔交易期望值 |
| Win rate | 盈利交易 / 已关联交易 |

### 6.2 详情统计

| 指标 | 含义 |
|---|---|
| Win rate | 盈利交易占比 |
| Trades | 已关联交易数 |
| Profit factor | 总盈利 / 总亏损 |
| Daily win rate | 盈利交易日占比 |
| Avg trade duration | 已关联交易平均持仓时长 |
| Win/Loss | 盈利和亏损交易数 |

### 6.3 规则统计

| 指标 | 含义 |
|---|---|
| Follow rate | 该规则 PASS 的比例 |
| Net profit/loss | 遵循该规则交易的净盈亏 |
| Profit factor | 遵循该规则交易的盈利因子 |
| Win rate | 遵循该规则交易的胜率 |

统计必须显示样本数、未评价数和缺失原因。

## 7. 复制策略

复制策略进入一期。

复制行为：

- 复制 Strategy 基本信息和当前草稿。
- 生成新的 Strategy 名称，例如 `Original copy`。
- 复制规则组和规则。
- 不复制已发布版本历史。
- 不复制交易关联。
- 不复制规则评价和历史统计。
- 新策略从草稿状态开始。

## 10. 验收标准

- 同一用户下 Strategy 名称唯一。
- 发布版本不可修改，再次编辑生成新草稿。
- 复制策略不复制历史评价和交易关联。
- 规则组和规则支持排序、编辑和删除。
- 规则结果条件支持 Always、Winner、Loser、Break even。
- 一笔交易可以同时关联多个 Strategy/Playbook，每个策略独立评价和统计。
- 已发布版本可以关联交易并完成规则评价。
- Playbook 更新不重写历史评价。
- 覆盖率不足时不产生正式执行分。
- 策略与规则统计显示样本数和缺失原因。
- Notes 使用共享基础编辑器，不重复实现编辑器内核。
- 订单明细可以复用策略评价组件和 Notes 组件。
