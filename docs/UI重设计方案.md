# TradeEZ Web 整体 UI 重构方案（待确认）

> 早期方向稿。深浅模式等已确认规则见一期需求评审；海军蓝色板、旧导航和手机底部导航不作为实施基线。最新全局样式规则见 [全局样式规则.md](全局样式规则.md)。

## 1. 设计目标

建立一套固定、克制、专业的交易分析视觉体系。重点是让用户快速判断绩效、发现问题并完成复盘，而不是展示主题定制能力。

设计关键词：高级、冷静、清晰、可信、数据优先、低干扰。

以 TradeZella 的产品体验为第一参考，包括产品结构、页面密度、数据层级、操作路径和复盘工作流；不复制其商标、素材或像素级界面。TradeEZ 只保留自身品牌标识和中文交易复盘定位。

## 2. 现有方案调整

### 删除

- 多套主题预设（default、brutalist、soft-pop、tangerine）。
- 用户自定义主色、字体、内容宽度、Navbar 样式、Sidebar 变体等入口。
- 与交易复盘无关的模板演示页、组件示例和冗余导航。
- 装饰性过强的渐变、彩色卡片和不统一阴影。

### 保留

- 明暗模式仅在确有使用场景时保留；默认采用深色分析工作台。
- 现有基础组件库、表格、图表和响应式能力，统一换肤与重构层级。
- 手机端采用同一设计语言，不再作为另一套主题。

## 3. 品牌视觉方向

整体视觉不再从 `website-design/logo` 中的封面图推导。Logo 文件夹仅提供产品 Logo/头像资产，封面图不作为后台系统的配色和界面依据。

视觉优先参考 TradeZella 的核心特征：固定导航、浅层级卡片、紧凑但不拥挤的数据布局、弱装饰、强筛选、统一图表语义、交易工作流优先。TradeEZ 的品牌蓝仅承担品牌识别和主要操作，不主导整个页面背景。

### 固定色板

| 用途 | 建议颜色 |
|---|---|
| App 背景 | `#07111F` |
| Sidebar / 深层容器 | `#0A1628` |
| Card | `#0E1C2F` |
| Elevated Card | `#12243B` |
| 主边框 | `#1E334D` |
| 主文字 | `#F4F8FC` |
| 次文字 | `#93A6BC` |
| 品牌主蓝 | `#1688FF` |
| 品牌高光 | `#35C2FF` |
| 盈利 | `#22C783` |
| 亏损 | `#F05D6C` |
| 警告 | `#F2B84B` |
| 信息/持平 | `#7C91A8` |

规则：品牌蓝用于操作和选择；绿红只表达盈亏或状态；同一张图最多使用一个主色加盈亏色，不使用彩虹色谱。

### 字体和形态

- 中文采用系统无衬线字体栈，数字采用等宽特性或 tabular numbers。
- 4/8px 间距体系；卡片圆角 12px；输入和按钮圆角 8px。
- 阴影极轻，以边框和明度区分层级。
- 数据数字优先，标签次之；货币、百分比和 R 倍数格式统一。

## 4. 应用框架

### 左侧固定导航

- 品牌区：TradeEZ Logo + 产品名。
- 核心区：总览、每日复盘、交易记录、深度分析、策略表现。
- 纪律区：执行规则、错误标签、复盘笔记。
- 系统区：账户同步、数据导入、设置。
- 底部：当前账户、同步状态、用户菜单。

默认宽度约 240px，可折叠为图标栏；不允许用户切换成顶部导航或其他框架。

### 顶部筛选条

全局日期、交易账户、品种、方向、策略、标签；筛选条件对当前分析页面持续生效。右侧放置同步状态和核心操作。

### 内容区

最大有效宽度约 1600px，桌面端保持 24px 页面边距；标题区固定包含页面名称、说明、日期上下文和主操作。

## 5. 信息架构

1. 总览 Dashboard：核心 KPI、累计净值、盈亏日历、近期交易、纪律摘要。
2. 每日复盘 Day Review：按日期切换，日内绩效、交易列表、执行评价、笔记和结论。
3. 交易记录 Trades：强筛选数据表、列配置、单笔详情抽屉。
4. 交易详情 Trade Detail：成交拆分、K 线标记、风险收益、策略/标签、截图和复盘笔记。
5. 深度分析 Reports：按时段、品种、方向、策略、持仓时长、星期、连续盈亏分析。
6. 策略与纪律：策略卡片、规则遵守率、错误模式、改进趋势。
7. 账户同步：MT5 账户、连接状态、最后同步、异常和 Key 管理。

## 6. 核心页面视觉结构

### Dashboard

- 第一行：净盈亏、胜率、Profit Factor、平均盈亏比、最大回撤。
- 第二行左侧：累计 P&L 主图；右侧：交易健康度/纪律得分。
- 第三行：月度日历热力图 + 本月统计。
- 底部：近期交易和待复盘提醒。

KPI 卡不使用不同背景色，通过数值颜色、趋势箭头和微型走势表达状态。

### 每日复盘

- 顶部：日期切换与当日核心结果。
- 左侧主区：日内累计 P&L、交易时间轴、交易列表。
- 右侧复盘栏：计划、执行、情绪、错误、总结。
- 使用明确的“未复盘 / 复盘中 / 已完成”状态。

### 交易详情

- 主画布以图表为核心。
- 左侧可折叠当日交易列表。
- 右侧使用 Stats、策略、执行、附件/笔记标签页。
- 买卖点、SL/TP、盈亏区间使用固定语义色，避免品牌蓝与盈亏色混淆。

## 7. 组件规范

- Button：Primary 蓝、Secondary 深层容器、Danger 仅删除动作。
- Card：统一标题、辅助说明、操作区、内容区和空状态。
- Table：粘性表头、数值右对齐、盈亏列固定语义色、行悬停克制。
- Chart：深背景、低对比网格、统一 Tooltip、禁止随机图表色。
- Filter：紧凑型控件，可一键清除，当前筛选数量可见。
- Empty State：说明“为什么为空”和下一步操作，不使用大面积插画。
- Loading：骨架屏保持页面布局稳定。
- Error：就地说明问题和恢复动作，不只弹 Toast。

## 8. 响应式策略

- ≥1280px：完整侧栏与多列分析布局。
- 768–1279px：折叠侧栏，双列或单列。
- <768px：底部核心导航 + 抽屉筛选；数据表切换为摘要卡片/横向滚动。
- 移动端优先查看结果和记录，复杂报告允许引导到桌面端。

## 9. 建议实施阶段

### UI-0：现状审计

列出全部路由、组件、主题依赖、演示页面和可删除代码。只审计，不改视觉。

### UI-1：设计基线

冻结色板、排版、间距、圆角、阴影、图表和状态语义；制作基础组件样板页。验收通过后再进入框架改造。

### UI-2：应用框架

重构固定 Sidebar、顶部筛选条、页面容器和移动端框架；移除主题/布局自定义入口。

### UI-3：核心页面

按 Dashboard → 每日复盘 → 交易记录 → 交易详情顺序重构，每完成一个页面单独验收。

### UI-4：分析与系统页面

重构 Reports、策略纪律、账户同步和设置。

### UI-5：统一性验收

检查桌面/移动端、空状态、加载、错误、权限、数据格式、图表色彩和可访问性。

## 10. 已确认的设计决策

以下决策已由产品方确认，后续页面设计和实现必须遵守：

1. 深色分析工作台为默认模式，保留一个固定浅色备用模式。
2. 采用 TradeZella 风格的中性深色、低装饰、数据优先方案。
3. 品牌蓝只用于操作、链接和选中状态，不表达盈利。
4. 取消所有主题、布局、字体和页面框架自定义能力。
