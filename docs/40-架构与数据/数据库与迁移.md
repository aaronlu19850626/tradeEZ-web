# 数据库与迁移

## 当前实现

- 数据库为 PostgreSQL，连接由 `TRADESYNC_DATABASE_URL` 提供。
- schema 版本以 `backend/app/migrations.py` 的 `SCHEMA_VERSION`、`_MIGRATION_STEPS` 和 `backend/migrations/` 为事实源。
- 新库和旧库升级都必须经过版本迁移；有业务表但缺少受支持版本记录时拒绝自动覆盖。
- 新代码使用 PostgreSQL 语义，不扩大历史 SQLite 兼容层。

## 迁移规则

同一时间只能有一个分支修改迁移链。新 revision 必须从最新 `main` 领取；已合并/部署迁移不得改写，修复使用后续迁移。迁移 PR 必须说明新库、升级路径、数据兼容、锁、不可逆操作、回滚和测试数据库。

## 数据分层

| 层 | 规则 |
|---|---|
| 原始事实 | 成交、快照、同步事件不可被人工复盘覆盖 |
| 派生投影 | 可重建的完整交易、统计和缓存 |
| 人工资料 | 复盘、标签、计划、附件独立保存并用版本/并发保护 |
| 系统基础数据 | 通过幂等 Seed 管理 |

生产测试库同步、备份和审批见[数据库变更与环境同步](../10-开发与协作/数据库变更与环境同步.md)。
