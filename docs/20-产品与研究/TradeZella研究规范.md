# TradeZella 研究规范

## 研究目标

逐功能点观察结构、交互、状态、数据关系和响应式表现，为 TradeEZ 的需求评审提供事实。研究结论不自动成为产品需求或实现授权。

## 每个功能点必须记录

- 参考产品 URL、账号状态和完整操作路径。
- DOM 结构、布局、关键间距、字体、图标、弹层位置和键盘行为。
- 默认、hover、active、focus、loading、empty、error、disabled、success 和权限状态。
- 桌面、平板、移动和主题差异。
- 输入、输出、分页、筛选、排序、保存和异常数据关系。
- 截图、trace 或其他可复核证据。

## 结论分类

| 分类 | 含义 |
|---|---|
| 参考产品事实 | 浏览器实际观察结果 |
| 用户明确要求 | Issue 或确认记录中的产品决策 |
| TradeEZ 自主设计 | 参考产品没有实现、不可观察或与全局规范冲突的部分 |

自主设计必须进入当前功能点矩阵和用户确认记录，不得用“参考产品就是这样”代替决策。

## 复刻边界

可以复刻信息结构、核心交互、状态和业务流程；不得复制品牌 Logo、品牌色、文案或受限资源。页面必须使用 TradeEZ Token、标准控件和业务组件。先完成研究和矩阵，再进入 Mock。
