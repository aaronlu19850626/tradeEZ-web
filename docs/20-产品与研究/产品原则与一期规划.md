# 产品原则与一期规划

## 已确认产品原则

- 交易原始事实可追溯、不可被人工复盘覆盖；派生交易和统计可以重建。
- 默认按用户、账户、平台、币种和权限隔离数据。
- TradeZella 只提供研究事实；TradeEZ 负责品牌视觉、文案、组件和最终产品规则。
- 先完成页面和数据逻辑的 Mock，再由产品负责人确认，随后才实现真实 API 和迁移。
- AI 只做授权范围内的整理、摘要、解释和问答，不执行交易、不修改账户、不覆盖用户原文。
- 统计金额、日期、市场涨跌颜色和状态语义必须由共享口径统一提供。

## 一期尚未确认

一期模块、优先级、开发波次、验收深度和明确不做项尚未锁定。旧 PRD、旧一期规划和历史 Issue 不构成当前授权。

## 一期确认入口

先创建“TradeZella 核心模块全面盘点”研究 Epic，按[TradeZella 研究规范](TradeZella研究规范.md)形成能力地图、用户路径、数据关系和差距矩阵，再由产品负责人在 GitHub Issue 中确认：

1. P0 核心闭环；
2. P1 可延后能力；
3. P2 探索能力；
4. 明确不做项和依赖顺序；
5. 每个模块的验收标准。

确认后的结果更新本文件和[模块目录](模块目录.md)，动态排期保存在 GitHub Project。
