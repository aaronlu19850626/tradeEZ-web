# 盘前日计划

迁移 `0012_day_plans` 增加按用户、账户和计划日期唯一的日计划，以及只增不改的计划版本。当前使用计划中明确展示的 IANA 时区解释日期。

日计划支持准备交易、仅观察和休息。准备交易可选择已启用 Setup 的已发布 Playbook，填写风险边界、停止条件、等待条件、改进重点，并维护多个候选场景；场景包含品种、方向倾向、关联版本、关注区域、入场确认、逻辑失效及退出原则。场景仅记录条件判断，不是下单指令。

准备交易时至少需要一个场景或等待条件；确认前还必须选择允许模型并填写停止条件。仅观察或休息必须填写原因。确认后再次保存会回到修订草稿并保留版本；首次确认时间不会被覆盖。当天已有开仓交易后才确认的计划标记为“晚于首笔交易”。

页面位于 `/dashboard/today`，接口为 `GET/PUT /api/v1/my/day-plan` 和 `POST /api/v1/my/day-plans/{id}/confirm`。下一步将在计划场景下创建交易意图，并支持与同步后的完整交易人工关联。

## 交易意图

迁移 `0013_trade_intentions` 增加交易意图和只增不改的状态事件。意图可从计划场景带入品种、方向、Playbook 和入场确认，也可独立创建；实际创建时间由系统记录。

状态支持观察中、准备执行、已执行待关联、已关联、主动放弃、条件失效和到期未执行。结束状态必须填写原因。系统按同账户、同品种和同方向展示未被占用的完整交易候选，由用户人工确认；一个完整交易只能关联一个意图。关联时间独立保存，不会覆盖意图创建时间。

## 盘后日总结

迁移 `0014_daily_reviews` 增加每日总结及不可变版本。当前汇总按账户、计划日期和计划时区计算原始成交数、完整交易数、净收益、待核对交易、已复盘／待复盘、模型关联、已确认违规及意图关联情况。

提交总结前需要确认已查看汇总，并回答计划差异、执行情况、保留行为、主要问题和下一日行动；也可以明确继续现有行动。总结与单笔复盘独立，存在待复盘交易时仍可提交。

提交时保存当时的汇总快照和来源摘要。迟到交易、费用、复盘或规则评价变化后，状态显示“数据变化待核对”，原文字、首次完成时间及旧版本继续保留。页面位于 `/dashboard/today`，接口为 `GET/PUT /api/v1/my/daily-review`。
