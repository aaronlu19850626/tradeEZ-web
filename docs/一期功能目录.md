# TradeEZ Web 一期功能清单（需求整理稿）

> 初期候选清单，仅用于追溯讨论；当前框架请以 [一期需求评审](一期需求评审.md) 为统一入口。候选能力不等同于已确认范围。

状态：待产品方逐项确认；本文件仅整理需求，不代表已开始开发。

## 1. 一期产品主线

以“一个交易日”为核心业务单位，串联：

```text
交易计划 → 交易执行 → 单笔订单复盘 → 日整体复盘 → 报告与改进
```

交易账户、Dashboard、交易记录、笔记、报告、策略、资源和 AI 都围绕这条主线提供上下文。

## 2. 一级功能模块

### 2.1 交易账户管理

目标：管理 MT5 账户与同步状态，为所有分析提供可靠数据来源。

候选能力：

- 账户列表、账户状态和账户别名。
- MT5 同步 Key、连接状态、最后同步时间。
- 同步异常、缺失数据和重复数据提示。
- 账户启用/停用和默认账户。
- 多账户切换和跨账户汇总口径。
- 账户基础信息、资金、净值和风险参数。

待确认：一期是否支持多个 MT5 账户同时汇总；账户删除是软删除还是停用。

### 2.2 Dashboard 总览

目标：登录后快速回答“我最近交易得怎么样、问题在哪里、今天要做什么”。

候选区块：

- 时间范围、账户、品种、策略全局筛选。
- 净 P&L、胜率、Profit Factor、平均盈亏比、最大回撤。
- 累计 P&L 和每日 P&L 趋势。
- 盈亏日历和交易日摘要。
- 今日计划状态、今日执行状态、今日复盘状态。
- 最近交易和待复盘交易。
- 纪律/规则执行摘要。
- AI 今日摘要入口。

### 2.3 交易记录

目标：提供可检索、可筛选、可追溯的交易数据工作台。

候选能力：

- 交易表格、分页、排序和列显示控制。
- 按日期、账户、品种、方向、结果、策略、标签筛选。
- 按订单号、Position ID 和品种搜索。
- 交易合并/拆分的展示口径（一期是否允许编辑待确认）。
- 点击进入单笔订单复盘。
- 批量标记、批量打标签和批量导出。

### 2.4 交易笔记

目标：记录交易前、交易中和交易后的主观信息，并与交易数据关联。

内容层级：

- 日计划笔记。
- 单笔订单复盘笔记。
- 日整体复盘笔记。
- 自由笔记和主题笔记。

候选能力：

- 富文本 Markdown 编辑器。
- 默认模板加载、保存为个人模板和模板版本。
- 标签、情绪、错误类型和交易评分。
- 图片/图表/附件。
- 草稿、自动保存、历史版本和完成状态。
- 笔记与账户、交易日、订单、策略之间的关联。
- AI 辅助整理、摘要、改写和检查遗漏。

### 2.5 交易报告

目标：将交易记录转化为可解释的表现和改进结论。

候选报告：

- Dashboard 周期报告。
- 日报告、周报告、月报告。
- 按品种、方向、时段、星期、策略和持仓时长分析。
- 胜率、期望值、Profit Factor、回撤、连胜/连亏。
- 计划执行率和规则遵守率。
- 错误类型、情绪类型和结果的关联。
- 报告保存、分享/导出（导出范围待确认）。
- AI 报告摘要和改进建议。

### 2.6 交易策略

目标：把策略、规则和实际交易结果关联起来，判断策略是否有稳定优势。

候选能力：

- 策略列表、策略详情和启用状态。
- 策略说明、适用市场、入场条件、出场条件和风险规则。
- 策略默认模板。
- 交易绑定策略、策略表现统计。
- 策略规则检查和偏离记录。
- 策略版本、变更历史和复盘结论。
- 策略与标签、笔记和附件关联。

## 3. 每日交易闭环

### 3.1 交易计划

计划属于“交易日”而不是某一张孤立的笔记。

候选字段：

- 日期、账户和交易时段。
- 市场背景、重要事件和数据发布时间。
- 关注品种和关键价位。
- 今日策略/Playbook。
- 计划入场条件、失效条件和风险上限。
- 情绪状态和执行目标。
- 计划模板。

### 3.2 单笔订单复盘

候选结构：

- 订单和成交概况。
- 入场/出场、SL/TP、风险收益和实际结果。
- 图表或截图。
- 执行过程时间线。
- 绑定策略和规则检查。
- 情绪、错误、评分和复盘结论。
- 单笔 AI 辅助总结（后续可选）。

### 3.3 日整体复盘

候选结构：

- 当日 P&L、胜率、交易数和规则执行率。
- 计划与实际执行对照。
- 最好交易、最差交易和典型错误。
- 情绪变化和纪律表现。
- 今日学到什么、明日要改什么。
- AI 日复盘摘要和建议。
- 完成日复盘并锁定状态。

## 4. AI 能力边界

AI 作为复盘助手，不替用户下单、不自动修改交易、不承诺收益。

### 一期建议纳入

- 根据当日成交、计划和笔记生成日整体摘要。
- 识别明显的执行偏离、重复错误、连续亏损和情绪模式。
- 将散乱笔记整理为结构化复盘结论。
- 根据用户选中的模板生成初稿。
- 对交易记录进行自然语言查询。
- 生成基础面/技术面信息摘要，并标注数据来源和时间。

### 必须明确的安全规则

- AI 输出标注“分析参考，不构成投资建议”。
- 基础面和技术面内容必须显示数据时间、来源和适用品种。
- 没有可靠数据时明确提示，不编造行情、事件或指标。
- AI 不能直接执行下单、改止损、改账户或删除数据。
- 用户可以查看、编辑、拒绝和撤销 AI 生成内容。

## 5. 资源中心

目标：为复盘提供上下文，不让用户在多个网站之间切换。

候选内容：

- 今日重要事件和经济数据发布时间。
- 事件影响等级、涉及品种和实际/预期/前值（数据源待确认）。
- 市场摘要和品种观察清单。
- 计算器、仓位/风险计算、盈亏计算等小工具。
- 复盘模板库和策略模板库。
- 使用说明和快捷操作。

一期建议先做：重要事件/数据卡片、模板库、小工具入口；实时行情和完整新闻系统延后。

## 6. 富文本 Markdown 编辑器重构

编辑器将作为跨模块基础能力，而不是某个页面的局部组件。

最低能力：

- Markdown 输入和富文本预览双模式。
- 标题、列表、引用、代码、表格、分割线。
- 图片、截图和附件。
- 自动保存、草稿恢复和字数/保存状态。
- 模板加载和变量填充。
- 插入交易、指标、策略和事件引用。
- AI 生成、改写、摘要、补全和结构化。
- 键盘快捷键、粘贴清理和移动端适配。

建议一期先冻结编辑器文档模型和模板变量协议，再开发各业务页面。

## 7. 一期范围建议

### 建议纳入

交易账户管理、Dashboard、交易记录、交易笔记、交易报告、交易策略、交易计划、单笔订单复盘、日整体复盘、基础模板、基础资源中心、编辑器基础能力、AI 日复盘摘要。

### 建议延后

完整新闻系统、自动技术分析引擎、Trade Replay、回测、AI 自动交易建议、导师协作、社区、Prop Firm 专用模块。

## 8. 需要产品方确认的问题

1. 一期是否支持多账户汇总，还是先单账户工作流。
2. 交易计划、单笔复盘、日复盘是否都必须完成后才算“日复盘完成”。
3. 日复盘完成后是否允许重新打开修改，是否需要版本记录。
4. 交易笔记模板是否允许用户创建、复制、编辑和删除。
5. 策略是否需要版本管理，还是一期只保留当前版本。
6. 报告是否需要导出 PDF/Excel，还是先只做网页查看。
7. 资源中心的事件和数据源由谁提供，是否已有 API 或数据订阅。
8. AI 一期只做基于本地交易数据的复盘，还是同时接入外部行情/事件数据。
9. AI 功能是否需要用户主动点击生成，还是在页面中自动生成草稿。
10. 编辑器是否统一使用 Markdown 存储，富文本只作为编辑界面。
