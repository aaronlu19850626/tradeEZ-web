# Dashboard（总览）模块设计 v0.2

状态：需求稿，待用户确认后进入前端 mock。参考实现：TradeZella `/tracking` 的 Main 模板（用户账号内实测 15 个面板）。

## 1. 模块目标与边界

- **定位**：全周期总览。默认时间范围 = 全部已同步数据（与交易记录模块默认一致），用户可改；不做"今日作战台"（那属于每日流程模块）。
- **统计维度与口径**：完全沿用交易记录模块——账户范围默认取统计账户、时区北京时间、统计周周一至周日、未平仓不计入、净盈亏 = 价格盈亏 + 库存费 + 佣金、币种固定 USD、指标缺失显示 N/A。筛选条件（日期范围、账户、方向、品种、结果）与交易记录模块共用同一套参数与 URL 深链。
- **v1 范围**：布局**固化**（Main 模板扣除"账户余额"后的 14 个面板）；**不做**自定义拖拽与模板管理。
- **v1 必须预留**（二期只加 UI，不改数据契约）：面板化容器、面板注册表、布局接口、用户布局存储、评分接口。
- **不包含**：账户余额/出入金分析（用户确认只分析净盈亏曲线）、财经事件、K 线回放、AI 助手、自定义模板 UI（二期）。
- **依赖下一个模块**：一致性热力图的"每日检查清单完成度"、单笔评分的"是否复盘/复盘质量"都来自即将开发的"订单复盘 + 日/周复盘"模块；本期先按不可用处理并预留字段，模块上线后自动生效。

## 4. 评分体系

原则：**可解释、可复算、有样本门槛**。每项展示原始值、档位区间与权重，不出现黑箱数字；样本不足（笔数 < 30 或有效 R 笔数 < 20）时综合评分显示"样本不足"，只展示原始指标。

### 4.1 综合评分（账户级，0–100）

六个维度，权重合计 100%，每维用**分段线性**曲线把原始指标映射到 0–100（断点可在服务端配置，便于后续按真实数据校准）：

| 维度 | 权重 | 原始指标 | 分段断点（原始值 → 分数） |
|---|---|---|---|
| 期望值 Expectancy | 25% | ΣR ÷ 笔数（逐笔 R 口径同交易记录） | -0.5R→0、0R→50、+0.3R→80、+0.6R→100 |
| 风险控制 Risk control | 20% | 0.6×最大回撤(R) + 0.4×最大单笔亏损(R) | 回撤：5R→100、10R→80、20R→50、40R→0；单笔：≤2R→100，每超 1R 扣 25 分 |
| 盈亏比 Payoff | 15% | 平均盈利R ÷ \|平均亏损R\| | 0.8→0、1.0→50、1.5→85、2.0→100 |
| 恢复因子 Recovery factor | 15% | 净利润 ÷ 最大回撤金额 | 0→0、1→50、2→80、≥3→100 |
| 稳定性 Consistency | 15% | 盈利交易日占比，再乘日盈亏波动惩罚 | 30%→0、45%→50、55%→75、≥65%→100；波动惩罚系数 = clamp(1 − 日盈亏标准差 ÷ 日均绝对盈亏 ÷ 3, 0.6, 1) |
| 胜率 Win rate | 10% | 盈利笔数 ÷ 总笔数 | 30%→0、50%→60、65%→85、80%→100 |

总分 = Σ(维度分 × 权重)，取整显示；同时给出"最弱两项 + 一句改进建议"（例如"风险控制 42 分：最大回撤 26R、单笔最大亏损 4.1R，建议先把单笔风险压到 1R 以内"）。

### 4.2 单笔交易评分（0–100）

五个分项，权重合计 100%；**"是否复盘"作为独立分项参与评分**，衔接下一个模块（订单复盘 + 日/周复盘）：

| 分项 | 权重 | 计算 | 说明 |
|---|---|---|---|
| 结果 Result | 30% | 该笔 R 映射：-1.5→0、-1→25、0→50、+1→75、+2→90、≥+3→100 | 避免"运气大赢"被过度奖励 |
| 风险合规 Risk | 20% | 无止损 → 0；有止损 → clamp(100 − 25×\|该笔风险金额 ÷ 账户平均风险金额 − 1\|, 0, 100) | 惩罚"这笔下注明显大于平时" |
| 出场方式 Exit | 15% | 收盘价贴近止盈（容差 0.2×风险距离）→100；贴近止损 →90；两者都不贴（手动平仓）→60；无 SL/TP →40 | 用价格距离判断，无需 tick 数据 |
| 费用效率 Cost | 15% | (佣金 + 库存费) ÷ \|毛利\| 映射：2%→100、10%→70、25%→40、≥50%→0 | 惩罚高频与长期过夜 |
| **复盘 Review** | **20%** | 是否复盘 40 分（该笔订单复盘已完成即得）+ 复盘质量 60 分（取该笔复盘的规则遵守率与执行评分加权；日/周复盘结论可回填修正） | 复盘模块上线后生效；未上线时该项按 0 计 |

- **未复盘状态**：未复盘的交易仍给出总分（最高 80 分），但界面显示"待复盘"角标，并提供"去复盘"入口；素材齐备后分数随复盘结果更新。
- 标签（可多个）：按计划止盈 / 按计划止损 / 手动平仓 / 未设止损 / 风险偏大 / 费用偏高 / 高R盈利 / 已复盘 / 待复盘。
- **预留**：接口按"分项数组 + 权重表"返回，权重与分项可增删；复盘模块上线后只需把"复盘"分项从占位改为真实取值，前端不改结构。

### 4.3 展示与可解释

- 综合评分：雷达（六维）+ 总分条；点击任一项 → 明细弹层（原始值、档位、加权贡献）；
- 单笔评分：出现在订单明细（二期）与交易记录表格可选列（列名"评分"，默认关闭），悬停显示四项分解与标签；
- 所有评分显示一位小数，并标注"由已平仓交易计算，未平仓不计入"。

## 6. 前端预留

- `PANEL_REGISTRY`：面板类型 → `{ title, description, defaultSize, Component, dataKey }`，v1 渲染固定顺序，二期面板库与拖拽直接读它。
- `<DashboardPanel>`：统一容器（标题/ⓘ/操作槽/加载/空态/错误），v1 与二期共用。
- `useDashboardLayout()`：v1 读 `GET /dashboard/layout`（失败回落本地常量），二期在同一 hook 内接编辑态与保存，页面组件不改。
- 面板组件只接收 `{ panel, filters }`，自己负责取数与状态——二期调整布局不需要改面板。

## 7. 状态、交互与边界

- 筛选/日期/账户变化 → 面板级重算（每面板独立请求，互不阻塞，先到的先渲染）；条件写入 URL，支持深链与刷新保持（复用交易记录已实现的机制）。
- 加载：面板级骨架；错误：面板内错误 + 重试，不清空整页；空态：无数据时给"配置 EA 同步或导入记录"的引导。
- 样本不足：综合评分显示"样本不足（当前 N 笔，需 ≥30 笔）"。
- 窄屏：<1280px 自动降为单列，顺序不变；指标卡 2×2 起排。
- 性能：15 个面板各自取数，服务端对同筛选条件的聚合结果做短 TTL 缓存（默认 30 秒），避免切筛选时重复全表扫描。

## 8. 已确认与待确认

### 8.1 已确认（2026-09-21 用户确认）

1. **不做账户余额分析**，本模块只分析净盈亏曲线（因此不依赖 `snapshots` 与出入金流水）。
2. **一致性热力图 = 0.6×当日盈亏强度 + 0.4×每日检查清单完成度**，盈亏强度权重大于清单完成度。
3. **回撤口径 = 已平仓累计盈亏曲线回撤**，不用账户权益回撤。
4. **月度日历独立设计**，不复用交易记录模块的月历组件。
5. **单笔评分必须包含"是否复盘"**，与即将开发的"订单复盘 + 日/周复盘"模块联动。
6. v1 布局固化、二期做自定义，但前后端接口按"面板化 + 布局接口"预留。
7. **单笔评分同时进入交易记录表格的可选列**（列名"评分"，默认关闭），显示分值 + "待复盘"角标，与交易记录模块的列显示机制共用。
