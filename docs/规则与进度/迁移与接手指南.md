# 迁移与接手指南

日期：2026-09-20。状态：前端已获用户确认，下一步开发交易账户后台接口。

## 新电脑打开方式

将 `tradeEZ-web` 目录作为 Codex 项目根目录（应包含本指南、AGENTS.md、frontend、backend 和 .git），不要只关联 frontend。可以复制整个目录，也可以从 GitHub 克隆 https://github.com/aaronlu19850626/tradeEZ-web.git 。本次发布位于 main 分支。

保留 .git 才能沿用版本历史及远程关联；执行 `git remote -v` 和 `git status` 检查。新电脑需重新登录 GitHub，并安装 Git、Node.js 22 LTS 和 Python 3.11 或更高兼容版本。不要搬用旧电脑 node_modules、.next、venv/.venv；重新安装依赖。

## 环境恢复

1. 安全复制旧电脑的 backend/.env 和 frontend/.env.local，或参照对应示例重新配置。这些文件不会上传 GitHub。数据库使用远程 PostgreSQL，真实连接信息由用户另行提供，不在文档保存密码。
2. 同一远程库必须保留原认证和同步密钥加密配置，尤其 TRADESYNC_SYNC_KEY_ENCRYPTION_SECRET，否则历史密钥可能无法解密。不要用示例值覆盖既有环境配置。
3. 后端：进入 backend，执行 `python -m venv .venv`，然后 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt`。启动前检查连接目标：现有启动流程可能自动运行数据库迁移。优先连接隔离开发库。启动命令 `.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000`。
4. 前端：进入 frontend，执行 `npm ci`，再 `npm run dev -- --port 3000`。API 地址使用 NEXT_PUBLIC_API_BASE_URL，默认本机 http://127.0.0.1:8000/api/v1；换电脑后不能沿用旧机器局域网地址。
5. 开发验证码使用 123456：仅开发环境设置 TRADESYNC_ENVIRONMENT=development 和 TRADESYNC_AUTH_TEST_MODE=true。生产环境禁用此模式。
6. 访问 /auth/v2/login、/dashboard/account-center；后端检查 /health 和 /docs。本地浏览器会话及 mock 操作状态不会随代码迁移。

## 已确认范围与下一步

交易账户页面位于 frontend/src/app/(main)/dashboard/account-center/page.tsx，目前为 React 内存 mock，刷新即恢复种子数据。界面通过不代表后台已经实现。

后台开发顺序：盘点旧数据库与 EA 协议 → 为独立新模块制定接口契约和兼容迁移 → 实现服务/权限/接口 → 切换前端真实数据 → 接口、异常路径、集成回归测试 → 用户验收 → 单独清理旧模块。

必须覆盖：

- 每用户最多 10 个账户，并发创建也须遵守；账户名称、MT5 账号、同步开始日期必填，券商服务器可选。
- 多个统计账户可独立加入或取消，允许全部取消；首个账户自动加入，后续默认不加入；删除不自动替补。统计范围用于后续面板/全局分析。
- 密钥可重复查看/复制，重置即使旧密钥失效，交易保留；密钥存储、鉴权及日志不得泄漏。
- 重置交易须填写新同步开始日期，并精确输入账户名称；保留密钥和统计选择。当前 mock 尚未把 resetStart 写回 syncStart，接入时补齐。
- 物理删除要求精确输入账户名称、校验归属、处理关联数据及密钥失效。
- 快照余额/净值、更新时间精确到秒；EA 最近 10 分钟有心跳为同步中，否则未检测到；无数据显示 N/A。
- CSV 仅在指定账户导入，处理重复、格式错误、时区、部分失败及导入结果；真实解析尚未实现。
- 交易报告暂保留入口，不实现报告计算；EA 帮助目前仍为提示占位，需补说明页面。
- 表格操作顺序：默认统计/取消统计、交易报告、查看密钥、重置密钥、导入交易、重置交易、删除账户；点账户名称改名。
