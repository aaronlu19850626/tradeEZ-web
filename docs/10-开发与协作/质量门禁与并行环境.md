# 质量门禁与并行环境

## 门禁命令

```bash
./scripts/quality/static.sh
./scripts/quality/e2e.sh
./scripts/quality/check.sh
python3 scripts/docs/check_docs.py
git diff --check
```

`static.sh` 覆盖后端 pytest、TypeScript、Biome、生产构建和 diff 检查。`e2e.sh` 使用受管前后端和独立数据库运行桌面、平板、移动 Playwright。`check.sh` 是完整本地门禁；`SKIP_E2E=1` 只代表浏览器门禁未运行，不能记录为完整通过。

## 按改动选择

| 改动 | 必需门禁 |
|---|---|
| 纯文档 | 文档检查、`git diff --check` |
| 后端逻辑/API | pytest、静态门禁 |
| 前端非行为代码 | TypeScript、Biome、构建 |
| 页面、交互、导航、认证、数据流 | 静态门禁和 E2E |
| 数据库迁移 | 新库和升级路径、后端测试、受影响 E2E |

## 并行隔离

每个任务独立使用：worktree、前端端口、后端端口、开发数据库、测试数据库、E2E 数据库、临时目录、上传目录和浏览器认证状态。数据库命名必须包含任务标识：

```text
tradeez_dev_<task>
tradeez_test_<task>
tradeez_e2e_<task>
```

不得让多个任务共享运行数据库或测试认证。迁移文件仍是 Git 共享资源，即使本地数据库已经隔离，也必须串行分配 revision。

## 证据

本地结果写入 PR，CI 结果由 GitHub Actions 保存。截图、trace 和报告作为 PR 附件或 Actions artifact；不提交固定结果报告。失败、跳过和环境阻塞必须如实记录。
