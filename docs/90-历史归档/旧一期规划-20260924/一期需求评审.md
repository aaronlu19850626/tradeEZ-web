# TradeEZ Web 一期需求终审稿

版本：v0.4；状态：历史评审输入，已被新的核心模块盘点流程取代。

> 本文保留旧讨论用于追溯，不是当前一期范围或排期。涉及 Notebook、笔记历史、笔记模板和编辑器的全部结论已经撤销；新需求必须从 TradeZella 核心模块盘点和用户重新评审开始。当前入口为 [一期方向与大模块开发计划](一期方向与大模块开发计划.md)。

本文是一期框架需求的统一评审入口，优先于此前功能清单、补充稿和第二轮问题清单。终审通过代表框架确认，不代表各模块详细需求或开发授权。文中“候选/建议/待详细设计”不视为用户已经批准的细节。

每个模块必须先建立独立详细设计文档，确认数据结构、功能清单、页面设计与验收标准，再开发；阶段验收通过后进入下一阶段。先固化全局样式，再逐模块推进。

## 一、目标与约束

围绕“账户同步 → 交易计划 → 交易执行 → 单笔复盘 → 日整体复盘 → 评分与报告 → 改进”建立交易复盘闭环。

- 默认深色分析工作台，保留固定浅色模式。
- 采用 TradeZella 风格的中性深色、低装饰、数据优先体验。
- 品牌蓝只用于操作、链接和选中状态，不代表盈利。
- 取消主题、布局、字体和页面框架自定义。
- 一期支持多交易账户汇总。
- 多账户汇总采用简单合并，不要求在汇总视图中分账户展示；单账户分析入口保留。
- 开仓和平仓时间统一转换为平台时区展示和划分业务日期；平台具体时区值及跨日持仓归属在详细设计时确认。

## 二、一期功能模块

### 1. 交易账户管理

多账户列表、账户别名、启用/停用、默认账户、账户汇总/切换、MT5 同步 Key、连接状态、最后同步时间、同步异常、缺失/重复数据、资金/净值/风险参数。

### 2. Dashboard 总览

全局日期/账户/品种/策略/标签筛选；净 P&L、胜率、Profit Factor、平均盈亏比、最大回撤；累计 P&L、每日趋势、盈亏日历、今日计划/执行/复盘状态、EZ 得分、百分制交易质量评估、最近交易、待复盘和 AI 今日摘要。

### 3. 交易记录

支持“日 / 周 / 全部”三种查看维度，三种视图可不同，具体页面在该模块阶段确认；支持日期、账户、品种、方向、结果、策略、标签筛选，订单号/Position ID 搜索，排序、分页、列控制、进入单笔复盘、批量标签。

### 4. 交易笔记

交易计划、单笔订单复盘、日整体复盘、策略笔记和自由笔记；Markdown 存储、富文本编辑；标签、情绪、错误、评分、图片、附件、自动保存、草稿恢复、关联账户/日期/订单/策略/事件、AI 整理和摘要。

### 5. 交易报告

日/周/月报告；按品种、方向、时段、星期、策略、持仓时长分析；胜率、期望值、Profit Factor、回撤、连胜/连亏、计划执行率、规则遵守率、错误和情绪关联；AI 摘要和建议。不做文件导出，支持手机浏览的外部只读分享。

### 6. 交易策略

策略列表、详情、市场/入场/出场/风险规则、系统默认模板、策略表现、规则偏离、复盘结论。

- 策略修改自动生成新版本；具体保存/发布粒度在详细设计时确定。
- 历史版本只读，可以逻辑删除；被历史交易引用的版本仍需可追溯。
- 历史交易永久绑定原策略版本，同时保存开仓时版本和复盘时版本，两者不能相互覆盖。
- 系统模板不可删除；修改作用于当前用户副本，不影响其他用户和系统原模板。
- 不提供“另存为个人模板”功能。用户副本属于系统模板的个性化配置。
- 系统模板升级不覆盖用户已使用的历史内容。

## 三、每日闭环

### 交易计划

日期、账户、时段、市场背景、重要事件、关注品种、关键价位、策略/Playbook、入场条件、失效条件、风险上限、情绪状态和执行目标。

### 单笔订单复盘

订单/成交、入场/出场、SL/TP、风险收益、执行时间线、图表、策略、规则、情绪、错误、评分和结论。

### 日整体复盘

当日 P&L、胜率、交易数、规则执行率、计划与执行对照、最好/最差交易、典型错误、情绪变化、今日总结和明日改进、AI 日摘要。

- 日复盘不做版本管理。
- 按平台时区，当天可以修改原稿；跨日后原稿只读，管理员也不能解锁。
- 跨日允许追加补充内容，但不允许修改原稿。原稿与补充内容分开展示；补充内容是否可再次编辑留待模块设计。

## 四、EZ 得分与交易质量

EZ 得分按交易日评价计划、执行、复盘和纪律完成度，候选维度：计划完成度、执行一致性、单笔复盘完整度、日复盘完成度、规则遵守率、风险控制、数据完整度。

Dashboard 交易质量为百分制、多维度、跨周期指标。候选维度为结果质量、执行质量、风险质量、纪律质量、复盘质量和稳定性；维度、公式及展示在评分模块详细设计时确认。

- EZ 得分与交易质量权重由管理员配置。
- 权重修改后历史得分保持不变。
- 无交易日或数据不完整时显示 N/A，不参与计算，不能默认为零分或擅自折算总分。
- 具体数据完整度门槛、评分定稿时点和历史计算依据保存方式在模块设计时确认。

## 五、AI 中心

AI 是独立的可配置、可计量、可控权限子系统：

- 基于本地交易数据生成日复盘、错误模式、计划偏离、报告摘要和改进建议。
- 可结合当日行情数据，生成基础面/技术面摘要，并显示时间和来源。
- 提供全局 AI 对话，回答用户关于自身账户、交易、策略和报告的问题。
- 用户端只选择低、中、高三档 AI 能力及默认档位，不展示供应商/具体模型供用户选择判断。
- 管理端配置实际供应商（如千问、DeepSeek）、模型、档位映射和各 AI 能力模块的消耗积分。可按“功能 × 档位”配置价格，具体规则在 AI 模块设计时确认。
- 最新规则取代此前“用户直接选择千问/DeepSeek及供应商价格”的方案；供应商成本与用户积分价格分开管理。
- 用户切换档位时不要求显示模型价格差异和预计消耗；积分余额与实际消费账单仍可查询。
- AI 可读取本人授权范围内的交易数据、笔记和附件，并结合平台提供的当日行情数据。
- 全局对话可选择一个账户或全部账户；支持历史会话，默认永久保存，用户可删除会话。
- AI 设置包含能力档位、数据能力开关、用户偏好提示词和记忆；管理端配置全局/模块提示词、供应商密钥和模型映射。自动记忆等细节留待模块设计。
- 自动生成和推送范围为日终摘要、AI 分析；由用户配置，支持站内通知和邮件。
- 自动推送同样消耗积分；调用失败退还积分。余额不足、重试去重和自动任务预算在详细设计时确认。
- 邮件验证和退订议题按用户要求暂缓讨论。
- AI 只能分析，不能下单、改止损、改账户或删数据；输出标注“分析参考，不构成投资建议”。
- 用户和管理员设置分离，供应商 API Key 只在服务端。

## 六、资源中心

平台通过 API 提供今日重要事件、经济数据和行情上下文；当前不指定供应商和品种覆盖范围，不设硬性延迟要求。

候选展示包括影响等级、相关品种、实际/预期/前值、市场摘要和品种观察；小工具候选包括仓位、风险收益和盈亏计算器。具体工具清单在模块设计时确认。数据应标注来源和更新时间。

## 七、编辑器与分享

所有撰写内容统一使用 Markdown 存储，编辑界面只采用所见即所得模式，不提供原始 Markdown 模式切换。支持图片/附件、自动保存、草稿恢复、模板加载、交易/策略/事件引用和 AI 辅助编辑。

模板变量支持日期、账户、品种、交易数、P&L、策略和订单列表。笔记模板与策略模板共同遵守“系统模板不可删除、可使用用户副本修改、不另存为个人模板、升级不覆盖旧内容”的规则。

分享对象为单篇报告内容，外部只读并支持手机浏览。分享链接唯一、无需密码、可设置有效期、可撤销。用户控制敏感字段隐藏或显示。分享页显示生成时间、有效期和数据更新时间。快照/动态内容及撤销后的缓存行为留待模块设计。

## 八、用户订阅与积分

- 一期只设置一个订阅档位，订阅提供系统使用权。
- AI 单独采用充值积分计费；订阅可赠送一定积分，赠送数量和发放方式由后续设计确认。
- 充值积分有效期由管理后台设置，不允许自动充值。
- 展示积分余额、充值记录、消费账单及失败返还记录。
- 订阅取消后保留已购积分和历史账单，未来重新订阅时继续使用；停订期间积分有效期是否暂停，留待订阅模块确认，不能擅自解释为延期或作废。
- 支付渠道、订阅价格/周期、积分兑换比例、退款范围在模块设计时确认。

## 九、管理端范围

管理端至少提供评分权重、AI 供应商和模型映射、功能积分价格、积分有效期、单档订阅及赠分规则、系统模板和全局/模块提示词配置。管理员权限和操作记录在详细设计中确认。

## 十、建议后置（非已确认的新增范围）

Trade Replay、完整回测、AI 自动交易建议、导师协作、社区、Prop Firm 专用模块、完整实时新闻系统。

## 十一、模块详细设计与阶段验收

每个模块单独建立一份详细设计文档，包含目标/非目标、功能清单、数据结构、权限、状态转换、页面与交互、接口、依赖、异常边界、验收用例和迁移方案。产品确认后实施，阶段验收后进入下一阶段。

本轮未答复的交易日实体设计、Dashboard 数据归属、开发依赖顺序、评分快照等技术问题，移入对应模块详细设计，不视为默许，也不要求在框架终审时一次性回答。

以下边界须在相关模块实施前确认：平台具体时区、跨日持仓归属、异币种账户合并口径、评分数据完整度与定稿时点、停订期间积分有效期、策略版本创建粒度、跨日补充编辑规则、报告分享内容更新方式、AI 任务预算和消费规则。

## 十二、终审记录

- 第一轮：方向和主要模块已评审。
- 第二轮：已收到用户逐项决策，并合并最新 AI 三档能力规则。
- 当前：等待框架终审；无业务代码开发。
- 终审内容：模块范围、已确认的跨模块规则、需留待详细设计的事项、分阶段验收流程。
- 终审通过后：先开展现状盘点与全局样式详细设计，确认后固化样式，再逐模块设计开发。模块实施顺序另行确认。
