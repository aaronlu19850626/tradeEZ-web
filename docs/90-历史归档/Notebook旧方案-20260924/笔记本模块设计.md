# 笔记本模块设计

版本：2.0；状态：Notebook 前端 Mock、Lexical 编辑器和图片编辑能力已落地，待验收；优先级：当前第一。

## 1. 模块定位

笔记本是用户的交易知识空间，用于保存不属于单笔交易事实的主观资料：

- 日常交易笔记
- 每日交易日志
- 交易笔记
- 盘前准备和盘后反思
- 学习记录、观察记录和目标

笔记本与订单明细、复盘、日复盘的关系：

```text
笔记本书写和组织
  -> 交易笔记关联一笔交易
  -> 每日交易日志复用 daily_reviews
  -> 订单明细读取关联内容
  -> 复盘和报表引用，但不复制
```

## 2. 范围

### 2.1 一期范围

- 笔记本导航和文件夹树。
- 一般笔记的新建、编辑、保存、删除和恢复。
- 交易笔记独立实体，一笔交易最多一条。
- 每日交易日志入口，复用 `daily_reviews`。
- 笔记模板和默认模板。
- 自动保存和版本冲突提示。
- 笔记本内部搜索。
- 笔记标签。
- 回收站和 30 天恢复。

### 2.2 一期不做

- 公网分享链接。
- 团队协作编辑。
- 多人实时共编。
- 复杂知识库双链和图谱。
- AI 自动改写用户原文。
- 多笔记批量合并导出 PDF。

## 3. 信息架构

页面：`/dashboard/notebook`

```text
左侧：文件夹和系统入口
  - 全部笔记
  - 每日交易日志
  - 交易笔记
  - 我的文件夹
  - 标签
  - 回收站

中间：笔记列表
  - 标题
  - 摘要
  - 更新日期
  - 关联交易或日期

右侧：编辑器
  - 标题
  - 正文
  - 模板
  - 标签
  - 保存状态
  - 关联对象
```

移动端采用文件夹、列表、编辑器三层导航，不同时并排展示三栏。

## 4. 业务对象

### 4.1 笔记文件夹

```text
notebook_folders
- id
- user_id
- parent_id
- name
- system_kind
- sort_order
- status
- created_at
- updated_at
```

系统文件夹：

- `daily_journal`
- `trade_note`
- `trash`

系统文件夹不能删除或重命名。

### 4.2 一般笔记

```text
notebook_notes
- id
- user_id
- folder_id
- title
- content_json
- content_text
- content_format
- status
- revision
- created_at
- updated_at
- deleted_at
```

`content_json` 保存编辑器结构，`content_text` 用于搜索和摘要。两者必须同时更新。

### 4.3 交易笔记

交易笔记是独立实体，不与复盘结论、每日日志混用：

```text
trade_notes
- id
- user_id
- trade_ref
- content_json
- content_text
- content_format
- revision
- created_at
- updated_at
```

约束：

- 一笔交易最多一条交易笔记。
- 交易重同步后，通过稳定 `trade_ref` 恢复关联。
- 原始交易事实变化时，笔记保留并提示核对，不自动改写。

### 4.4 每日交易日志

每日交易日志复用 `daily_reviews`，不创建第二份内容。

笔记本中的每日交易日志是入口和展示层：

- 按用户和交易日读取。
- 与日视图、订单明细的每日日志指向同一实体。
- 结构化问题仍由日复盘模块维护。
- 长文本笔记可以在后续扩展 `daily_reviews` 的内容字段，不建立平行日记。

### 4.5 笔记标签

```text
note_tags
- id
- user_id
- name
- color
- status

note_tag_links
- note_id
- note_type
- tag_id
```

笔记标签与交易标签完全分离，不在两个模块之间自动同步。

### 4.6 模板

```text
note_templates
- id
- user_id
- name
- description
- note_kind
- content_json
- is_default
- status
```

模板可以设置为某个系统文件夹的默认模板。

## 5. 编辑器

编辑器需要支持：

- 标题和正文
- 标题层级
- 加粗、斜体、下划线
- 多色高亮与清除高亮
- 文字颜色（深色/浅色两套默认方案）与背景颜色
- 有序列表、无序列表、待办列表
- 引用、代码和分割线
- 表格
- 图片粘贴和拖拽
- 链接
- 撤销、重做
- 自动保存

编辑器和策略 Notes 统一复用 [富文本编辑器选型与实现](Markdown编辑器选型.md) 已确认的 Lexical。Lexical 负责编辑器状态、节点模型、Markdown/JSON 序列化、划词工具栏、`/` 命令菜单、表格、自定义图片节点和未来 AI/语音扩展；工具栏、弹窗和视觉样式映射 TradeEZ 全局 Token 与标准控件。

图片节点采用显式编辑态：

- 默认只显示图片，不显示操作图标。
- 单击图片后显示缩放、裁剪和对齐控件。
- 点击图片外部或按 `Esc` 退出编辑态。
- 缩放保存未裁切基准宽高，裁剪比例独立保存。
- 裁剪使用边缘 `75%` 区域的剪刀控件，方向与所在边一致。
- 编辑器区域禁用 Lexical 右键菜单和浏览器原生右键菜单。

不能使用 `contentEditable` 手工实现完整编辑器，也不允许 Notebook 和 Strategy Notes 各自封装不同编辑器。

## 6. 主要交互

### 6.1 新建笔记

```text
选择文件夹
  -> 新建笔记
  -> 加载默认模板
  -> 输入标题和正文
  -> 自动保存
```

### 6.2 交易笔记关联

```text
打开交易笔记
  -> 搜索交易
  -> 选择账户、品种、方向、时间或交易引用
  -> 建立关联
  -> 订单明细和复盘可以读取同一笔记
```

### 6.3 删除和恢复

- 删除后进入回收站。
- 保留 30 天。
- 恢复后回到原文件夹。
- 原文件夹已删除时恢复到“全部笔记”。
- 到期后物理删除。

### 6.4 自动保存冲突

- 每次保存携带 `revision`。
- 服务端版本变化返回 `409`。
- 前端保留本地内容，提示用户比较或覆盖。
- 不静默覆盖另一个窗口的内容。

## 7. 推荐接口

```text
GET    /api/v1/my/notebook/folders
POST   /api/v1/my/notebook/folders
PATCH  /api/v1/my/notebook/folders/{folder_id}
DELETE /api/v1/my/notebook/folders/{folder_id}

GET    /api/v1/my/notebook/notes
POST   /api/v1/my/notebook/notes
GET    /api/v1/my/notebook/notes/{note_id}
PUT    /api/v1/my/notebook/notes/{note_id}
DELETE /api/v1/my/notebook/notes/{note_id}
POST   /api/v1/my/notebook/notes/{note_id}/restore

GET    /api/v1/my/trade-notes
GET    /api/v1/my/trade-notes/by-trade/{trade_ref}
PUT    /api/v1/my/trade-notes/by-trade/{trade_ref}

GET    /api/v1/my/notebook/templates
POST   /api/v1/my/notebook/templates
PATCH  /api/v1/my/notebook/templates/{template_id}
DELETE /api/v1/my/notebook/templates/{template_id}

GET    /api/v1/my/note-tags
POST   /api/v1/my/note-tags
PUT    /api/v1/my/notes/{note_type}/{note_id}/tags
```

所有接口必须按当前用户隔离，不能只依赖前端传入的 `user_id`。

## 9. 验收标准

- 用户可以创建文件夹并在其中创建笔记。
- 刷新页面后草稿不丢失。
- 两个窗口同时编辑时不会静默覆盖。
- 一笔交易只能关联一条交易笔记。
- 每日交易日志与日视图、订单明细读取同一实体。
- 删除的笔记 30 天内可恢复。
- 笔记标签和交易标签互不影响。
- 所有按钮、表单、Dialog、菜单和编辑器工具栏使用标准组件。
- 桌面、平板和移动端无页面级横向溢出。
