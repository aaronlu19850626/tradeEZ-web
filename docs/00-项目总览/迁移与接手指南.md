# 迁移与接手指南

版本：2.0；状态：已生效；用途：新机器或新成员建立正确仓库和隔离运行环境；维护人：集成负责人；依赖：《开发交接指南》《新工作启动操作手册》；验收入口：从 main 安装、启动、门禁验证和一次任务交接。

## 1. 确认实际仓库

远端为 `https://github.com/aaronlu19850626/tradeEZ-web.git`。本机历史外层目录包含 `github-src/`，实际开发根目录必须有 `.git`、`AGENTS.md`、`frontend/` 和 `backend/`。新电脑克隆后的目录本身就是根目录，不额外套一层 `github-src`。

```bash
git clone https://github.com/aaronlu19850626/tradeEZ-web.git
cd tradeEZ-web
git rev-parse --show-toplevel
git status --short --branch
git remote -v
git log -1 --oneline
```

已有仓库先 `git status` 和核对未提交成果，再 fetch；不得用旧远端覆盖未提交代码。本轮已获用户授权将此前未提交成果纳入主干，当前最终同步状态必须以本轮基线记录和实际提交为准，不能仅凭文档宣称已推送。

`main` 是后续干净起点。新任务按《新工作启动操作手册》创建独立 worktree；主 worktree 用于同步和集成，不直接做日常业务开发。

Notebook、笔记历史、笔记模板旧方案已重置，不能从归档恢复开发安排；保留的通用编辑器代码只是现有能力，需新需求评估是否复用。账户、交易记录、总览、策略等现状应读代码与最新进度，本文不再固定“下一步开发账户后台”等过时安排。

## 3. 重建本地环境

安装 Git、GitHub CLI、Node.js 22/npm、Python 3.11+、PostgreSQL 16 或 Docker，依赖版本以 CI 和锁文件为准。按操作手册完整执行：

1. 从模板新建本机 `backend/.env`、`frontend/.env.local`，使用本机随机密钥；不复制其他人的认证文件或生产环境。
2. 每个任务分配独立 dev/test/e2e 数据库、开发端口和 E2E 端口；`TRADESYNC_TEST_DATABASE_URL` 使用 `tradeez_test_*`，`TRADEEZ_E2E_DATABASE_URL` 使用 `tradeez_e2e_*`，不向开发库回退。
3. 新建 `backend/.venv`、按 requirements 安装；在 frontend 执行 `npm ci` 与 `npx playwright install chromium`。不搬运 node_modules、.next、.venv 或浏览器状态。
4. 开发前端 API 指向当前任务后端的 `/api/v1`；E2E 使用单独的 `TRADEEZ_BASE_URL` 与 `TRADEEZ_API_URL`（后者包含 `/api/v1/`）。
5. 启动前检查数据库目标；后端启动可能自动迁移。通过 `/readyz` 和登录页检查，再运行静态及浏览器门禁。

具体命令、三库建立、配置和终端操作均见《新工作启动操作手册》第 5、7 节，避免维护两套相互冲突的启动命令。Windows 建议 WSL；原生 PowerShell 需使用对应 venv 路径和环境变量语法。

## 4. 环境与生产数据不是代码迁移的一部分

本指南只迁移开发代码和已确认文档。真实数据库、同步密钥加密配置、备份和部署属于独立运维任务：由环境负责人通过安全渠道提供，并保留必要的原加密密钥，不能拿开发示例覆盖。未经该运维任务授权，不把研发启动连接到远程生产库。

固定验证码仅用于隔离开发/测试环境；生产关闭测试模式。运行数据、日志、`.env`、密钥、Playwright storageState 均不得进入 Git。

## 5. 迁移成功的检查单

- 仓库/分支/HEAD 与目标 main 或交接分支一致，未提交成果都有归属。
- 三个隔离数据库和任务端口已登记；健康检查与登录页可访问。
- 后端 pytest、前端类型/风格/构建和必要 E2E 有当前提交的真实结果。
- 接手者能够说清当前阶段、最近确认、未决项、允许修改目录与下一步。
- 无“旧 Notebook 继续开发”“账户还是内存 Mock”等未经核实的历史指令残留在当前任务中。
