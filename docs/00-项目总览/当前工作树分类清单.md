# 当前工作树分类清单

版本：2.0；状态：一次性基线整合记录；用途：记录远端主干落后时，本轮如何完整保留并验证本地代码；维护人：项目负责人；验收入口：本轮主干基线提交。

## 分类规则

用户已明确当前未提交代码必须进入主干，因为远端 `main` 仍是旧内容。本轮是建立新协作机制前的一次性基线整合：保留已有代码、清理失效文档、完成统一门禁后提交到 `main`。本轮完成后，所有新工作恢复“一模块、一分支、一 worktree、一 PR”。

| 分类 | 当前内容 | 本轮处理 |
|---|---|---|
| 治理 | `AGENTS.md`、规范、模板、CI、质量脚本 | 纳入基线并通过静态和浏览器门禁 |
| 通用编辑器 | `frontend/src/components/editor/`、设计系统 Lexical 演示 | 作为未绑定业务需求的共享实验资产保留；不作为 Notebook 需求依据 |
| 旧 Notebook 资料 | 模块设计、历史、模板、研究证据和临时研究脚本 | 移入 `docs/90-历史归档/Notebook旧方案-20260924/`，从活动索引移除 |
| 策略中心 | Playbooks 页面和策略相关共享代码 | 保留现有代码并验证；是否进入一期由新盘点决定 |
| 交易账户、交易记录和总览 | 当前页面、数据逻辑和测试 | 保留现有代码并完成统一回归 |
| 共享 UI | 全局样式、导航、图标、Dialog 和设计系统页 | 作为当前可运行基线纳入，后续改动按串行资源治理 |
| 依赖与锁文件 | `package.json`、`package-lock.json`、旧 `pnpm-lock.yaml` | npm 为唯一包管理器，提交 npm 锁文件并删除 pnpm 锁文件 |

## 基线规则

- 基线提交前不创建新的业务模块 worktree。
- 不丢弃用户未提交代码；失效资料进入历史归档。
- 基线验证和推送完成后，新模块只能从最新干净 `main` 创建。
- 本轮直接整合主干是用户针对旧远端基线的明确决定，不形成以后绕过 PR 的先例。
