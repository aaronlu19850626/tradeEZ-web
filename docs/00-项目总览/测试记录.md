## 7. 性能结果

### 7.1 后端服务路径

数据规模：136,803 笔已平仓交易，其中 USD + 外汇市场性能集 126,803 笔。完整对照见《PERF-001 性能优化报告》。

| 接口 | 优化前 | 最终冷路径 | 最终热路径 | 响应体积 |
|---|---:|---:|---:|---:|
| `/summary` | 约 1.709s | 约 0.518s | 约 0.018s | 34.5KB |
| `/groups` 摘要 | 约 260KB | 约 0.18s | 按展开懒加载 | 19.5KB |
| `/group-trades` 单组明细 | 未拆分 | 约 0.02s | 展开后才请求 | 3.2KB |
| `/overview` | 约 3.3s | 约 1.49s | 接口层约 1.5s，缓存命中未体现为端到端收益 | 292KB |
| `/calendar` | 约 5.7s | 约 0.02s | 约 0.02s | 按月返回 |
| `/trades?page=1&page_size=100` | 未单独记录 | 约 0.15s | 约 0.15s | 当前页 |

### 7.2 真实浏览器 API 请求

- 最终总览请求 `/trades/overview?...from_day=2014-01-17&to_day=2026-09-22...`：冷路径约 1.49s，响应约 292KB
- 汇总请求 `/trades/summary?...`：冷路径约 0.52s，热路径约 18ms
- 交易记录分组摘要 `/trades/groups?include_trades=false...`：约 0.18s，约 19.5KB
- 单组交易明细 `/trades/group-trades...`：约 0.02s，约 3.2KB
- 月历 `/trades/calendar?month=2026-09...`：约 21–43ms
- 账户列表 `/accounts`：约 30–125ms

### 7.3 已实施性能修复

- 总览改为 SQL 聚合统计、评分输入、日线、累计/回撤、最近交易和一致性。
- 总览三张散点图改为固定 256 个像素桶，每桶保留最小和最大盈亏边界，真实数据下三图共约 1,404 点。
- 汇总统计和累计曲线改为 SQL 聚合，累计曲线最多返回约 1,000 个采样点。
- 月历改为 `closed_trades` 的单一 SQL 聚合，不再加载全量交易后在 Python 中扫描。
- 日/周分组首屏只返回分组摘要，第一组自动加载明细，其他分组在展开时通过 `/group-trades` 按需加载。
- 总览累计净损益和回撤不再由接口重复返回，改为前端从唯一日线数据派生。
- 账户页交易数改为 `closed_trades` 投影计数，避免每个账户扫描 `deals`。
- 总览和交易记录在日期范围确定前不发起重数据请求，消除首屏重复请求。
- 汇总、分组和总览增加 30 秒用户级缓存，并在同步、重置、删除、导入和账户配置更新后失效。
- 统一 R 倍数口径：只有止损价格有效且大于 0 时才计算 R，`sl_price=0` 不再误计入评分。

## 8. 本轮发现并修复的问题

| 问题 | 根因 | 修复 | 状态 |
|---|---|---|---|
| 总览多品种筛选不更新统计和最近交易 | 前端只提交第一个品种，后端只接收单品种 | `symbol` 支持逗号分隔多品种，SQL 使用 `symbol IN (...)` | 已修复 |
| 全部视图排序只影响当前页 | 表格本地排序只处理当前页 | 排序改为服务端参数，排序后回第 1 页 | 已修复 |
| 分页无法跳转到指定页 | 只有上一页/下一页 | 增加页码输入框，回车/失焦跳转 | 已修复 |
| 总览首屏重复请求重数据 | 日期范围未初始化前先请求一次，初始化后再请求 | 日期范围确定前只取账户边界和品种，不请求总览/分组 | 已修复 |
| 月历接口大数据慢 | 全量加载交易后在 Python 中扫描 | 改为 `closed_trades` SQL 按日聚合 | 已修复 |
| 账户列表慢 | 每个账户扫描 `deals` 统计交易数 | 改为 `closed_trades` 投影计数 | 已修复 |
| 总览/汇总构造大量 Pydantic 对象 | 12.6 万笔交易全部构造 `TradeItem` | 聚合路径改用 `LightTrade` | 已修复 |
| 空账户首屏闪空态 | 账户范围未解析完就先渲染空态 | 增加初始加载判定 | 已修复 |
