# 质量门禁与统一检查

版本：1.1；状态：已生效；用途：统一本地、PR 和 CI 质量门禁；维护人：技术负责人；验收入口：质量脚本。

## 1. 统一命令

仓库根目录执行：

```bash
./scripts/quality/check.sh
```

静态门禁：

```bash
./scripts/quality/static.sh
```

依次执行 `git diff --check`、后端 `pytest -q`、前端 `tsc --noEmit`、Biome 和生产构建。

浏览器门禁：

```bash
./scripts/quality/e2e.sh
```

校验专用空数据库和端口后，播种合成数据、自启受管前后端，再运行 Playwright 桌面、平板、移动三档回归。

完整本地门禁：

```bash
./scripts/quality/check.sh
```

若只需静态检查，直接运行 `./scripts/quality/static.sh`。`SKIP_E2E=1` 仅用于明确记录浏览器门禁未运行的临时场景，不能作为完整门禁通过证据。

## 2. 前置条件

- 显式设置 `TRADESYNC_TEST_DATABASE_URL`，数据库名必须以 `tradeez_test_` 开头。
- 显式设置 `TRADEEZ_E2E_DATABASE_URL`，数据库名必须以 `tradeez_e2e_` 开头且运行前为空。
- 受管 E2E 默认后端为 `http://127.0.0.1:8311`、前端为 `http://127.0.0.1:3311`；通过 `TRADEEZ_API_URL` 和 `TRADEEZ_BASE_URL` 为并行任务分配独立地址。
- 本地 PostgreSQL 可用；E2E 脚本负责迁移和合成数据，绝不指向开发或生产库。
- 后端虚拟环境位于 `backend/.venv`
- 本地 Playwright 默认使用 Google Chrome；CI 使用 Playwright Chromium。

`e2e.sh` 会拒绝占用中的端口和非专用数据库，自启服务并检查 `/readyz` 与登录页。测试结束后自动停止自己启动的进程。

## 3. 结果记录

每次 PR 以 CI 检查结果为准；本地结果通过命令输出、Playwright HTML/JSON 报告和 PR 评论记录，不在本文档写入会过期的固定数量。

## 4. 排除范围

- `public/platforms/*.svg` 是外部品牌静态资源，由页面 `<img>` 提供可访问名称，不作为内联 SVG 参与 Biome 可访问性检查。
- `frontend/src/components/ui` 和 `frontend/src/components/calendar` 继续由 shadcn 上游样式管理，不纳入当前业务代码规范检查。

## 5. 维护规则

- 后续新增前端模块后，必须继续保证全量 `biome check`、TypeScript、生产构建和三档 Playwright 通过。
- 新增后端功能必须进入 `pytest`，不得只依赖手工接口验证。
- 任何临时跳过项必须在本文档登记原因和移除条件。
- 并行任务必须使用独立数据库、端口和 Playwright 状态目录，不得共享认证文件或运行数据。
