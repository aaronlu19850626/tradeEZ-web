# 质量门禁与统一检查

版本：1.0；状态：已生效。

## 1. 统一命令

仓库根目录执行：

```bash
./scripts/quality/check.sh
```

命令按顺序执行：

1. 后端 `pytest -q`
2. 前端 `tsc --noEmit`
3. 前端全量 `biome check`
4. 前端 `next build`
5. Playwright 桌面、平板、移动三档回归

只执行静态门禁、不执行 Playwright：

```bash
SKIP_E2E=1 ./scripts/quality/check.sh
```

只执行浏览器回归：

```bash
./scripts/quality/e2e.sh
```

## 2. 前置条件

- 后端运行在 `http://127.0.0.1:8000`
- 前端运行在 `http://127.0.0.1:3000`
- 本地 PostgreSQL 可用并已执行迁移
- 后端虚拟环境位于 `backend/.venv`
- Playwright 使用本机 Google Chrome

`e2e.sh` 会先检查 `/readyz` 和前端首页，任一服务未启动时立即失败，不会运行半套用例。

## 4. 排除范围

- `public/platforms/*.svg` 是外部品牌静态资源，由页面 `<img>` 提供可访问名称，不作为内联 SVG 参与 Biome 可访问性检查。
- `frontend/src/components/ui` 和 `frontend/src/components/calendar` 继续由 shadcn 上游样式管理，不纳入当前业务代码规范检查。

## 5. 维护规则

- 后续新增前端模块后，必须继续保证全量 `biome check`、TypeScript、生产构建和三档 Playwright 通过。
- 新增后端功能必须进入 `pytest`，不得只依赖手工接口验证。
- 任何临时跳过项必须在本文档登记原因和移除条件。
