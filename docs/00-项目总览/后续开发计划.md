# TradeEZ 后续开发计划

版本：1.0；状态：执行中。

## 1. 立即收尾

- 网络恢复后推送本地待提交内容。
- 确认当前本地数据库版本与代码迁移头一致。
- 确认 MT5 V2 `2.0.1` EA 已在测试终端完成编译、挂载和全历史回填验证。

## 2. MT5 时区与夏令时

### 2.1 券商规则目录

- 收集并确认常见 MT5 券商的服务器时区规则。
- 将确认后的规则写入 `broker_timezone_profiles`。
- 规则来源必须明确：官方说明、实测偏移样本或内部运营确认。

### 2.2 自动学习收口

- 继续完善欧洲、英国、美国、澳洲以外时区的识别。
- 对无法稳定识别为 IANA 时区的券商使用固定偏移规则。
- 增加候选置信度和状态审计。

### 2.3 自动回填

- 观察 `timezone_backfill_required` 账户的完成率和失败率。
- 确保旧 V1 账户在升级前不会被反复清空游标。
- 验证自动重算不会覆盖用户手动导入的交易时间。

## 3. 连接器分发与升级

- [x] 后端提供 MT5 V2 EA 文件下载接口。
- [x] 握手响应中的下载地址改为当前服务可访问地址。
- 记录 EA 版本分布，观察 `2.0.1` 升级率。
- 后续版本发布时提供 `upgrade.required` 和最低版本策略。

## 4. 同步可观测性

- 提供同步运行、批次、事件和异常的内部查询接口。
- 建立失败批次、冲突批次和候选时区指标。
- 在保留幂等规则的前提下增加必要的重试和告警。

## 5. 多平台连接器

- 将账户身份从 `mt5_login` 泛化为平台账户标识。
- 定义平台能力清单和凭证模型。
- 按优先级接入 MT4、cTrader、ATAS、CTP。
- 每接入一个平台补充账户、成交、品种、快照、持仓和心跳测试。

## 6. 性能治理

- [x] 为成交查询增加账户、方向、时间复合索引。
- [x] 为交易列表按用户和筛选条件增加短 TTL 查询缓存，并在同步、重置、删除、导入后自动失效。
- [x] 后端单页上限提升到 1000，前端首次全量装载时减少请求轮次。
- [x] 交易列表默认排序改为数据库 `LIMIT/OFFSET + COUNT`，不再全量取回切片。
- [x] 交易记录“全部视图”已切换到服务端分页和汇总接口。
- [x] 新增交易日期边界和分组分页接口。
- [x] 交易记录日/周视图已切换到服务端分组接口，右侧日历按月份从 `/trades/calendar` 拉取。
- [x] 交易总览已切换到 `/api/v1/trades/overview` 服务端聚合接口，不再循环拉取全部成交。
- [x] 交易总览散点图已增加服务端固定像素桶，并保留每桶盈亏边界。
- [x] 建立 `closed_trades` 投影表与按账户惰性刷新机制，交易查询不再重复聚合 `deals`。
- [x] 汇总、分组键和总览统计已改为 SQL 聚合，筛选变化不再触发 Python 全量交易聚合。
- [x] 汇总、分组和总览增加 30 秒用户级缓存，并在同步、重置、删除、导入和账户配置更新后失效。
- [x] 总览散点改为固定 256 像素桶，累计与回撤改为前端从唯一日线派生，总览响应降至约 292KB。
- [x] 分组首屏改为摘要加按需明细，摘要响应降至约 19.5KB，单组明细约 3.2KB。
- [ ] 将分组摘要统计进一步下沉到单条 SQL，降低当前约 0.39 秒的摘要计算耗时。
- [ ] 评估单组明细按表格列裁剪字段的策略。
