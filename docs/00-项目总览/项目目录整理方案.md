# TradeEZ Web 项目目录整理方案

版本：1.0；状态：已批准并完成首轮执行（2026-09-22）。

本文用于整理前端、后端、连接器、脚本和说明文档，建立一个职责清晰、入口稳定、可迁移、可持续扩展的项目目录。方案已按 A-E 阶段完成首轮执行，路由、API 和运行命令保持稳定。

## 1. 整理目标

1. 目录名称能够直接表达职责，不依赖历史上下文猜测。
2. 页面入口、业务组件、共享组件、领域逻辑和基础设施分层明确。
3. 三个核心模块保持一致的组件和设计规则。
4. 文档只有一个权威版本，历史稿和副本集中归档，不再与当前文档混放。
5. MT5、MT4、cTrader、ATAS、CTP 等连接器有稳定的扩展位置。
6. 移动文件时保持路由、API、导入路径和运行命令可控。
7. 每一批整理都能独立验证和回滚。

## 2. 当前问题

> 以下内容是整理前基线，用于解释拆分动机；其中的旧路径已在首轮执行中迁移。

### 2.1 前端页面文件过大

当前主要巨型文件：

- `frontend/src/app/(main)/dashboard/trade-center/page.tsx`：约 2518 行。
- `frontend/src/components/dashboard/overview-panels.tsx`：约 1527 行。
- `frontend/src/app/(main)/dashboard/account-center/page.tsx`：约 942 行。

问题：

- 页面入口、筛选逻辑、图表、表格、弹窗、格式化函数和常量混在同一文件。
- 修改一个控件容易影响同一文件中的多个模块。
- 代码复用和测试边界不清晰。

### 2.2 共享组件与业务组件边界不清晰

当前存在：

- `frontend/src/components/dashboard/`
- `frontend/src/components/*.tsx`
- `frontend/src/lib/tradesync/`

`components/dashboard` 同时包含多个模块都可能使用的组件和只服务一个页面的业务组件；`lib/tradesync` 同时放 API、类型、格式化、Mock、i18n 和评分逻辑。

### 2.3 文档存在重复和同名副本

需要归档或合并的内容：

- `API规范V2-副本1.md`
- `API规范V2-副本2.md`
- `TradeEZ-SOP_数据同步接口说明(1).md`
- `设计说明-副本1.md`
- 多份 UI / 全局样式 / 产品说明中可能重复的规则

问题：

- 无法判断哪一份是权威版本。
- 文档更新容易只改一份。
- 新环境阅读顺序不清晰。

### 2.4 EA 和连接器目录不统一

当前同时存在：

- `ea/`：探针和辅助脚本。
- `syncEA/MT5/`：同步客户端。
- `backend/app/connectors/`：服务端连接器接口。

未来还会加入 MT4、cTrader、ATAS、CTP，当前结构无法表达客户端、协议版本和平台归属。

### 2.5 临时文件和历史实现缺少归档层

Mock、副本、旧协议说明、旧模板和中间设计稿需要统一进入归档目录，不能继续和当前实现文档放在同级。

## 6. 分阶段迁移计划

### 阶段 A：文档整理，低风险

- 建立 `docs/README.md`。
- 将副本和历史稿移动到 `docs/90-历史归档/`。
- 合并重复规则，只保留一个权威版本。
- 更新所有跨目录引用。
- 验收：所有 Markdown 链接有效，索引无重复权威文档。

### 阶段 B：前端共享组件归类

- `ui/` 保持不变。
- 将跨模块组件移动到 `components/shared`、`data-table`、`charts`、`dialogs`、`filters`、`domain`。
- 更新导入路径，不改变渲染结果。
- 验收：tsc、Biome、三个模块浏览器回归。

### 阶段 C：交易记录页面拆分

- 先拆纯函数和常量。
- 再拆表格、日历、弹窗和视图组件。
- 最后收敛 `page.tsx` 为数据编排层。
- 验收：排序、筛选、日历、表头吸顶、分页、多选和弹窗全部回归。

### 阶段 D：账户和总览拆分

- 按新建目录结构拆分账户弹窗、表格、指标和总览面板。
- 共享部分进入 `features` 或 `components`。
- 验收：新增账户、重置交易、总览图表和筛选全部回归。

### 阶段 E：连接器和脚本归并

- 将 EA、探针和协议版本移动到 `connectors/`。
- 将本地、LAN、数据库脚本移动到 `scripts/` 分类目录。
- 保留旧路径兼容说明或短期转发文件。
- 验收：EA 下载、部署脚本、探针启动和连接器测试。

## 7. 命名规则

- 目录使用小写英文和连字符：`trade-center`、`account-center`。
- 页面级组件使用 `_components`、`_hooks`、`_lib`，避免污染全局。
- React 组件使用 PascalCase；纯函数和 hooks 使用 camelCase。
- 类型、API 客户端、格式化和 Mock 分开命名，不再使用模糊的 `utils` 存放领域逻辑。
- 文档使用中文文件名和明确版本状态。

## 8. 验收基线

每次迁移后必须满足：

- `npx tsc --noEmit`
- Biome 检查
- 后端 pytest（如涉及后端）
- 三个核心模块浏览器回归
- 390 / 768 / 1024 / 1440 响应式检查
- Light / Dark 检查
- 中英文检查
- 所有文档引用可访问
- 运行命令和路由保持不变

## 9. 风险与回滚

| 风险 | 处理 |
|---|---|
| 导入路径遗漏 | 每批只移动一类文件，使用 TypeScript 与全局引用扫描验证 |
| 页面行为变化 | 先拆分纯函数，再拆 UI，最后收敛入口 |
| Git 历史难追踪 | 使用 `git mv`，避免删除后新建 |
| 文档链接失效 | 迁移后运行链接扫描并人工打开入口文档 |
| EA 下载/脚本路径变化 | 先保留旧路径转发，确认外部下载完成后再删除 |
| 大范围改动难以回滚 | 按 A-E 阶段独立提交，每阶段可单独回滚 |

## 10. 建议审批方式

请选择：

1. 批准完整 A-E 计划。
2. 只批准阶段 A，先整理文档。
3. 先批准阶段 A+B，整理文档和前端共享组件。
4. 调整目标目录后再批准。

审批通过后，按阶段建立独立提交和验收记录；每个阶段完成后再进入下一阶段。
