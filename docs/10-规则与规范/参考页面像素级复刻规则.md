# 参考页面像素级复刻规则

版本：1.0；状态：强制遵守。

## 1. 一句话触发方式

后续只需发送：

> 按《参考页面像素级复刻规则》复刻：`<网址、页面名或具体功能点>`。

收到该指令后，必须完整执行本文流程，不得跳过研究、源码审计、弹框枚举、状态覆盖和浏览器验证。

## 2. 第一原则

1. 不得凭记忆、截图印象或相似组件猜测实现。
2. 必须通过专用研究浏览器实际打开目标页面，检查 DOM、CSS、资源和真实交互。
3. 目标页面无法访问时立即停止编码，并向用户索取：
   - 当前页面截图。
   - 浏览器保存的 HTML。
   - 可用时提供 CSS、JS、字体和图片资源。
4. 每次只复刻一个明确功能点，但同一功能点的所有状态、子面板和弹层必须一次纳入。

## 3. 研究浏览器源码审计

编码前必须记录以下证据：

### 3.1 页面与环境

- 页面 URL、页面标题和用户状态。
- 桌面端实际视口；移动端如有必要同步采集。
- Light/Dark 主题、语言和缩放比例。
- 页面壳、导航、内容区、滚动容器和固定层。

### 3.2 DOM 与 CSS

逐项记录：

- 元素层级和稳定选择器。
- `outerHTML` 摘要。
- 实际尺寸、位置、间距、内边距、外边距。
- 字号、字重、行高、字距、字体族。
- 背景、文字、边框、圆角、阴影。
- `z-index`、定位方式、溢出和滚动行为。
- `hover`、`active`、`focus-visible`、`disabled`、`loading`、`selected` 状态。
- 动画的 duration、timing-function、transform-origin 和进出场方向。

### 3.3 交互

- 触发元素和触发方式。
- 键盘行为：Tab、Enter、Space、Escape、方向键。
- 焦点进入、焦点陷阱和关闭后的焦点回归。
- 打开、关闭、切换、选择、提交、取消、重置和错误恢复。

### 3.4 图标与资源

- 原始 SVG 的 `viewBox`、path、fill、stroke。
- 图标实际渲染尺寸、外部容器尺寸和对齐规则。
- 位图资源路径、尺寸和用途。
- 关键图标必须进入
  `frontend/src/components/icons/tradezella/icon-registry.json`
  并提供稳定语义名。
- 图标命名、来源和使用方式见《TradeZella 图标注册表》。

## 4. 弹框穷举

必须列出页面中的每一个弹框，并形成表格：

| 弹框 | 触发者 | 类型 | 关闭方式 | 关键状态 | 是否已复刻 |
|---|---|---|---|---|---|

弹框类型包括但不限于：

- Dialog。
- AlertDialog。
- DropdownMenu。
- Popover。
- Tooltip。
- Drawer / Sheet。
- 日历、时间、颜色和其它复合选择器。

每个弹框都必须核对：

- 遮罩层和层级。
- 锚点方向、位置、尺寸、边距和最大宽高。
- 标题栏、内容区、底部操作区。
- 内边距、分隔线、滚动区和滚动条。
- 表单字段、默认值、禁用态、必填规则、校验时机和错误提示。
- 主按钮、次按钮、危险按钮和关闭按钮。
- 右上角 X、Escape、点击遮罩、提交成功、取消和路由变化关闭。
- 打开动画、关闭动画和焦点管理。
- 键盘导航和屏幕阅读器语义。

只要弹框没有完成上述审计，整个任务不得标记为完成。

## 5. 标准控件映射

1. 优先映射到 TradeEZ 现有标准控件。
2. 不得为了复刻视觉而复制一套新的 Button、Input、Select、Table、Dialog 或 Popover。
3. 参考产品的控件只作为视觉和交互参考，底层仍使用 TradeEZ 标准语义组件。
4. 标准控件无法覆盖时，先提交非标准控件评审。
5. 图标只允许使用以下来源：
   - `frontend/src/components/icons/tradezella/` 中的统一注册表。
   - TradeEZ 现有标准图标。
   - 参考页面原始 SVG，经审计后加入注册表。
6. 禁止用文字、字母、emoji 或近似图标替代原始 SVG。

## 6. 状态矩阵

每个控件和弹框至少覆盖：

| 状态 | 必查 |
|---|---|
| 默认 | 是 |
| hover | 是 |
| active / pressed | 是 |
| focus-visible | 是 |
| disabled | 是 |
| loading | 是 |
| selected | 是，适用时 |
| empty | 是，适用时 |
| error | 是，适用时 |
| success | 是，适用时 |

## 7. 响应式、主题和国际化

- 至少验证：390px、768px、1024px、1440px。
- Light 和 Dark 均需实际渲染检查。
- 中文和英文均需检查文本长度、截断、换行和快捷键。
- 页面、弹框和工具栏不得产生意外页面级横向滚动。

## 8. 实现后回测

必须使用 Playwright 或同等真实浏览器自动化完成：

1. 打开真实本地运行页面。
2. 按研究记录逐项操作。
3. 对每个弹框截图。
4. 量取尺寸、位置和计算样式。
5. 验证所有状态。
6. 验证关闭方式和焦点回归。
7. 验证提交、校验、loading、错误和成功。
8. 与参考页面的源码审计表逐项对账。

测试证据至少包括：

- 页面和弹框截图。
- DOM 摘要。
- 计算样式数据。
- 交互测试日志。
- 未解决差异清单。

## 9. 交付物

每个复刻任务完成时必须交付：

- 可运行代码。
- 自动化测试。
- 研究浏览器审计记录。
- 图标注册表变更。
- 参考页面与本地页面的对齐报告。
- 未解决项和风险。
- 项目进度更新。

## 10. 停止条件

出现以下任一情况必须暂停并请求用户补充：

- 目标页面无法访问。
- 关键弹框无法触发。
- 资源缺失且无法合法获取。
- 参考实现依赖无法确认的业务规则。
- 标准控件无法覆盖且尚未评审。

除此之外，不得因实现复杂而自行简化布局、图标、状态或交互。
