# TradeEZ UI 规范

版本：1.0；状态：已确认，前端开发强制遵守。

当前配色基线：Palette A `Conservative Professional`，支持 Light / Dark。

Dark 主题按参考图重新定义：近黑页面 `#05090D`、侧栏独立冷黑 `#0D1217`、深灰卡片 `#101418`、细灰边框 `#2A3035`，主操作紫 `#7357E6`；盈利 `#3BCB9A`、亏损 `#FF6868`、警告 `#F3B43F`、信息 `#3F7CFF`。

## 1. 执行范围

本规范覆盖所有前端页面、业务组件、共享组件和弹层。新增或修改前端代码必须先阅读本规范，再阅读对应模块设计文档。

底层组件统一使用 `frontend/src/components/ui/` 中的 shadcn / Radix 组件。禁止在业务代码中重新发明按钮、输入框、徽标、表格、弹窗和 Tooltip。

组件总览页：`/dashboard/design-system`。

## 2. 组件优先级

1. 优先使用 `src/components/ui/` 现有组件。
2. 需要业务语义时，在 `src/components/` 或模块 `_components/` 中做轻量包装。
3. 不得直接修改 `src/components/ui/` 和 `src/components/calendar/`。
4. 原生 `<button>` 只允许用于 shadcn Trigger、日历格子、表格排序等必须定制布局的场景，并必须使用全局 Button 变体或明确的语义类。
5. 所有交互控件必须支持键盘焦点、禁用态、加载态和鼠标手型。

## 3. 颜色体系

统一使用语义 token，不允许业务页面散落任意色值。

| 语义 | Token / 变体 | 用途 |
|---|---|---|
| 主操作 | `primary` | 提交、创建、确认、主链接 |
| 主操作悬停 | `primary-hover` | 主按钮 hover，必须比默认色更深 |
| 主操作浅色 | `primary-soft` | 已选账户、选中筛选、轻量主操作 |
| 次操作 | `secondary` / `outline` | 取消、辅助操作 |
| 成功/盈利 | `success` | 成功状态、盈利语义 |
| 危险/亏损 | `danger` / `destructive` | 删除、重置、亏损语义 |
| 警告 | `warning` | 风险提醒、重置交易、重置密钥 |
| 信息 | `info` | 普通信息、说明、持平状态 |
| 中性 | `muted` / `accent` | 背景、悬停、次要文字 |

按钮和徽标必须提供实色与浅色两套状态。浅色状态用于信息层级较低但仍需明确语义的场景。

## 4. 按钮规范

### 4.1 变体

全局 Button 支持：

- `default`：主操作。
- `outline`：普通次操作和筛选触发。
- `secondary`：选中或轻量操作。
- `ghost`：工具栏、图标、无边框操作。
- `destructive`：删除、重置等危险操作。
- `link`：文本链接。
- `success` / `success-soft`：成功、盈利、完成。
- `danger` / `danger-soft`：失败、亏损、危险。
- `warning` / `warning-soft`：警告、需注意。
- `info` / `info-soft`：普通信息。
- `primary-soft`：选中态、账户范围、筛选选中项。

悬停状态必须让颜色加深，不使用变浅或仅降低透明度的方式。

### 4.2 尺寸

| 尺寸 | 高度 | 用途 |
|---|---:|---|
| `xs` | 24px | 极紧凑表格和标签操作 |
| `sm` | 24px | 工具栏、表格行内操作 |
| `default` | 32px | 页面和表单主操作 |
| `form` | 40px | 日期选择器等必须与 Input 等高的表单触发控件 |
| `lg` | 36px | 强调主操作 |
| `icon` | 32px | 常规图标按钮 |
| `icon-sm` | 28px | 面板、表格图标按钮 |
| `icon-xs` | 24px | Tooltip、辅助图标按钮 |

小按钮必须真实小于默认按钮。不得通过全局 `min-height` 把小按钮撑高。

### 4.3 使用规则

- 工具操作优先使用图标按钮，并提供 `aria-label`。
- 明确命令使用文字按钮，例如“确认”“关闭”“添加新账户”。
- 同一区域最多一个主操作。
- 危险操作必须使用 danger/destructive 变体，不能伪装成普通按钮。
- 下拉菜单的普通、警告和破坏性操作分别使用 `default`、`warning`、`destructive` 变体，不在业务页硬编码 amber/red。
- 不使用自造渐变、阴影或彩色边框替代全局变体。
- 不要在 Dropdown Item 中嵌套第二个按钮外观；底部确认操作用真正的全局 Button。

## 5. 徽标规范

Badge 必须使用全局变体，不用自定义色块替代。

- `default`：主状态。
- `secondary`：中性状态。
- `outline`：轻量状态。
- `destructive` / `danger`：错误、失败、风险。
- `success`：正常、盈利、已同步。
- `warning`：等待、需处理。
- `info`：信息、持平。
- `primary-soft`：已选中、统计范围、当前配置。
- 浅色状态使用 `success-soft`、`danger-soft`、`warning-soft`、`info-soft`。

## 6. 表单与筛选

- 输入框、选择器、检查框、单选框、开关和滑杆统一使用 `src/components/ui`。
- 筛选控件必须使用全局入口 `@/components/filters`，不得在业务页复制筛选器结构。
- 单选、多选、复杂多条件、日期范围、Tab 切换统一遵循《[筛选器控件规范](筛选器控件规范.md)》。
- 筛选器使用草稿确认模式：选项只修改草稿，点击“确认”后应用；关闭不应用。
- 单选使用 `RadioGroup`，多选使用 `Checkbox`；两类控件行高和上下间距必须一致。
- 多条件面板左侧为条件名称、右侧为对应选项；底部左侧清空条件，中间按“条件名称：条件值”展示可逐项删除的已选条件，“全部”不参与展示，右侧固定“关闭 / 确认”标准按钮。
- 无筛选条件时显示“无 / 全部日期”，不能把默认全范围伪装成已选条件。
- 平台、币种等账户表单控件继续复用全局 Button 与全局选择器，不自定义状态样式。
- 币种默认优先 USD；CTP 默认并锁定 CNY。
- 同步开始日期留空时，表单必须显示“留空默认同步全部历史交易”。

### 6.1 数值格式化

全局数值格式化入口为 `frontend/src/lib/format-numbers.ts`。业务页面、共享组件和模块模型不得再各自实现金额、数量、百分比或 K 值逻辑。

- `formatMoney`：精确金额，固定两位小数，并带币种符号，例如 `-$1,234.56`。
- `formatMoneyStat`：指标、统计卡和分组摘要使用；绝对值达到 `10,000` 时显示 K 值并保留一位小数，例如 `-$12.3K`。
- `formatMoneyCompact`：图表刻度和空间受限标签使用，与 `formatMoneyStat` 使用同一阈值和 K 值口径。
- `formatMoneyAxis`：需要完整整数轴值时使用，例如 `-$12,346`。
- `formatCount`：交易数、账户数等数量达到 `10,000` 时统一显示 K 值，例如 `62.4K`。
- `formatPercent`：百分比统一传入百分数数值，默认保留两位小数；紧凑场景可显式指定小数位。
- `formatPrice`、`formatVolume`：价格和数量分别按全局精度规则输出。

金额默认币种为 `USD`；需要展示账户或交易原币时，必须显式传入 `USD / CNY / EUR / GBP / JPY / HKD`。金额不得在没有币种说明的情况下跨币种合并。

### 6.2 市场涨跌配色

- 国内市场使用 `market_profile="cn"`，正收益和上涨为红色，负收益和下跌为绿色。
- 外汇市场使用 `market_profile="fx"`，正收益和上涨为绿色，负收益和下跌为红色。
- 交易结果只能使用 `profit / loss` Token，业务组件不得写死红绿。
- `success / danger / destructive / warning / info` 是固定产品语义色，不跟随市场切换。
- 混合市场必须强制选择单一市场；CNY 默认联动国内，USD 默认联动外汇。
- 详细契约见《[市场涨跌配色方案](../30-模块设计/市场涨跌配色方案.md)》。

## 7. 面板与卡片

- 页面区块使用无边框留白结构；Card 只用于独立重复单元、弹窗和明确工具容器。
- 卡片圆角不超过 8px；现有设计系统需要更大圆角时保持全局一致。
- 卡片标题、说明、操作和正文必须形成清晰层级。
- 指标卡数值使用 tabular-nums，金额、百分比、R 倍数格式统一。
- 不把 Card 嵌套在 Card 中。

## 8. 数据表格

- 业务数据表统一使用 `src/components/data-table.tsx`；只有小型、静态、无统一列模型的展示表可以直接使用 `src/components/ui/table.tsx`。
- 表头使用浅紫灰背景，标题加粗，高度约 40px，支持粘性表头。
- 时间、数量、金额使用 tabular-nums；金额右对齐，方向、状态和短标识居中。
- 表格中的交易方向统一使用 `TradeSideBadge`：`TrendingUp / TrendingDown` 前缀图标加描边徽标，不使用红绿配色。
- 行操作放在行内，使用 Button 变体；危险操作使用 danger/destructive。
- 表格窄屏允许局部横向滚动，不允许整个页面横向溢出。
- 空、加载、错误和 N/A 必须在表格区域内表达。
- 多选表头使用 Checkbox 的 `checked / indeterminate` 状态控制当前页全选，行 Checkbox 使用行选择 API；同时显示“已选择 x / y 行”，无选择时批量操作禁用。
- 分页使用 `nav[aria-label="pagination"]`，上一页/下一页提供明确 aria-label，当前页使用 `aria-current="page"`。

## 9. 弹窗与提示

- 核心操作使用居中 Dialog 或 AlertDialog，不使用右侧抽屉承载核心操作。
- Dialog 必须遵循 `Dialog + DialogContent > DialogHeader(Title/Description) + DialogBody + DialogFooter` 结构。
- `DialogHeader` 始终可见，正文统一放入 `DialogBody` 独立滚动，`DialogFooter` 固定显示；禁止让整个 Dialog 滚动或出现正文嵌套滚动。
- 每个 Dialog 必须有 `DialogTitle` 和 `DialogDescription`；不适宜展示的描述使用 `sr-only`。
- Dialog 默认保留右上角关闭按钮；只有明确要求阻止直接关闭时才使用 `showCloseButton={false}`。
- Dialog 必须在短视口内限制最大高度，Footer 不得超出屏幕；底部操作顺序为次要操作左、主操作右。
- Dialog 打开初始焦点落在容器，不自动聚焦首个 Tooltip 触发器。
- Tooltip 最大宽度 256px，内容换行，统一使用全局 Tooltip。
- 信息提示统一使用共享 `InfoTip`：默认显示 24px 浅灰圆底与 12px Info 图标；hover/focus 只提升图标文字对比度，不隐藏或改变圆形背景。
- Tooltip 只在鼠标悬停或键盘聚焦时出现，弹窗打开不得自动展开。
- 底部按钮顺序：次要操作在左，主操作在右。

## 10. 加载、空态与错误

- 筛选、刷新或数据结构变化必须提供明确加载反馈；可使用遮罩和波形加载动画。
- 初始化或筛选重载期间，筛选工具栏必须进入 `aria-busy + inert + pointer-events-none` 状态，禁止再次修改筛选；保留当前值和布局，不使用全页模糊遮罩。
- 加载反馈不能改变页面主要布局尺寸。
- 空态必须说明原因和下一步动作。
- 接口错误必须就地显示并提供重试，不清空已有数据。
- 缺失数据使用 `N/A`，不能默认显示 0。

## 11. 页面响应式标准

采用 Tailwind 默认断点：

| 断点 | 宽度 | 页面规则 |
|---|---:|---|
| 默认 | `< 640px` | 单列、16px 页面间距、筛选横向滚动或换行 |
| `sm` | `≥ 640px` | 指标卡 2 列，按钮组开始展开 |
| `md` | `≥ 768px` | 表单可双列，筛选工具栏同行 |
| `lg` | `≥ 1024px` | 页面两侧 40px 留白，复杂区域可双列 |
| `xl` | `≥ 1280px` | 页面两侧 48px 留白，总览三列、交易记录主表+日历 |
| `2xl` | `≥ 1536px` | 页面最大宽度 `max-w-screen-2xl`，数据密度优先 |

### 11.1 页面容器

- 页面根容器：`mx-auto flex w-full max-w-screen-2xl flex-col gap-5`。
- 移动端页面间距 16px；桌面按现有 Dashboard 工作区规则自动扩展。
- 窄屏不允许出现页面级横向滚动；表格和筛选可以局部滚动。
- 展开侧栏宽度 196px；分组左右内边距 12px，菜单行高 40px、行间距 6px，分组标题与首项额外间隔 4px。

### 11.2 交易总览

- 指标卡：移动端 1 列，`sm` 2 列，`xl` 5 列。
- 评分/一致性/累计净损益：移动端 1 列，`xl` 3 列。
- 每日净损益/最近交易/回撤：移动端 1 列，`xl` 3 列。
- 月历与右侧图表：移动端上下排列，`xl` 左侧跨两行、右侧两面板上下排列。
- 筛选变化显示遮罩加载态。

### 11.3 交易记录

- 移动端工具栏换行，表格横向滚动。
- `xl` 以下月历和主表上下排列；`xl` 主表与日历并排。
- 视图切换使用全局 `ToggleGroup`，选中态统一使用 `primary-soft + 主色文字 + font-semibold` 高亮；筛选触发器使用全局 `@/components/filters` 控件。
- 日期范围使用 `RangeControl`，面板内是独立的开始日期、结束日期 `DatePickerField`，支持月份、年份下拉；右侧月历使用全局 `Calendar` 并通过官方 `DayButton` 扩展盈亏内容。
- 右侧月历日期格 36px，不使用外边框或日期卡片背景色，日期与底部盈亏色条水平居中；非交易日不灰化，当天使用默认浅灰背景，盈亏金额只放在 Tooltip，第七列不得溢出。
- 日期范围必须保证开始日期不晚于结束日期；快捷区包含全量日期、今日、本周、上周、近30日、年初至今，最近周期包含近12个月和近6个季度。无日期条件必须显示“全部日期”，且请求不携带日期字段。
- 账户范围使用全局 `AccountScopeMenu`；品种代码统一使用共享 `SymbolBadge`（底层 `Badge variant="secondary"`）。
- 笔记、回放等附加操作使用全局次要 Button，不使用 Badge 伪装按钮。
- 列显示按钮右侧提供全局交易记录展开/收起图标按钮，仅日视图和周视图显示；单张卡片仍可独立展开。
- 右侧月历必须与左侧主面板顶边对齐；吸顶后与筛选工具栏保持 12px 间距，月份导航控件不得被遮挡。
- 表格排序使用标准 `ArrowUpDown / ArrowUp / ArrowDown` 图标，并保持全局 Button 视觉。
- 日视图和周视图内的交易明细区域固定约 10 行高度，超过后在表格内部滚动且表头吸顶；周视图日期弹窗必须直接复用共享 `TradeDayDetailDialog`。
- 日视图默认展示最新 8 个日期分组，周视图默认展示最新 6 个周分组；仅第一日/第一周默认展开交易表格，其余分组默认收起，可通过全局按钮统一展开或逐组切换。
- 全部视图使用与交易总览相同的 sticky 工具栏；表格直接铺满 Card，不增加内层边框和外围 padding，最大高度使用视口相对值 `50dvh`；内容不足时自然收缩，超过时表头始终固定在表格滚动容器顶部。

### 11.4 交易账户

- 指标卡：移动端 1 列，`md` 3 列。
- 账户表在窄屏横向滚动，操作区不压缩成不可读图标。
- 新增账户弹窗：移动端接近全屏，桌面 `max-w-3xl`。
- 平台桌面一行 5 个，移动端 2 列；币种桌面一行 6 个，移动端 3 列。

## 12. 可访问性与交互

- 所有可点击控件显示手型光标，禁用状态不显示手型。
- 键盘可聚焦，焦点环必须可见。
- 图标按钮必须有 `aria-label` 或 `title`。
- 选中、展开、禁用和加载状态必须有 ARIA 或原生语义。
- 颜色不能作为唯一信息，金额同时使用正负号和颜色。

## 13. 开发与验收清单

新增或修改页面必须检查：

- 是否使用 `src/components/ui` 的全局组件。
- 是否使用正确的 Button / Badge 状态变体。
- 按钮悬停是否加深，而不是变浅。
- 小按钮是否确实更小。
- 是否误用了原生 `<button>`。
- 是否通过 Keyboard、Tab、Enter 和 Escape 操作。
- 是否有加载、空、错误、禁用和 N/A 状态。
- 是否在 390px、768px、1024px、1440px 验证。
- 是否出现页面级横向溢出或文字重叠。
- 是否在 `/dashboard/design-system` 中补齐新的全局组件示例。
