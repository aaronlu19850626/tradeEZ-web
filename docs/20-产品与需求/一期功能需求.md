## 1. 产品目标与范围

### 1.1 产品目标

帮助交易者回答以下问题：

1. 我实际做了哪些交易，数据是否完整？
2. 我为什么做这笔交易，它属于什么模型？
3. 我是否遵守了交易前约定的规则？
4. 我的盈亏与哪些模型、时段、行为存在关联？
5. 我反复出现的问题是什么？
6. 下一次交易时，我具体需要改变哪个行为？
7. 我是否形成稳定的盘前准备和盘后总结习惯？

### 1.2 核心闭环

盘前计划 → 场景与规则确认 → 交易意图记录 → 实际交易同步 → 单笔复盘 → 每日总结 → 周期分析 → 改进行动 → 下一次盘前计划。

系统应同时支持两种入口：

- 从历史交易开始：同步历史数据，补充分类与复盘，再逐步使用每日计划。
- 从今天开始：先建立当天计划，记录意图，交易结束后关联真实数据。

不得要求历史用户先补齐全部旧交易复盘，才能使用当天流程。

### 1.3 第一阶段包含

| 能力 | 范围 |
|---|---|
| 账号同步基础 | 添加账号、密钥、同步日期、日志、EA 参数只读、重同步、账号删除 |
| 交易管理 | 原始订单查询、完整交易查看、关联检查、数据完整性提示 |
| 标签 | 分组、自定义、停用、合并、批量应用、统计关联 |
| 交易规则 | Setup、简版 Playbook、规则清单、版本、人工评估及可验证的自动评估 |
| 单笔复盘 | 笔记、截图、情绪、规则评估、复盘结论、改进行动 |
| 交易分析 | 整体表现、模型、时段、风险、错误、执行及标签分析 |
| 每日流程 | 盘前计划、交易意图、当日记录、盘后总结、不交易日 |
| 持续改进 | 轻量周复盘、行动跟进、过程习惯统计、站内提醒 |

### 1.4 第一阶段不包含

- 自动下单、复制交易、Web 强制阻止 EA 开仓。
- 基于实时浮亏的强制风控。
- 完整行情回放、自动回测、自动形态识别。
- 完整订单流、DOM、实时信号、方向预测。
- 课程平台、公开案例社区、复杂技能评分。
- 依赖 AI 才能完成的复盘流程；AI 可作为后续增强。
- 强制接入外部经济日历；首版允许用户手工记录事件。
- MT4、CSV 等多渠道导入的完整产品化；本版以现有 EA 同步为主要入口。

### 1.5 成功标准

首版首先保证：数据可核对、流程可完成、结论有依据、改进可跟进。不能把收益提高作为上线验收条件，也不能通过鼓励增加交易次数提高产品活跃度。

## 2. 使用者、权限与基础原则

### 2.1 使用者

首版面向管理一个或多个账户的个人交易者。功能只对当前使用者有权访问的数据生效。多角色团队协作、导师批改和公开分享不在首版范围。

### 2.2 权限要求

- 用户只能查看和操作自己的账号、交易、规则、笔记及附件。
- 多账号统计只能包含用户已选且有权访问的账号。
- 导出、附件预览、通过链接访问详情，也须遵守相同的数据访问限制。
- 删除和批量修改前，必须展示当前实际影响范围。
- 系统不得因为用户打开另一条交易链接，就沿用上一条交易的编辑权限。

### 2.3 核心原则

1. 交易事实与主观复盘分离。
2. 盈亏结果与执行质量分离。
3. 交易前记录与交易后补录分离。
4. 缺失信息不使用零或“通过”代替。
5. 用户可保存不完整草稿，不强迫编造答案。
6. 已确认的计划、规则、复盘发生修改时，保留可理解的版本记录。
7. 所有分析能够回到组成结论的交易集合。
8. 休息、等待和按计划放弃机会均是有效行为。

## 3. 业务对象与交易统计单位

### 3.1 原始订单、成交、持仓与完整交易

| 对象 | 业务含义 | 用途 |
|---|---|---|
| 原始订单 | 交易平台上的下单及相关订单记录 | 对账及查看平台事实 |
| 成交 | 实际发生的买卖执行记录 | 数量、价格、费用及盈亏计算依据 |
| 持仓 | 交易平台表达的头寸及关联标识 | 辅助归并交易过程 |
| 完整交易 Trade | 从建立某次交易敞口到该次敞口完全结束的一次过程 | 复盘、胜率、模型及执行分析 |

用户口中的“订单复盘”，默认针对完整交易，而非对每条成交分别重复评分。原始订单及成交始终可展开查看。

### 3.2 归并规则

- 同一交易过程中的部分平仓，仍归属同一完整交易。
- 有明确关联依据的加仓，纳入同一交易过程；保留每次成交。
- 对冲账户中独立持仓，不因品种和方向相同而自动合并。
- 净持仓账户需要正确区分减仓、完全退出及反向建立的新交易。
- 跨账号交易不得合并。
- 同品种、同方向、时间相近只能作为提示，不能作为唯一归并依据。
- 无法可靠归并的记录标为“待核对”，并说明缺少的依据。
- 首版支持查看关联明细与报告归并问题；任意拖拽合并、跨持仓重组策略交易不作为必需能力。

原始数据层面的持仓归并与主观“一个交易想法”不是同一概念。一个想法执行为多个独立持仓时，首版保留多个完整交易，通过同一场景关联查看，不私自合成一笔。交易数限制必须说明按完整交易首次建立计算，不能用平仓成交条数代替。

### 3.3 交易生命周期

| 状态 | 说明 | 分析行为 |
|---|---|---|
| 未结束 | 有可靠数据表明交易仍有敞口 | 可写过程笔记，不纳入最终胜率 |
| 已结束 | 交易过程已完整退出 | 纳入完整交易统计及正式复盘 |
| 待核对 | 缺少开仓、关联异常、数量不一致等 | 默认排除依赖完整交易的指标 |
| 数据待恢复 | 重同步期间交易事实暂不可用 | 保留复盘资料，暂停相关统计 |

如果同步能力只能提供已平仓记录，不得把“暂未看到更多记录”解释为可靠的实时持仓状态。

### 3.4 模型、规则与标签

- Setup：机会分类，例如趋势回踩。
- Playbook：执行该类机会的一套具体条件及管理要求。
- 标签：描述特征、情绪、错误或其他观察。
- 一笔交易最多关联一个主要 Setup 和一个主要 Playbook 版本。
- Playbook 可关联一个主要 Setup；同一 Setup 可以存在不同 Playbook。
- 次要观察通过标签表达，避免一笔交易在多个主模型中重复计数。

## 4. 全局时间、状态与数据来源规则

### 4.1 时间规则

- 每个工作空间应能设置展示时区和交易日分界时间，首次使用时确认。
- 默认建议北京时间及 00:00 日切，允许按交易习惯修改。
- 账号详情保留交易服务器时间口径说明，避免与展示时区混淆。
- 同步起点按明确的时间口径解释，选择日期后须显示实际起始时刻及所用时区。
- 时间筛选明确包含起点、不包含下一周期起点，避免午夜记录重复统计。
- 伦敦、纽约等时段使用带夏令时规则的时区定义，重叠时段通过明确优先规则或独立分组处理；主时段统计中一笔交易只计入一个组。
- 时段默认按首次开仓时间归属，界面明确说明。
- 交易日设置变更会影响日期分组，应提示影响；已有计划和日记保留创建时的交易日定义，不静默搬移。
- 跨不同交易日定义的历史习惯统计须分段说明，不能直接混成一个无解释的连续指标。

### 4.2 数据来源标识

以下来源应可辨识：EA 同步、系统计算、规则判断、用户手填、事后补录。

自动字段发生人工纠正时，应保留原始值、纠正值、原因和时间；原始成交事实不能直接通过笔记编辑覆盖。

### 4.3 完整性提示

使用明确的提示，例如：

- “尚未收到首次同步。”
- “缺少初始风险，本交易不参与 R 指标计算。”
- “缺少入场成交，暂不参与完整交易胜率。”
- “无历史价格路径，MAE/MFE 暂不可用。”
- “已完成复盘，但 2 项规则无法判断。”
- “该统计包含 38 笔交易，其中 26 笔有有效 R。”

### 4.4 状态独立

交易生命周期、同步状态、复盘状态、规则结论互相独立。例如，交易可以是“已结束 + 复盘已完成 + 证据不足”，不能用一个“已完成”覆盖所有含义。

## 5. 导航及核心业务流程

### 5.1 功能入口

| 入口 | 内容 |
|---|---|
| 今日交易 | 盘前准备、场景、当日交易、待办、盘后总结 |
| 交易日志 | 完整交易列表、详情、单笔复盘 |
| 交易分析 | 统计、筛选、分组比较、下钻 |
| 交易日历 | 各日已实现盈亏、计划和复盘状态 |
| 交易规则 | Setup、Playbook、检查清单与版本 |
| 标签管理 | 标签分组、定义、使用与合并 |
| 账号管理 | 同步账号、只读参数、同步记录、重同步及删除 |
| 设置 | 时区、交易日、交易安排、提醒偏好 |

以上定义功能关系，不规定具体菜单布局或视觉样式。

### 5.2 新用户流程

1. 设置时区和交易日。
2. 添加同步账号并确认历史同步起点。
3. 将密钥配置到 EA，等待首次同步。
4. 检查账号、品种和交易数量是否合理。
5. 创建一个模型及简版规则，或从模板复制后修改。
6. 完成一笔历史交易复盘，了解分类与规则评价。
7. 创建下一个交易日的计划。

模板中的风险数字不能直接成为已生效个人限制；用户需自行填写并确认。

### 5.3 日常流程

确认盘前计划 → 记录候选场景或意图 → 进行交易或选择不交易 → 同步事实 → 核对关联 → 完成单笔复盘 → 每日总结 → 指定下次行动。

### 5.4 历史分析流程

筛选时间和账号 → 查看整体表现 → 按模型、标签或执行情况细分 → 查看样本数量与缺失情况 → 下钻交易 → 核对笔记和证据 → 形成待验证的改进行动。

## 6. 同步账号管理

### ACC-01 添加账号

必填：交易账号、服务器名、同步开始日期。选填：显示名称、备注。

业务规则：

1. 账号与服务器组合用于识别交易账户；相同范围内不能重复添加同一组合。
2. 创建成功后生成与该账号绑定的密钥，不依靠公开的账号和服务器名直接推算密钥。
3. 明确说明同步起点按平仓时间判断；开始日期当天包含在范围内。
4. 为还原跨越起点的完整交易，允许接收范围外的关联开仓资料，并标为重建辅助资料；不得把这些资料当作范围内新增平仓交易重复统计。
5. 若无法获得关联开仓资料，保留可用平仓事实并提示完整交易缺失。
6. 不接受未来同步起点；历史最早可同步范围受可取得的数据限制，无法取回时明确提示。
7. 成功后展示接入信息、复制操作和“待首次同步”状态。

### ACC-02 账号列表与详情

显示名称、账号、服务器、币种、同步起点、同步状态、已同步记录数、完整交易数、待核对数、最新平仓时间、最近同步成功时间、最近联系时间。

“最新平仓时间”指已保存数据中的最大平仓时间；“最近同步成功时间”可因无新增数据的成功同步而更新。

账号详情包含基本信息、交易记录、EA 配置、同步日志。关键状态不可只用颜色表达。

### ACC-03 EA 配置只读

- 展示 EA 名称、版本、实例标识、配置参数及快照时间。
- 参数按含义分组，名称与原始参数标识均可查询。
- 密钥等敏感配置不完整显示。
- 长时间未上报时显示“配置可能已过期”，不暗示实时生效。
- 多实例分别显示配置，不能由最后上报的实例覆盖其他实例身份。
- 首版不支持在 Web 直接修改 EA 参数。

### ACC-04 密钥重新生成

确认信息：旧密钥立即失效，EA 需要更新配置。确认后仅改变接入凭据，不删除订单、不修改同步起点、不重置复盘。

新密钥仅在生成时完整展示；关闭后无法再次完整查看，需要时重新生成。

### ACC-05 停用与恢复

停用后拒绝新的同步写入，历史数据仍可查看和分析。恢复后允许继续同步，不自动清空历史记录。页面说明停用账号不等于停止交易平台中的交易行为。

### ACC-06 清空订单并重新同步

流程：显示影响范围 → 强制重新确认同步开始日期 → 选择复盘资料处理方式 → 确认 → 清空交易事实并重置进度 → 等待新同步 → 重新关联资料。

默认保留人工标签、笔记、截图和复盘作为待恢复资料。若选择一起删除，必须展示单独的明确说明。

清空过程中旧同步请求不能重新写回；只有新一轮有效同步数据可进入当前数据集。账号状态明确展示“重新同步中”，分析不得将暂时空数据解释为真实零业绩。

### ACC-07 删除账号

展示账号、交易数量、复盘数量和附件影响范围，要求输入交易账号确认。

删除后物理清除账号及其专属交易、密钥关联、同步日志、参数快照、笔记、截图、复盘和统计派生结果。旧 EA 请求被拒绝，不能自动重建账号。

共享标签定义、共享模型和规则保留；共享每日计划按照第 20 节处理。备份中的保留与清理周期需在部署运营规则中另行明确，不将业务库删除宣传为所有备份立即清除。

## 7. 同步日志与原始订单管理

### SYN-01 日志生成

- 有新记录写入时，必须生成日志，包含总接收条数、实际新增条数及相关订单号。
- 只有已有数据更新时，生成更新日志。
- 无变化且成功时，更新联系时间，可不生成业务列表日志。
- 失败时生成失败日志，展示可理解的原因。
- 首次历史同步和重新同步按批次记录，并能辨别所属同步轮次。

### SYN-02 日志内容

账号、服务器、开始与结束时间、结果、接收数量、新增数量、更新数量、重复数量、失败数量、处理耗时、订单号及成交标识。

日志详情支持大量订单号分页查看和精确搜索。成功数量必须与真实保存结果一致；失败重试不增加虚假的新增数量。

### ORD-01 原始订单查询

支持账号、服务器、品种、方向、开平仓时间、订单号、成交编号、持仓编号、Magic Number、备注及处理状态筛选。

默认按平仓时间倒序；相同时间使用稳定的次级顺序。可排序的业务列均支持升序和降序，排序作用于全部筛选结果。

### ORD-02 全字段查看

显示同步实际取得的所有业务字段，包括关联标识、价格、数量、时间、方向、费用、盈亏、币种及同步时间。列表可自定义列；详情展示完整字段及关联完整交易。

没有取得的字段显示缺失。止损、止盈需说明是初始值、最终值还是某次快照，不混为一个无时间含义的字段。

## 8. 完整交易管理

### TRD-01 列表

默认列：账号、品种、方向、首次开仓时间、最终平仓时间、成交量、净盈亏、R、主模型、主规则、复盘状态、执行结论、主要错误。

可选列：开平仓均价、费用、持仓时长、时段、环境、标签、评分、证据完整度、计划归属、同步状态。

默认按最终平仓时间倒序。未结束及待核对交易提供单独筛选，时间缺失的排序位置明确。

### TRD-02 筛选

支持账号、品种、方向、开仓／平仓日期、模型、规则版本、时段、结果、复盘状态、规则结论、分数范围、标签、主要错误、计划内外、资料完整性。

- 多个不同条件之间默认“并且”。
- 多选标签可切换“任意命中”与“全部命中”。
- 条件以可见形式展示，支持单项移除和全部清除。
- 从分析下钻时保留分析条件，返回后恢复原筛选与位置。

### TRD-03 详情

包含交易摘要、成交时间线、模型和标签、关联计划、规则评估、笔记、截图、复盘结论及修改记录。

允许快速切换上一笔／下一笔，但编辑未保存时必须明确保存状态。切换顺序遵循当前列表筛选及排序。

### TRD-04 批量操作

首版支持批量添加／移除普通标签及批量分类模型。变更模型可能影响规则关联时须预览冲突，不自动覆盖已有已完成评价。

不能通过批量按钮直接将所有交易标成已完成复盘或全部规则通过。选择当前页与选择全部筛选结果应明确区分。

## 9. 标签定义与应用

### TAG-01 标签分类

| 分类 | 选择规则 | 示例 |
|---|---|---|
| 市场结构 | 同一维度单选 | 上涨、下跌、震荡、无法判断 |
| 波动环境 | 单选 | 高波动、常态、低波动、未知 |
| 事件环境 | 多选 | 数据发布、政策事件 |
| 关键位置 | 多选 | 昨日高点、区间下沿 |
| 入场确认 | 多选 | 回踩、结构突破、收盘确认 |
| 执行错误 | 多选，可选主要错误 | 追单、提前入场、超仓 |
| 正向行为 | 多选 | 等待确认、按计划退出 |
| 情绪 | 按交易阶段记录 | 平静、焦虑、疲劳 |
| 自定义 | 分组指定单选／多选 | 用户自定义特征 |

模型、方向、账号、盈亏不作为重复的自由标签录入。

### TAG-02 定义

标签具有名称、所属分组、说明、使用示例、颜色、顺序、启用状态。名称在同一分组内不得重复；只改颜色不改变历史含义。

错误标签需说明判定条件。内置标签可复制调整；不能将一种旧含义直接改成另一种含义而不提示历史影响。

### TAG-03 编辑、停用、删除与合并

- 改名保留关联，显示对历史展示的影响。
- 含义改变应创建新标签，或执行有说明的迁移。
- 已使用标签默认停用；停用后历史可查，不能继续新选。
- 未使用标签可删除。
- 合并前展示来源、目标、使用数和冲突；多次命中同一目标只保留一次关联。
- 单选分组迁移产生多值冲突时由用户处理，不任意保留一个值。
- 标签合并后相关统计更新；既有周期复盘中的文字结论不自动改写，显示样本可能变化。

### TAG-04 应用

标签可在交易详情和复盘流程中编辑，也支持批量操作。自动建议必须标明来源，用户可确认、拒绝或修改。首版不依赖自动识别。

### TAG-05 标签分析

支持查看使用次数、涉及交易、净盈亏及有效 R。多标签集合可能重叠，提示“分组结果不可直接相加”。主要错误分组与全部错误分组单独提供。

## 10. 交易模型与执行规则

### PB-01 模型管理

创建名称、说明、适用品种、方向范围和示例。支持启用、停用及查看相关交易。内置趋势回踩、流动性扫单仅作为可修改模板，不宣称有已验证优势。

### PB-02 Playbook 内容

包括市场环境要求、关键位置、触发条件、失效条件、风险约束、持仓管理、退出原则及禁止事项。

规则应回答一个明确问题，避免把多个条件压缩成一个无法定位失败原因的句子。

### PB-03 规则属性

每条规则设置名称、解释、分组、检查时点、回答形式、评估方式、是否关键、是否允许不适用及权重。

回答形式包括是非、数值、选项、文本。评估方式包括人工、确定性自动评估；AI 辅助不属于首版必需。

文本记录默认不评分。数值规则必须定义单位、比较条件和阈值。百分比必须注明相对于哪个时点的余额或权益；缺少对应数据时无法自动判断。

### PB-04 关键规则

关键规则用于判断规则整体是否遵守。例如用户定义的风险上限。关键规则失败必须独立显示，不因总分较高而被隐藏。

关键规则默认不允许“不适用”；确有条件适用场景时，在规则定义中预先说明。评价人不能为了提高得分临时将其排除。

### PB-05 发布与版本

草稿可自由修改；发布后形成可引用版本。再次修改生成新版本。历史计划与交易保留引用版本，不自动追随最新版。

用户可主动重评历史交易，但必须保留原评估与重评结果，标记“按新规则回看”。历史当时合规统计仍使用当时版本。

### PB-06 停用

停用后不能创建新的关联，历史引用与统计保留。删除未被使用的草稿不影响历史。已经使用的规则不能直接物理删除而使历史评价失去解释。

## 11. 单笔交易复盘

### REV-01 复盘内容

| 部分 | 内容 | 来源及要求 |
|---|---|---|
| 交易事实 | 时间、数量、成交、费用、盈亏 | 同步，只读 |
| 交易分类 | 模型、环境、位置、时段 | 自动值或用户确认 |
| 计划关联 | 每日计划、场景、意图 | 显示关联及原始创建时间 |
| 入场依据 | 当时理由、确认、失效条件 | 已有记录继承，补写标记 |
| 过程 | 加减仓、止损调整、退出理由 | 事实与用户解释并列 |
| 规则评价 | 通过、失败、未知、不适用及证据 | 按绑定版本 |
| 心理 | 入场前后情绪、可选强度及说明 | 主观自评 |
| 结论 | 保留行为、主要问题、下次行动 | 用户填写 |

### REV-02 标准流程

1. 核对成交及交易归并。
2. 选择或确认模型和 Playbook。
3. 关联盘前场景；没有计划时如实标记。
4. 补充必要依据及过程说明。
5. 完成规则逐项评价。
6. 添加错误或正向行为标签。
7. 写明一项结论及后续行动，或明确无需新增行动。
8. 查看完成情况并提交复盘。

### REV-03 最低完成条件

- 用户已确认交易事实，或明确记录无法核对的原因。
- 已完成模型分类；允许明确选择“暂未分类”并说明。
- 关联了规则时，每条适用规则均已有回答，允许“无法判断”但必须说明原因。
- 未关联规则时可以完成复盘，状态显示“未评分”，不计入已评分交易数量。
- 必须有简短复盘结论。
- 必须有下次行动，或明确选择“继续执行现有规则，无新增行动”。
- 截图不是所有交易的强制条件；规则要求图形证据时，缺图可能导致无法判断。

### REV-04 状态

待复盘 → 草稿 → 已完成。已完成后可重新编辑并再次提交，保留版本与修改时间。

原始数据、交易归并或费用发生实质变化时，状态变为“待重新核对”，保留原结论，展示具体变化；用户确认后恢复完成状态。

仅新增一个普通备注、修复错别字，不应无理由撤销完成状态。

### REV-05 笔记

支持交易前、交易中、交易后三类笔记，分别记录实际创建时间。用户填写的“事件发生时间”不能替代系统记录时间。

自动保存草稿，显示保存中、已保存或失败。提交完成是显式操作，不因离开页面自动视为完成。

### REV-06 截图

支持盘前、入场、退出、复盘分类，添加标题、说明和所示周期。支持排序、预览、替换和删除。

上传失败可重试；未成功上传的文件不能显示为已保存。图片中的交易信息只是证据材料，不能未经确认直接覆盖交易事实。

第一阶段不要求内置画线工具，不依赖 AI 读图识别。

### REV-07 情绪与错误

入场前情绪和退出后情绪分别记录。事后回忆需标记，不伪装为当时记录。

错误可以多选，主要错误最多一个；允许没有错误。不能因亏损自动贴“错误”标签，也不能因盈利自动移除违规。

## 12. 规则评价与执行评分

### SCR-01 状态定义

| 状态 | 业务含义 | 处理 |
|---|---|---|
| 通过 PASS | 有依据满足规则 | 计为通过 |
| 未通过 FAIL | 有依据违反规则 | 计为失败 |
| 无法判断 UNKNOWN | 缺少证据或事实不明确 | 不冒充通过或失败 |
| 不适用 N/A | 预先定义的适用条件不成立 | 说明理由后从适用规则中排除 |

### SCR-02 首版评分规则

为减少历史草案中多层权重的歧义，建议首版采用规则权重直接计算。规则分组只用于展示，不再叠加类别权重。

- 证据覆盖率 = 已判定为通过或失败的规则权重 ÷ 全部适用评分规则权重。
- 覆盖率不足 100% 时，不产生正式总分，展示已通过／失败／未知数量及覆盖率。
- 覆盖率达到 100% 时：执行分 = 100 × 通过规则权重 ÷ 全部适用评分规则权重。
- 没有适用评分规则时显示“不适用／未评分”，不显示 0 分或 100 分。
- 分数展示一位小数；筛选使用实际计算值，边界规则明确。
- 规则权重为正值，由规则版本固定；文本型非评分项目不进入分母。

例如：适用权重 10，已确认通过 6、失败 2、未知 2，则显示覆盖率 80%，不显示正式执行分；未知项补齐后才计算正式分数。

### SCR-03 合规结论

- 没有关联规则，或全部规则均不适用：显示“未评价／无适用规则”，不能利用空集合认定全部遵守。
- 无失败且无未知：已评估适用规则全部遵守。
- 至少一个失败：存在违规；若仍有未知，同时显示证据不完整。
- 无失败但存在未知：证据不足，暂不能认定全部遵守。
- 关键规则失败：额外突出显示“关键规则违规”。

首版不强制 A+／A／B 等等级，也不使用未经确定的 80、85 分作为“优秀”阈值。

### SCR-04 结果对照

以“遵守规则／存在违规／证据不足”与“盈利／亏损／持平”交叉展示。使用中性事实表达，例如“遵守规则但亏损”“存在违规但盈利”，不将单笔利润解释为能力证明。

## 13. 整体交易分析

### ANA-01 公共筛选与口径

账号、日期范围、品种、方向、模型、规则版本、时段、标签、复盘状态和规则结论应可组合使用。

默认完整交易绩效按最终平仓时间筛选；切换开仓时间分析时明确说明。每日已实现盈亏按实际实现时间计算，不能直接与完整交易归属日金额混用。

默认分析所有有效已结束交易，不只选择已复盘交易。执行分析使用可评价子集，同时显示未复盘、未评分或证据不足数量。

### ANA-02 指标定义

| 指标 | 业务口径 |
|---|---|
| 完整交易数 | 当前筛选下有效已结束 Trade 数，不是成交条数 |
| 净盈亏 | 所选交易实际盈亏与归属费用的净额；费用已含则不得再次扣减 |
| 胜率 | 净盈利交易数 ÷ 有效已结束交易数；持平包含在分母并单独列出 |
| 平均盈利 | 盈利交易净额总和 ÷ 盈利交易数 |
| 平均亏损 | 亏损交易净额绝对值总和 ÷ 亏损交易数 |
| 盈利因子 | 盈利交易净额总和 ÷ 亏损交易净额绝对值总和 |
| 已实现 R | 完整交易净盈亏 ÷ 有效初始风险金额 |
| 净 R | 有效 R 交易的 R 之和，表述为“累计 R”，不等于账户收益率 |
| 平均 R／样本期望 R | 同一有效 R 样本的 R 总和 ÷ 样本数，两种名称不得给出不一致数值 |
| 金额期望 | 同币种有效交易净额 ÷ 有效交易数 |
| 连续亏损 | 当前定义序列中连续净亏损交易数，持平中断；可另行扩展其他口径 |
| 持仓时长 | 首次开仓至最终退出的时间 |

零亏损分母下的盈利因子显示“无亏损样本，暂不定义”，不展示误导性的固定大数。无盈利或无亏损时对应平均值显示不可用。持平按来源精度判断，不随页面四舍五入改变分类。

### ANA-03 风险与数据限制

充值、提现、内部转账及无法归属交易的账户调整不计入交易胜率和交易净盈亏，应与交易活动区分。无法分配的费用单独显示“未分配费用”，不能静默丢弃或任意分摊到某笔交易。

每日已实现账目按实际入账／实现时间计入交易收益及费用；完整交易净额汇集归属于该交易的全生命周期收益和费用。因此二者在短时间筛选内可能不同，需提供对账解释。缺少费用发生时间时不能伪造每日分配，应标明仅可用于整笔统计或时间归属待确认。

跨越同步起点的交易，若已取得完整生命周期，可用于整笔交易分析，并提示其含起点之前的关联活动；每日账目只展示所选时间内真实发生的金额。资料不完整时不得将可见的部分盈亏标成完整交易的最终净额。

初始风险必须来源可追溯。不得使用最后一次止损或最终盈亏倒推原始风险。

简单无加仓交易可在输入充分时计算风险。存在加仓或复杂风险变化时，应使用明确的整个交易风险基准；未定义或无法确认时，不自动生成 R。可由用户补录并标记来源与依据。

缺少风险或权益数据的交易仍可参加适用的金额统计，但不参与 R 或风险百分比统计。

首版不自动汇兑：不同币种分开展示金额。跨账号累计 R 仅表示交易结果的 R 汇总，不代表资金加权组合收益。

### ANA-04 总览

展示关键指标、累计已实现净盈亏、每日已实现盈亏、交易结果分布及有效 R 分布。

没有完整浮盈浮亏轨迹时，不把曲线命名为实时权益曲线。对应回撤称为“已实现盈亏曲线回撤”，并注明不含浮动回撤。

默认回撤在选定范围内，以范围开始处累计净盈亏为零起点计算局部峰谷差。与账户全历史峰值相比的回撤属于不同指标，不混用。

### ANA-05 模型与规则分析

各组显示交易数、净盈亏、有效 R 数、平均 R、胜率、执行评价数量及复盘完成情况。

支持按规则版本查看，避免新版与旧版条件混杂。可以比较同一规则通过与失败的交易，但需显示其他筛选条件和样本差异，不声称比较证明因果。

### ANA-06 时间分析

支持主交易时段、星期、开仓小时区间和持仓时长区间。每个区间的边界可查，记录只归入一个对应组。

跨日交易按首次开仓时间归属开仓时段，按实际费用与盈亏发生时刻归属每日已实现账目。

### ANA-07 错误分析

显示错误次数、涉及交易数、相关交易净盈亏、有效平均 R、近阶段变化及具体交易。

名称使用“带该错误的交易盈亏”，不称“该错误造成的损失”。多个错误标签对应的盈亏存在重叠，不能作为独立成本相加。

可切换主要错误分组，以获得每笔最多归属一组的视图；未指定主要错误须保留独立组。

### ANA-08 执行与计划分析

比较遵守规则、存在违规、证据不足、未评价四类交易；显示各组样本量与金额、R。

计划关联拆分为：交易前已有计划且关联场景、盘中修订后才适用的场景、交易后补关联、没有适用计划、无法判断。

“符合计划”还需核对具体条件，不能仅凭存在关联就认定符合。风险限制、模型和时段只是可验证的一部分。

### ANA-09 标签与多维比较

允许按一个主维度分组，再叠加其他筛选条件。首版不要求任意复杂交叉透视。

稀少样本仍可展示事实，但不得自动标为“最优策略”。不设未经验证的盈利结论阈值。

### ANA-10 下钻与导出

点击指标或分组可打开组成该结果的交易集合，保留筛选、币种、时间口径及样本排除说明。

支持导出当前页或全部筛选结果，两者清楚区分。导出记录包含范围、时间口径、币种和生成时间。标签多值、缺失项与补录来源需保留含义。

## 14. 每日交易工作台

### DAY-01 当日信息

显示当前交易日、所用时区、适用账号、盘前计划状态、当日意图、已同步交易、待复盘事项、盘后总结状态及当前改进行动。

同一交易日以一份主计划和一份主日记为基础，场景按品种及账号范围区分，风险限制按账号区分。

### DAY-02 每日流程状态

未准备 → 计划草稿 → 计划已确认 → 当日执行中 → 待总结 → 已总结。

“不交易”是当日决策，不等同流程失败。可以确认不交易计划并完成简短总结。

系统不能仅因时钟过了某个时间就自动认定交易者已结束交易；可提示进入总结，结束决定由用户或已配置的明确规则表达。

### DAY-03 当日统计拆分

分别显示当日新开完整交易、当日结束完整交易、当日成交记录、当日已实现盈亏。部分平仓和跨日交易不混为同一数量。

如果开仓资料不完整，相关计数显示“已知数量／资料不完整”，不假装覆盖全部当日活动。

### DAY-04 日历

每天显示已实现盈亏、计划状态、总结状态、待复盘数量及不交易标记。无数据与真实零盈亏不同显示。

点击某日查看当时计划、相关成交、完整交易及总结。今天查看历史日期不改变历史确认时间。

## 15. 盘前分析与计划

### PRE-01 计划字段

| 内容 | 要求 |
|---|---|
| 日期、时区、账号 | 必填，有默认值但需可见 |
| 今日是否准备交易 | 必填：准备交易／仅观察／休息 |
| 自身状态 | 精力、情绪、可用时间，可简要填写 |
| 市场判断 | 结构、重要周期、依据；允许明确不确定 |
| 关键位置 | 类型、价格或区域、说明；可附截图 |
| 事件安排 | 手动记录事件、时间、回避区间；允许明确未核对 |
| 允许模型 | 选择模型或明确暂不允许开仓 |
| 交易场景 | 条件、确认、失效、行动、放弃条件 |
| 风险边界 | 按账号设置交易次数、风险或停止条件；未配置明确显示 |
| 今日改进重点 | 关联上一日／周行动，或明确无新增重点 |

### PRE-02 场景定义

每个场景包含名称、品种、方向倾向、关联模型和规则版本、关键区域、入场确认、逻辑失效、计划退出原则、适用时段、账号范围。

示例表达：“如果价格进入关注区域，随后出现已定义确认，且风险要求满足，则考虑执行；若失效条件出现，放弃该场景。”示例不预填真实下单建议。

允许同一天多个候选场景；互斥场景可以同时准备，但不能把所有方向都泛泛标为计划内。

### PRE-03 确认条件

准备交易时，至少明确允许模型、一个可执行场景或明确等待条件、风险设置状态和停止条件状态。未配置风险限制可确认计划，但突出显示“未设定”，不视为已完成风险检查。

选择仅观察或休息时，不强制填写入场价格和交易场景。

首次确认保存时间和版本。计划在当天首笔交易之后才确认时，标记“晚于首次交易”；不计入该日按时盘前准备。

### PRE-04 复制与模板

支持复制昨日结构、规则及关注项为草稿。日期、价格、事件、市场判断和风险信息需重新检查；复制不会直接产生今日已确认计划。

过期场景不自动延续为当日有效条件。

### PRE-05 盘中修订

市场变化后允许修订，填写简短原因并产生新版本。新版本只用于其生效后发生的决策评价，不回溯改变已有交易的计划归属。

历史补建计划标为补录，不能修正原先缺少盘前准备的事实。

### PRE-06 不交易计划

支持原因：没有符合模型的机会、事件风险、状态不佳、时间不足、计划休息、自定义。

若之后发生实际交易，保留原不交易决策，并要求复盘说明变更原因；不得删除原标记使之看起来一直允许交易。

## 16. 盘中记录与交易意图

### INT-01 意图创建

在尚未同步到真实交易时，记录账号、品种、方向、场景、模型、预期入场依据、风险计划及可选截图。

分为“观察候选”和“准备执行”。不要求所有观察都形成交易。

### INT-02 意图状态

观察中 → 准备执行 → 已执行待关联 → 已关联；也可转为主动放弃、条件失效或到期未执行。

记录每次状态变化时间和简短原因。放弃交易可以关联正向行为，不能算作一笔盈利或亏损交易。

### INT-03 真实交易关联

同步后可根据账号、品种、方向、时间展示候选，用户确认关联。证据充分且唯一的匹配可自动关联，但须标记来源并允许纠正。

首版默认一个执行意图关联一个完整交易，一个场景可产生多个独立意图。连续再次入场需建立新的意图，避免一次计划无限覆盖后续交易。

关联动作发生在交易后，不必然意味着意图是事后补写；按意图实际创建时间判断，并保留关联时间。

### INT-04 风险与纪律提示

显示已知交易次数、已实现盈亏、已知连续亏损及用户设置的限制。资料不完整时注明不能完整判断。

达到可验证停止条件时，提示停止计划内交易并记录决策；Web 本身不保证阻止交易平台继续下单。

缺少实时持仓、权益和行情时，不展示“实时账户风险安全”之类结论。

## 17. 每日盘后复盘

### POST-01 自动汇总

汇总本交易日已实现盈亏、开仓／结束数量、成交数、已完成及待完成复盘数量、计划关联情况、已确认违规、主要错误和有效风险信息。

展示最新同步时间和完整性提示，允许在数据未齐时先写总结草稿。

### POST-02 必答内容

1. 今天的计划与实际市场有什么主要差异？允许“无明显差异”。
2. 是否按照计划和停止条件执行？有偏离时说明。
3. 今天应保留的一个行为是什么？允许没有明确发现。
4. 今天最需要改进的问题是什么？允许没有新增问题。
5. 下一个交易日采取什么具体行动？可继续既有行动。

实际交易较少或无交易时提供简版，不要求无意义长文。

### POST-03 完成条件

用户确认已查看当日汇总，必答问题有回答，改进行动已明确或说明继续现有规则，即可提交每日总结。

每日总结与单笔复盘独立：允许总结已完成、仍有 2 笔待复盘；工作台持续提示，不因提交总结自动完成单笔复盘。

### POST-04 无交易日

区分计划休息、按计划观察未交易、未出现机会、数据未同步、用户未记录。只有用户明确确认时才认定真实无交易日。

存在未同步警告时，不能自动把当天记为“成功克制未交易”。

### POST-05 完成后的变化

后续新增迟到交易、费用修正或交易被删除时，总结标为“数据有变化，待核对”。保留原总结文本及当时汇总，并展示当前差异。

重新确认不抹去最初完成时间；按时完成指标和最新有效状态分别记录。

## 18. 周期复盘与改进行动

### CYC-01 轻量周复盘

按已设置交易日生成周期摘要：交易数量、有效净盈亏与 R、模型分布、规则执行、重复错误、盘前及盘后完成情况。

用户填写：最值得保留的行为、最重要的问题、下周期重点、验证方式。允许没有交易的周期仅总结观察与准备情况。

### CYC-02 改进行动

每个行动包含问题来源、具体行为、触发场景、适用账号或全局范围、开始时间、目标周期、验证方式和状态。

示例：“下一次入场前记录触发条件，再关联交易。”不能仅以“更自律”“少亏钱”作为可验证行动。

状态：待开始、进行中、已完成、待继续验证、已取消。完成必须有执行说明或证据；取消需说明原因，不自动算完成。

### CYC-03 行动继承

下一交易日展示进行中的重点行动，用户确认继续、调整或结束。避免每日生成大量相同待办；同一行动可持续跟踪多日。

首版建议同时突出一项主要行动，其余保留列表，不强制规定用户只能有一个改进方向。

### CYC-04 效果评价

先评价行为是否执行，再观察结果变化。短期盈利不能直接证明行动有效，短期亏损也不能直接否定执行改善。

## 19. 习惯、提醒与进度

### HAB-01 交易安排

用户可设置计划交易日、休息日、准备时间和总结时间。计划可临时调整，但事后调整保留时间，不删除已发生的漏准备事实。

历史导入区间默认不自动计入习惯考核；用户从启用每日流程之日起建立习惯统计。

### HAB-02 指标口径

所有比例在分母为零时显示“暂无适用样本”，不显示 0% 或 100%。尚未到达截止时间的当日事项显示进行中，不提前计作逾期。

| 指标 | 分子 | 分母 |
|---|---|---|
| 按时盘前准备率 | 规定准备时间前确认且早于首笔实际交易的日期数 | 需要准备的计划交易日数 |
| 交易前计划率 | 首笔实际交易前已有有效计划的交易日数 | 有实际交易且数据可判断的日期数 |
| 单笔复盘完成率 | 已完成且无需重新核对的完整交易数 | 习惯统计范围内应复盘的已结束有效交易数 |
| 每日总结完成率 | 已完成日总结数 | 需要总结的交易或观察日数 |
| 规则评价覆盖率 | 有正式评分的交易数 | 已关联评分规则且已结束的有效交易数 |
| 行动执行情况 | 有明确执行记录的行动 | 到期需核对的行动 |

不具备足够时间或交易数据时单列“无法判断”，并显示数量。计划休息日不计入需要准备或总结的分母；休息日实际交易后应进入实际交易日统计并提示安排偏离。

### HAB-03 提醒

首版至少提供站内待办：盘前未确认、盘后未总结、交易待复盘、数据待核对、行动待验证。

用户可配置提醒时间、关闭某类提醒或稍后处理。重复提醒应合并；同一事项已完成后停止提醒。系统关闭期间不保证外部推送送达，外部消息渠道另行设计。

### HAB-04 连续性展示

若展示连续完成天数，只计算需要执行流程的日期，计划休息不中断。补录可增加“已完成”数量，但不增加“按时完成”数量。

不以交易次数、手数、单日盈利或连续盈利授予纪律奖励。

## 20. 数据修正、重新同步与删除

### DAT-01 重复同步

同一事实重复接收不新增重复交易，不重置标签、笔记、规则结果和复盘状态。只有实际业务字段变化才触发核对。

### DAT-02 事实修正

费用、成交价格、数量、归并关系等变化后，相关分析更新；展示原值与新值。受影响复盘转待核对，用户文字不自动改写。

只有无关展示信息改变时，不要求用户重新完成全部复盘。

### DAT-03 清空重同步并保留人工资料

清空时将人工资料标为待恢复，保留原交易关联信息用于匹配，但不当作仍有效的交易事实参与统计。

新数据能够唯一匹配时恢复关联；无法唯一匹配则待用户处理，不任意挂到同品种交易。匹配后事实相同可恢复原状态，事实变化则待核对。

新同步起点排除的旧交易资料显示为范围外待处理。用户可保留为不参与统计的归档资料，或明确删除；不得悄悄丢弃。

### DAT-04 清空交易及人工资料

作为比普通重同步更彻底的选择，明确列出交易、标签关联、笔记、截图和复盘数量。共享标签定义和规则不清除。

### DAT-05 删除账号的共享资料规则

- 账号专属计划、意图、日记及附件随账号删除。
- 多账号共享计划保留其他账号内容，移除被删账号关联、专属场景、风险记录和引用摘要。
- 共享标签、模型、规则保留，删除该账号使用关系。
- 自由文本中由用户手写的账号提及无法可靠自动识别，删除确认必须说明共享文本保留，并提供查看和手动处理入口。
- 账号删除后从全部动态统计移除；共享周期复盘显示样本变化，移除可识别的被删账号交易引用。
- 同样账号重新添加视为新接入，不能凭账号相同自动恢复已删除资料。

### DAT-06 修改影响传播

交易事实变更影响金额及相关统计；标签变更影响标签分析；规则新版本不影响旧评价；计划修订只影响生效后的决策。页面应解释变化来源，避免同一个统计看似无原因跳变。

## 21. 通用体验与质量要求

### UX-01 草稿与保存

较长内容自动保存草稿，并有明确状态。保存失败保留本次输入并提供重试，不显示假成功。离开仍未保存的内容时提示风险。

同一内容在多个页面同时编辑时提示冲突，不能无提示覆盖较新的内容。

### UX-02 空状态

区分没有账号、尚未同步、筛选无结果、未填写、数据缺失、重同步中和真实零交易。每种状态提供相关下一步入口。

### UX-03 筛选与列表

支持分页、列宽、列顺序和显示列偏好。大结果集不一次展示全部。加载中、失败和重试有明确状态，避免旧结果冒充新筛选结果。

### UX-04 可解释性

关键指标可查看计算口径、样本数量、时间依据和缺失数据处理方式。金额始终带币种，风险值带单位。

### UX-05 危险操作

删除账号、彻底清空复盘和大规模标签合并须展示具体影响。普通保存、添加标签、查看分析不增加不必要确认。

### UX-06 附件与隐私

上传限制、支持格式和失败原因在操作前后可见。删除专属附件应使其无法继续通过旧访问入口查看。导出文件和截图可能含账号资料，用户应能选择导出范围。

### UX-07 分析一致性

列表、总览、分组、导出使用同一业务口径。统计更新中明确显示进度或旧数据时间，不把部分更新的结果标为最终值。

### UX-08 基本可用性

关键状态除颜色外有文字。表单必填、条件冲突、单位与错误就近显示。复盘长文支持正常换行，用户输入不得作为页面指令执行。

## 22. 分阶段交付及验收清单

### 22.1 交付顺序

| 交付 | 内容 | 完成标志 |
|---|---|---|
| A：数据与复盘 | 账号同步、原始订单、完整交易、标签、笔记截图、单笔复盘、基础金额分析 | 用户能核对并解释一笔交易 |
| B：规则与分析 | 模型、规则版本、评估、评分、R、模型／时间／错误／执行分析 | 用户能比较结果与执行过程 |
| C：每日闭环 | 盘前、意图、盘后、周复盘、行动、习惯及提醒 | 改进能够进入下一次交易计划 |

A、B、C 共同构成本次第一阶段范围，不因分批交付把 C 默认为可省略。完整 AI、课程、行情回放不阻塞验收。

### 22.2 核心验收用例

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC-01 | 添加账号未填写同步日期 | 无法完成，提示选择日期与时间口径 |
| AC-02 | 同账号同服务器重复添加 | 提示已有账号，不创建重复项 |
| AC-03 | 重新生成密钥 | 旧密钥失效，订单及复盘不变 |
| AC-04 | 无新交易的成功同步 | 最近成功时间更新，无虚假新增日志 |
| AC-05 | 同一批数据重试 | 无重复订单，日志新增数不膨胀 |
| AC-06 | 清空订单未确认起点 | 不执行清空 |
| AC-07 | 清空时旧请求到达 | 旧轮次数据不能写回 |
| AC-08 | 查看 EA 配置 | 参数只读，快照时间清晰，敏感密钥不暴露 |
| AC-09 | 删除账号后 EA 继续上传 | 上传被拒绝，不重建账号 |
| AC-10 | 一次开仓三次部分退出 | 保留全部成交，完整交易统计不算三笔独立交易 |
| AC-11 | 相邻两笔独立同向持仓 | 不因相似而错误合并 |
| AC-12 | 缺少开仓资料 | 标记待核对，不产生虚假持仓时长和完整胜率 |
| AC-13 | 原始订单排序 | 作用于全部筛选结果，相同时间翻页稳定 |
| AC-14 | 停用已使用标签 | 历史可见，新交易不可选 |
| AC-15 | 合并标签出现单选冲突 | 展示冲突，用户处理后完成 |
| AC-16 | 一笔交易有两个错误标签 | 两组可出现该交易，提示金额不能相加 |
| AC-17 | 亏损但所有规则通过 | 显示规则遵守，亏损不扣执行分 |
| AC-18 | 盈利但关键规则失败 | 显示关键违规，盈利不覆盖违规 |
| AC-19 | 规则存在未知项 | 无正式总分，显示覆盖率与原因 |
| AC-20 | 所有规则均不适用 | 显示未评分，不显示满分 |
| AC-21 | 修改已发布规则 | 新建版本，旧交易评价保持原依据 |
| AC-22 | 没有 Playbook 但写完复盘 | 可完成复盘，显示未评分，不计入已评分量 |
| AC-23 | 交易结束后补写理由 | 显示补录，不计作交易前准备 |
| AC-24 | 截图上传失败 | 保留其他草稿，失败图片可重试 |
| AC-25 | 缺少初始风险 | 金额统计可用，R 不计算且显示有效样本数 |
| AC-26 | 盈利因子没有亏损分母 | 显示暂不定义，不给虚假大值 |
| AC-27 | 多账号币种不同 | 金额分币种，无无说明合计 |
| AC-28 | 只有平仓数据 | 曲线标为已实现盈亏，不冒充实时权益 |
| AC-29 | 点击模型统计 | 能定位一致的交易样本并返回原分析 |
| AC-30 | 复制昨日计划 | 生成今日草稿，须重新确认 |
| AC-31 | 首笔交易后才确认计划 | 标记晚于首次交易，不算按时准备 |
| AC-32 | 盘中修订计划 | 新交易采用有效版本，旧交易不被回溯洗白 |
| AC-33 | 先记录意图，平仓后关联 | 按意图真实创建时间识别交易前记录 |
| AC-34 | 当天按计划未交易 | 可完成观察总结，不判作习惯失败 |
| AC-35 | 同步未完成但暂无订单 | 不自动认定真实无交易 |
| AC-36 | 日总结完成但两笔未复盘 | 日总结完成，单笔待办仍保留 |
| AC-37 | 总结后收到迟到交易 | 标记待核对，保留原文本和汇总 |
| AC-38 | 计划休息日 | 不计入漏打卡；实际交易后提示安排偏离 |
| AC-39 | 补录昨日总结 | 可计已完成，不改为按时完成 |
| AC-40 | 重同步保留复盘 | 唯一匹配后恢复，匹配不明不任意关联 |
| AC-41 | 重同步起点晚于旧交易 | 旧人工资料标范围外，不参与业绩统计 |
| AC-42 | 跨日部分平仓 | 每日金额按实现日；完整交易数按最终结束日 |
| AC-43 | 数据修正影响 R 或盈亏 | 分析更新，复盘待核对，原说明不被自动改写 |
| AC-44 | 历史导入数百笔旧交易 | 不自动追溯生成数百天习惯失败 |
| AC-45 | 删除多账号中的一个账号 | 专属数据清除，共享规则及其他账号资料保留 |
| AC-46 | 无权访问的交易或附件链接 | 无法访问，不泄露其他用户资料 |
| AC-47 | 多页面同时编辑复盘 | 提示冲突，不静默覆盖 |
| AC-48 | 导出全部筛选结果 | 数量和金额与相同口径分析一致 |

### 22.3 交付前检查

- 所有核心状态都有可触达的入口和明确下一步。
- 至少使用包含部分平仓、跨日、费用、重复同步、缺失风险、多个币种的样本完成业务验收。
- 完整交易统计与原始成交账目差异能够解释。
- 规则评价不依赖盈亏正负，未知与不适用处理一致。
- 清空重同步、账号删除对人工资料的影响与确认内容一致。
- 每日流程能够在无交易、计划修订、数据迟到情况下正常完成。
- 充值提现不进入交易绩效；未分配费用、跨起点活动和每日账目与完整交易统计差异有明确说明。

## 23. 评审决策与术语表

### 23.1 已明确的用户要求

- 账号添加必须选择同步开始日期，填写账号和服务器名。
- 密钥可重新生成。
- 清空重同步必须重新提示并确认起点。
- 有新增交易的同步日志要包含条数和订单号。
- 最新平仓时间与 EA 参数只读展示。
- 删除账号要物理清除其全部专属资料和订单。
- 原始订单支持跨账号查询、全信息查看、列升降序，默认平仓时间倒序。
- 第一阶段重点为标签、复盘、整体分析及每日盘前盘后流程。
- 当前文档不包含接口与数据库设计。

### 23.2 本版新增的建议基线

| 决策 | 本版采用 | 原因 |
|---|---|---|
| 复盘单位 | 完整交易为主，保留原始成交 | 避免部分平仓重复统计 |
| 评分 | 规则权重直接计算，完整覆盖后出正式分 | 减少多层权重与未知项歧义 |
| 等级 | 暂不强制 A+ 等评级 | 历史阈值尚未统一 |
| 重同步 | 默认保留人工资料待关联 | 避免同步维护破坏复盘资产 |
| 行情证据 | 截图优先 | 不让行情回放阻塞首版 |
| 跨币种 | 分币种统计 | 避免无汇率口径的合计 |
| 事件 | 首版手填 | 保持盘前流程独立可用 |
| 习惯起点 | 从启用每日流程开始 | 不将历史导入误作漏打卡 |
| 模型模板 | 可复制修改，不预设风险数值 | 尊重用户实际规则 |
| 交易控制 | 提醒与记录，暂不强制下单控制 | 与已平仓同步能力一致 |

### 23.3 实施前需结合实际数据确认的事项

以下事项不阻止业务文档评审，但在对应功能实施前必须确认实际能力：

1. 当前 EA 是否提供完整入场成交、持仓关联、初始止损、费用明细和配置快照。
2. 实际服务账户包含哪些净持仓／对冲模式，以及跨起点交易能否补齐。
3. 经纪商费用的正负号、计入时点和是否已包含在利润字段中。
4. 用户最终使用的交易日分界、主时段定义及重叠归属规则。
5. 复杂加仓交易的风险基准是否已有可用的原始记录。
6. 账号删除的附件、共享自由文本和备份处理规则是否满足部署环境。
7. 上传数量、大小、导出规模和响应时间目标根据实际样本与运行环境确定，不在本阶段虚构承诺。

### 23.4 术语

| 术语 | 说明 |
|---|---|
| Trade | 用于复盘的一次完整交易过程 |
| Setup | 交易机会模型 |
| Playbook | 执行某类机会的规则集合 |
| R | 相对于明确风险基准的净盈亏倍数 |
| MAE / MFE | 持仓路径中的最大不利／有利变化，需相应路径数据 |
| 计划关联 | 交易与计划场景存在引用关系，不自动等于遵守计划 |
| 规则覆盖率 | 当前适用评分规则中已有明确判定的权重比例 |
| 事后补录 | 在相关交易行为发生后创建的解释或计划材料 |
| 待核对 | 数据或结论需要用户确认，不能直接视为失败 |
| 已实现盈亏 | 已发生并确认的交易结果，不包含尚未实现的浮动盈亏 |
